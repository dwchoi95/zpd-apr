## 논문 요약

이 논문은 학생의 제출 이력에서 실행 결과가 개선되는 전이를 자동 추출하여 Progress, Strict, Answer라는 세 종류의 QLoRA 수리 정책을 학습하고, 검증 문제에서 실행 커버리지를 최대화하도록 세 체크포인트를 선택하는 ZPDPatch를 제안한다. 온라인 제어기는 관측 테스트 비회귀와 선택적인 AST 편집거리 예산을 보장한다.

실험 결과 자체는 저자의 최초 동기보다 훨씬 절제되어 있다. 전체 시스템은 zero-shot보다 크게 우수하지만, 이전 제출들을 직렬화한 입력은 current-code-only 입력보다 일관되게 낫지 않다. 관계별 정책을 강제로 하나씩 포함하는 구성도 Answer 체크포인트 세 개보다 열등하다. 따라서 주된 커버리지 향상은 trajectory conditioning이나 관계 이질성보다 독립 학습된 체크포인트의 다양성에서 온다는 것이 논문의 실제 결론이다.

## 주요 강점

1. **정직한 메커니즘 분석**  
   history serialization의 효과가 없고 관계 강제가 오히려 성능을 낮춘다는 부정적 결과를 숨기지 않는다. 교육적 효과나 ZPD 측정으로 확대 해석하지 않는 점도 좋다.

2. **강한 실행 기반 안전장치**  
   현재 프로그램을 fallback에 포함하여 관측 테스트 비회귀를 보장하고, AST TED 예산을 만족하지 않는 변경을 제거하는 제어기는 명확하고 감사 가능하다.

3. **상당히 폭넓은 평가**  
   문제 holdout, 사용자 중첩 층화, problem-cluster bootstrap, equal-problem estimand, observed/hidden 테스트 분할, 세 번의 전체 재학습, 학생 holdout Java 데이터까지 포함한다.

4. **좋은 대조군 설계 의도**  
   zero-shot뿐 아니라 Answer-3Seed, relation-constrained portfolio, generated-feedback ablation, 동일 target의 history ablation을 포함한다. 특히 seed diversity가 강한 교란 요인임을 인식한 점은 높이 평가한다.

5. **재현성 관련 설명**  
   학습 설정, 실행 제한, 캐시 키, 토큰 제한, AI 도구 사용 범위를 구체적으로 공개한다. 결과 해석도 대체로 신중하다.

## 주요 약점

### 1. 가장 중요한 Answer-9Choose3 결과가 없다

Section 4.6은 \(M_9-A_9\)만이 pool size, 84-way validation search, selector, test-time budget을 일치시켜 mixed targets의 효과를 식별한다고 명시한다. Section 5.3도 Answer-9Choose3를 “selection-matched control”로 소개하고 추가 여섯 개 Answer 체크포인트의 학습까지 설명한다.

그러나 결과 절과 Tables 4 및 7에는 Answer-9Choose3 결과가 전혀 없다. 논문 전체에서 해당 이름은 방법 설명에만 등장한다. 따라서 “checkpoint diversity rather than target heterogeneity”라는 중심 인과 해석은 논문이 스스로 설정한 mechanism-identification ladder를 완결하지 못했다.

이는 단순한 부가 분석 누락이 아니다. Answer-9Choose3가 mixed-target-9Choose3보다 우수한지, 동등한지, 열등한지에 따라 제목, 초록, 기여, 결론의 해석이 달라진다.

### 2. 핵심 trajectory 가설이 지지되지 않는다

RQ2에서는 Full Trajectory가 Current Code Only보다 일관되게 우수하지 않다. RQ4에서는 relation-constrained portfolio가 Answer-3Seed보다 낮고, unconstrained winner도 두 Answer와 한 Progress로 구성되어 Answer-3Seed와 사실상 동률이다. Java replication에서도 mixed portfolio가 Answer-3Seed를 이기지 못한다.

따라서 현재 증거가 지지하는 핵심은 “trajectory-conditioned ZPD repair”가 아니라 “독립적으로 학습된 SFT 체크포인트 여러 개를 실행 선택하면 단일 체크포인트보다 커버리지가 높다”이다. 후자는 유용하지만 제목과 방법의 복잡성을 정당화할 만큼 새로운지 더 설득해야 한다.

### 3. patch-scope specialization 근거가 충분히 강하지 않다

Table 6의 Progress/Strict/Answer TED 평균은 각 방법이 성공한 서로 다른 부분집합에서 계산된다. 따라서 15.85, 17.45, 20.22라는 순서는 성공 사례 구성 차이로도 생길 수 있다. 이를 target relation에 의한 specialization으로 해석하려면 공동 성공 사례에서의 paired TED, 문제-clustered paired interval, 생성 코드 보존율 등의 분석이 필요하다.

AST TED 자체도 가독성, 개념적 근접성, 학생 이해 가능성의 대리변수가 아니다. 논문이 이를 위협으로 인정하지만, 이 한계는 “trajectory supervision이 더 좁은 수리를 만든다”는 남은 긍정적 주장을 직접 약화한다.

### 4. 검증 선택의 일반화 구조가 불명확하다

Seen validation과 Seen test는 trajectory만 분리되고 문제 identity는 공유한다. 체크포인트 portfolio를 문제별 validation execution으로 선택한 뒤 동일 문제들의 다른 trajectory에서 평가하면 문제군 특성에 맞춘 선택 효과가 포함될 수 있다. Unseen 평가가 이를 부분적으로 보완하지만, Unseen은 의도적으로 저빈도 문제만 모은 비무작위 집합이다.

최소한 validation/test 문제 중첩 수, 문제-held-out portfolio selection 결과, 선택된 triple의 bootstrap 안정성을 보고해야 한다.

### 5. 이론적 포장이 기여보다 크다

후보가 9개이고 크기 3인 모든 조합이 84개이므로 선택은 작은 유한 집합의 완전 탐색이다. set-union coverage가 monotone submodular라는 사실은 맞지만, 알고리즘이나 근사 보장에 실제로 활용되지 않는다. 기여 목록의 “finite-family problem-level selection guarantee”도 본문에서는 exact finite validation optimum과 독립 test evaluation 이상으로 명확히 정식화되지 않는다.

이 부분은 정리와 증명을 추가하거나, 단순하고 정확한 validation set-coverage selection으로 표현을 낮추는 편이 낫다.

### 6. 외부 replication의 범위가 제한적이다

CodeWorkout은 학생은 분리되지만 모든 split에 동일한 17개 exercise가 포함되고, Java 전용으로 다시 학습한다. 따라서 이는 학생 holdout과 별도 데이터셋에서의 재학습 재현이지, 새로운 과제나 cross-language transfer의 증거는 아니다. 논문은 대체로 올바르게 범위를 제한하지만 “external replication”이라는 표현은 이 구분을 더 전면에 드러내야 한다.

### 7. 제출 형식 위반 위험

현 PDF는 총 21쪽이고, 결론이 19쪽에 있으며 References도 19쪽에서 시작한다. 즉 일반 본문이 18쪽을 넘어간다. FSE 2027 최초 제출은 본문과 그림 18쪽, 참고문헌 4쪽만 허용하며 비준수 논문은 desk reject한다고 명시한다. Data Availability 문장은 페이지 제한에서 제외되지만, 19쪽의 Conclusion은 제외 대상이 아니다. [FSE 2027 제출 지침](https://conf.researchr.org/track/fse-2027/fse-2027-papers)

## Accept 판단을 위해 필요한 변경

1. 결론까지 18쪽 이내로 이동하여 FSE 페이지 제한을 충족한다.
2. Answer-9Choose3의 모든 핵심 결과를 보고하고 \(A_1\), \(A_3\), \(A_9\), \(M_9\)의 계획된 대비를 완결한다.
3. 결과에 따라 초록, 제목, 기여, 결론을 수정한다. 현재 증거만 유지된다면 핵심 기여는 trajectory conditioning의 성공이 아니라 그 효과를 checkpoint diversity와 분리한 부정적 메커니즘 연구여야 한다.
4. Progress/Strict/Answer 및 최종 portfolio의 patch-size 차이에 공동 성공 사례 기반 paired 분석을 추가한다.
5. 동일 문제 기반 validation selection의 영향을 정량화하고, 가능하면 문제-held-out validation 또는 nested selection 분석을 추가한다.
6. 외부 Java 결과를 “student-held-out after dataset-specific retraining”으로 일관되게 한정한다.
7. 익명 artifact에 splits, checkpoint identity, validation coverage sets, 모든 생성 결과, Answer-9Choose3, hidden-test partition, 통계 재생성 코드를 포함한다.
8. 관련 연구나 강한 fine-tuned repair baseline과의 비교를 추가하거나, 실행 불가능한 경우 왜 Answer ensemble과 LSGen이 가장 적절한 비교인지 명확히 정당화한다.

## 최종 판단

이 논문은 실험적 자기비판성과 실행 기반 통제 설계가 상당히 좋다. 특히 원래의 trajectory/ZPD 동기가 실험으로 지지되지 않았음을 솔직히 드러낸 점은 학술적으로 가치가 있다. 그러나 현재 원고는 약속한 결정적 대조군을 보고하지 않아 중심 해석이 완결되지 않았고, 실제로 지지되는 기여가 제목과 시스템 framing보다 좁다. 페이지 제한까지 고려하면 현 상태의 Accept에는 반대한다. **Major Revision이 가능하면 그 경로를 지지하며, 이분법적 결정이라면 Weak Reject이다.**
