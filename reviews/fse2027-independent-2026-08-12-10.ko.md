# FSE 2027 독립 리뷰

## 논문 요약

이 논문은 실행 기반 자동 프로그램 수정(APR)에서 흔히 한꺼번에 변화하는 네 요인, 즉 후보 생성 횟수, 독립 체크포인트의 다양성, 학습 목표 데이터의 구성, 검증 집합 기반 포트폴리오 선택을 분리하여 분석한다. 이를 위해 학생의 실제 제출 궤적에서 다음 세 가지 감독 관계를 자동 추출한다.

- `Progress`: 테스트별 결과가 하나도 악화되지 않으면서 적어도 하나 개선되거나, 판정 자체가 개선된 전이
- `Strict`: 온라인 저지 판정의 순서가 엄격히 개선된 전이
- `Answer`: 실패한 제출에서 최종 정답 제출로 직접 연결한 전이

각 관계에 대해 여러 QLoRA 체크포인트를 학습하고, 검증 문제에서 실행 성공 집합의 합집합을 최대화하는 크기 3의 포트폴리오를 선택한다. 실행 시에는 현재 프로그램을 fallback으로 포함하여 관측 테스트 비회귀를 보장하고, 선택적으로 AST tree-edit-distance(TED) 예산을 적용한다.

핵심 실험은 \(A_1 \rightarrow S_3 \rightarrow A_3 \rightarrow A_9 \rightarrow M_9\) 사다리로 구성된다. 결과는 unrestricted repair 성능의 대부분이 관계별 감독이나 독립 체크포인트보다 단일 체크포인트에서 여러 후보를 생성하는 candidate breadth에서 나온다는 것을 보여준다. 궤적 전체를 입력에 직렬화하는 것도 안정적인 이득이 없으며, 오히려 current-code-only prompt가 더 좋다. 한편 혼합 관계 목표는 제한된 편집 예산 아래에서 작지만 양의 효과를 보이고, exercise-held-out Java 실험에서도 효과가 나타난다. 저자들은 이 결과를 보편적인 trajectory superiority가 아니라 조건부 효과로 제한하여 해석한다.

## 강점

### 1. 혼동되기 쉬운 메커니즘을 실제로 분리한 실험 설계

가장 강한 기여는 새로운 앙상블 자체라기보다 실험적 식별 설계다. 특히 \(A_1\), \(S_3\), \(A_3\), \(A_9\), \(M_9\)를 단계적으로 비교해 다음 효과를 분리한 점이 좋다.

- 한 체크포인트에서 후보 수를 늘리는 효과
- 서로 다른 학습 seed의 효과
- 검증 선택에 제공되는 체크포인트 풀 크기의 효과
- 관계별 학습 목표 구성의 효과

\(M_9\)과 \(A_9\) 사이에서 체크포인트 수, 84개 포트폴리오 탐색, 검증 데이터, 선택기, 추론 호출 수를 맞춘 것은 특히 설득력 있다. Answer 데이터가 더 많아 오히려 대조군에 유리하다는 점도 명시한다.

### 2. 부정적·혼합 결과를 숨기지 않는 정직한 해석

논문의 동기는 제출 궤적이지만, 결과는 다음을 명확히 인정한다.

- 전체 궤적 입력은 안정적인 이득이 없다.
- unrestricted \(M_9-A_9\) 효과의 주 추정치는 신뢰구간이 0을 포함한다.
- 1.5B에서는 혼합 목표의 효과가 음수 방향이다.
- Unseen 문제에서도 \(M_9\)과 \(A_9\) unrestricted RR은 동일하다.
- 실제 권장 배포 구성은 trajectory prompt를 제거한 current-only \(A_3\)다.

이러한 결과를 무리하게 긍정적으로 포장하지 않고 “candidate breadth가 지배적이며 관계 목표 효과는 조건부”라고 결론 내린 점은 높은 신뢰를 준다. 유의하지 않은 unrestricted 결과와 제한적 budget 효과를 구분한 것도 적절하다.

### 3. 광범위하고 세심한 강건성 검증

다음 검증들이 기술적 신뢰도를 크게 높인다.

- 문제 단위 cluster bootstrap과 equal-problem estimand
- 5-fold problem-cross-fitted 포트폴리오 선택
- 관측 테스트와 hidden test를 분리한 확인 실험
- 1.5B 모델 규모 반복
- Python CodeNet과 Java CodeWorkout의 언어·도메인 반복
- student-held-out과 exercise-held-out의 분리
- current-only prompt 재선택 및 frozen-member 비교
- 판정 순서를 변경한 재학습
- 여러 seed와 실행 순서 재현
- 절대 TED 및 프로그램 크기로 정규화한 TED 분석
- 소스 토큰·라인 보존율 분석
- fallback 비회귀 및 TED budget 위반 감사

특히 hidden-test 결과를 후보 선택이나 prompt에 노출하지 않은 채 관측 테스트에서 선택된 수정을 독립적으로 확인한 것은 generate-and-validate APR의 테스트 과적합 우려에 직접 대응한다.

### 4. 실행 제어기의 보장이 명확함

현재 프로그램을 후보 집합에 포함하고 pass rate와 TED를 사전식으로 최적화함으로써 관측 테스트에서의 비회귀와 편집 예산 준수를 구조적으로 보장한다. 보장의 범위를 hidden-test correctness나 교육적 유용성까지 확대하지 않고 명확히 제한한 것도 적절하다.

### 5. 재현 가능성을 고려한 상세한 기술

데이터 필터링, split, seed, QLoRA 설정, optimizer, token limit, 실행 timeout, memory limit, Java 버전, cache key, 포트폴리오 탐색 수, 통계 seed가 상당히 구체적이다. 분석의 사전 고정 여부와 exploratory 분석을 Table 2에서 구분하고, 실행 과정의 conformance amendment도 공개한다. Data Availability 절도 FSE 요구에 맞게 결론 뒤에 배치되어 있다.

### 6. 표현과 구성

21쪽 PDF는 본문·그림 18쪽과 참고문헌 3쪽으로 구성되어 FSE 2027의 18+4쪽 제한에 부합한다. 익명화, 단일단 형식, Data Availability 배치도 적절하다. 표와 그림은 깨짐 없이 읽히며 Figure 1은 전체 구조를 효과적으로 요약한다. 수식, 표, 주요 결과의 연결도 대체로 명확하다.

## 주요 우려 사항

### 1. 가장 독창적인 방법 요소의 효과가 작고 모집단 의존적임

논문의 대표적인 방법 요소는 Progress/Strict/Answer 관계를 이용한 혼합 목표 학습이다. 그러나 가장 엄격하게 통제된 unrestricted 비교에서 그 효과는 작고 불확실하다.

- CodeNet 7B Seen cross-fitted \(M_9-A_9\): +2.2점, CI가 0 포함
- CodeNet Unseen: 사실상 0
- CodeNet 1.5B: -0.8점
- student-held-out Java: +0.6점 수준의 near-null
- exercise-held-out Java: +3.9점의 양의 효과

편집 예산 평균에서는 약 +1.2점의 양의 효과가 있지만 크기는 작다. 따라서 ZPDPatch의 관계별 감독이 일반적인 APR 성능 개선 방법이라는 결론은 지지되지 않는다. 논문도 이를 인정하지만, 결과적으로 독자가 받아들여야 할 핵심 기여는 “새로운 강한 repair 방법”보다는 “혼합 감독, seed diversity, candidate breadth를 구별한 대규모 음성·조건부 결과”가 된다.

이 자체는 가치가 있지만, FSE 수준의 significance 판단은 이 메커니즘 연구가 후속 APR 실험 설계에 얼마나 일반화될 수 있는지에 달려 있다. 현재 증거는 한 계열의 Qwen2.5-Coder 모델과 특정 SFT/QLoRA 설정에 집중되어 있다.

### 2. trajectory-conditioned repair라는 동기가 실제 배포 결과와 긴장 관계에 있음

논문의 출발점은 동일한 현재 코드라도 이전 제출 경로에 따라 필요한 지원이 다를 수 있다는 것이다. 그러나 target-matched RQ2에서 전체 궤적은 안정적 이득이 없고, frozen prompt 비교에서는 과거 제출을 제거하면 RR이 8.8–11.1점 개선된다. 최종 권장 구성도 current-only \(A_3\)다.

따라서 제출 궤적은 유용한 inference context라기보다 감독 데이터를 채굴하는 오프라인 원천으로만 남는다. 이것은 논문이 명시적으로 인정하고 있지만, 현재 제목과 초기 동기는 독자에게 trajectory-conditioned inference가 핵심인 것처럼 보일 수 있다. 논문의 진짜 기여가 “trajectory supervision의 효과 분해”라면 서론에서 이 구분을 더 일찍, 더 선명하게 제시할 필요가 있다.

또한 이 결과는 현재 benchmark가 history-sensitive counterfactual을 거의 포함하지 않아서 발생했을 가능성과, 모델이 긴 history prompt를 제대로 활용하지 못해서 발생했을 가능성을 구별하지 못한다. 논문이 제시한 유사-current-code audit에 적합한 표본이 6개와 12개뿐이라는 사실이 바로 이 식별 한계를 보여준다.

### 3. 교육적 가치와 TED 기반 locality 사이에는 큰 간극이 있음

작은 AST TED, 토큰 보존율, 라인 보존율은 “수정 범위가 작다”는 점을 보여주지만 다음을 의미하지는 않는다.

- 학생이 수정 내용을 이해할 수 있음
- 적절한 next-step hint임
- 학습을 촉진함
- 학생 의도나 전략을 보존함
- 최종 답을 직접 제공하는 것보다 교육적으로 우수함

논문은 ZPD를 심리적 측정이나 학습 효과 주장으로 사용하지 않는다고 정확히 제한한다. 그럼에도 ZPD와 교육적 지원이라는 동기가 상당한 지면을 차지하므로, 실제 기여는 교육 효과가 아니라 실행 기반 locality control임을 더 강하게 전면화해야 한다. 현 상태에서 “ZPD”는 직관적 명명에는 도움을 주지만 실증 구성요소는 아니다.

### 4. baseline 범위의 한계

Answer-9Choose3는 핵심 메커니즘을 분리하는 훌륭한 대조군이고 LSGen도 의미가 있다. 다만 시스템 수준의 비교는 제한적이다.

- Zero-shot은 동일 모델을 사용한 공정한 내부 대조군이지만 최신 강력한 LLM APR 시스템 전체를 대표하지 않는다.
- LSGen은 same-problem 저장소에 접근하므로 정보 조건이 다르고 Unseen에서는 비교할 수 없다.
- SelfAPR, PyDex, CREF, CEGIS 계열은 기능적으로 논의되지만 정량 비교가 없다.
- current-only \(A_3\)가 최적 배포 설정이라면, 이 구성이 일반적인 multi-sample decoding이나 더 강한 decoding/search 전략과 비교될 필요가 있다.

특히 단일 체크포인트의 세 stochastic sample이 큰 이득을 보였으므로, temperature, top-\(p\), pass@k, 후보 다양성 제어, best-of-three execution selection을 더 폭넓게 조정한 대조가 있었다면 “candidate breadth가 지배적”이라는 결론이 더 일반적이었을 것이다.

### 5. 데이터 분할과 일반화 해석의 제약

Seen split은 문제 안에서 trajectory를 나누므로 같은 문제의 해답 패턴을 학습할 수 있다. 저자들도 memorization 가능성을 인정한다. Unseen은 trajectory 수가 적은 하위 10% 문제로 구성되므로 무작위 problem holdout이 아니며, Seen보다 절대 RR이 높은 현상도 두 집단의 난이도가 직접 비교 가능하지 않음을 보여준다.

exercise-held-out Java 실험은 4개 exercise만으로 구성되고 train-test student identity가 151명 겹친다. 반대로 student-held-out 실험에서는 혼합 목표 효과가 near-null이다. 모든 네 exercise에서 방향이 양수라는 사실은 고무적이지만, 4개 cluster에서 계산한 cluster interval은 일반적인 과제 모집단에 대한 안정적인 추론으로 보기 어렵다.

따라서 외적 타당성은 다음 정도로 제한하는 것이 타당하다.

- candidate breadth 효과는 여러 설정에서 반복됨
- 혼합 trajectory targets의 효과는 특정 편집 제약 또는 특정 과제 이동에서 관찰됨
- 혼합 목표의 보편적 coverage 효과는 아직 입증되지 않음

논문의 실제 결론은 대체로 이 수준을 지키지만, 초록의 Java replication 문장은 이 모집단 차이를 더 직접적으로 드러낼 수 있다.

### 6. 분석이 매우 많고 완전한 사전등록은 아님

논문은 분석 provenance를 정직하게 공개하며, 최종 테스트 전 고정한 분석과 결과 확인 후 exploratory 분석을 나눈다. 이는 강점이다. 그러나 분석 수가 매우 많고 외부 사전등록은 없었다. 주요·보조 endpoint, robustness, post-review confirmation, repository-frozen 분석이 혼재되어 있어 독자가 어떤 결과를 확증적으로 받아들여야 하는지 추적하기 어렵다.

현재는 cross-fitted unrestricted \(M_9-A_9\)와 6개 TED budget 평균을 주·보조 메커니즘 추정치로 지정했지만, 초록과 결론에서 다음 세 층위를 더 명확히 분리하면 좋겠다.

1. 주 효과: candidate breadth
2. 제한적 보조 효과: cross-fitted budget frontier
3. 독립적이지만 소규모인 외부 반복: 4개 held-out Java exercise

### 7. 재현 패키지의 실제 접근 가능성은 원고만으로 확인할 수 없음

Data Availability는 splits, checkpoints, JSONL, code, tests, pinned environment, digest map을 제공한다고 쓰고 있다. 다만 원고에는 익명 artifact URL이나 supplemental-material 식별자가 보이지 않는다. 실제 제출 시스템에 패키지가 별도로 첨부되어 있다면 문제없지만, 그렇지 않다면 FSE의 open-science 기대를 충족하기 위해 익명 접근 방법을 명시해야 한다.

또한 체크포인트 선택, cache rebinding amendment, hidden-test repartition, exhaustive portfolio 결과를 처음부터 재생성할 수 있는 단일 실행 경로와 예상 계산 비용이 artifact에 포함되어야 한다.

## 항목별 평가

### Novelty / Originality

높음과 중간 사이이다. Progress/Strict/Answer라는 개별 관계의 아이디어보다, 동일한 후보 예산과 선택 기회를 맞추어 candidate breadth, seed diversity, pool selection, target construction을 분리한 식별 사다리가 더 독창적이다. 음성 결과를 중심 기여로 전환한 점도 신선하다. 반면 최종 권장 시스템인 current-only \(A_3\) 자체는 기술적으로 새롭지 않다.

### Technical Soundness

전반적으로 높다. 데이터 생성 규칙, 실행-evidence order, fallback 보장, exact portfolio enumeration, cross-fitting, cluster bootstrap이 잘 정의되어 있다. 주장 범위도 대체로 증거에 맞는다. 가장 큰 제약은 iid 선택 bound가 실제 문제 분포와 겹침 구조를 충분히 표현하지 못한다는 점, 그리고 관계 목표의 효과가 학습 데이터 크기·target distance 등과 완전히 분리되지 않는다는 점이다. 후자는 저자들도 인정한다.

### Empirical Evidence

매우 풍부하고 대체로 강하다. 997 Seen, 250 problem-held-out, 1.5B 반복, 두 Java 분할, hidden-test 확인, 여러 seed와 prompt 통제가 포함된다. 다만 풍부한 분석과 별개로 논문의 가장 고유한 \(M_9-A_9\) 효과는 작고 일관되지 않다. candidate breadth에 대한 증거는 강하지만, relation-mined mixed targets에 대한 증거는 조건부다.

### Significance

APR 연구에서 여러 후보를 생성하는 것과 여러 체크포인트를 학습하는 것, 검증 선택과 supervision 다양성을 혼동하지 말아야 한다는 메시지는 중요하다. 특히 “앙상블 성능 향상”을 새로운 감독 방법의 효과로 잘못 귀속할 위험을 실증적으로 보여준 점은 후속 연구 설계에 기여할 수 있다. 반면 실제 배포 성능 관점에서는 current-only 세 후보 구성이 결론이므로, ZPDPatch 자체의 시스템적 진보는 제한적이다.

### Clarity

전체적으로 명확하고 전문적이다. 표와 그림도 읽기 좋다. 다만 18쪽에 매우 많은 실험과 통제를 압축해 서술하여 인지 부하가 높다. \(A_1, S_3, A_3, A_9, M_9\) 기호를 반복해서 되짚어야 하고, selection-frozen, repository-frozen, cross-fitted, current-only 결과가 여러 절에 분산된다. 핵심 주장-증거 매핑 표를 하나 제공하면 크게 개선될 것이다.

### Reproducibility

원고의 방법 상세도는 높고, seed·환경·runner·통계 절차가 잘 기록되어 있다. artifact 설명도 좋다. 다만 실제 replication package의 접근성과 완전성은 PDF만으로 확인할 수 없다. artifact가 제출물에 실제로 포함되었다는 전제에서는 높은 재현 가능성을 기대할 수 있다.

### Limitations

논문이 스스로 대부분을 정확하게 인정한다. 한 모델 계열, public-test overfitting, Seen memorization, 비무작위 Unseen, 4개 Java exercise, TED의 교육적 한계, 관계 의미와 target distribution의 불완전한 분리를 명시한다. 추가로, history effect를 평가할 counterfactual support가 극히 적어 trajectory-conditioning에 대한 부정적 결과도 benchmark-specific일 수 있음을 더 강조할 필요가 있다.

## 저자에게 묻고 싶은 질문

2. \(S_3\)의 temperature 0.8/top-\(p\) 0.95는 어떻게 정했는가? validation-tuned stochastic decoding이나 더 다양한 후보 생성 설정에서도 \(A_3\)와 \(M_9\)에 대한 결론이 유지되는가?
3. Full Trajectory의 성능 저하가 prompt 길이 증가 때문인지, 오래된 제출의 노이즈 때문인지 분리할 수 있는가? 예를 들어 동일 token 길이의 current-only control 또는 최근 \(k\)개 제출만 포함하는 통제가 가능한가?
4. CodeWorkout exercise-held-out의 exercise-cluster CI는 cluster가 4개뿐인 상황에서 어떤 bootstrap 절차로 계산했는가? 이 구간을 모집단 추론보다 기술적 반복 결과로 보는 것이 더 타당하지 않은가?
5. 편집 예산 평균 +1.2점은 통계적으로는 양수지만 절대 효과가 작다. 모델 9개를 학습·선택하는 비용을 고려할 때, 어떤 실제 배포 조건에서 current-only \(A_3\)보다 \(M_9\) budget portfolio를 선택해야 하는가?
6. Progress와 Strict 데이터의 수와 target-distance 분포를 Answer와 맞추는 subsampling 또는 reweighting 실험이 가능한가? 현재 \(M_9-A_9\)는 관계 의미뿐 아니라 데이터 분포 차이도 함께 측정한다.

## 필요한 수정

게재 전 다음 사항을 우선적으로 보완하기를 권한다.

- 서론과 초록에서 기여를 “trajectory-aware inference의 우수성”이 아니라 “trajectory supervision, checkpoint diversity, candidate breadth의 분리”로 더욱 명확히 정렬할 것.
- primary, secondary, exploratory 결과를 요약하는 한 개의 claim-evidence 표를 추가할 것.
- Java exercise-held-out 결과의 4-cluster 한계를 초록 또는 결과 요약에서 직접 표시할 것.
- Full Trajectory의 성능 저하에 대한 prompt-length/noise 설명을 추가 분석하거나 최소한 중요한 미해결 원인으로 논의할 것.
- 익명 artifact의 접근 경로와 재현 범위를 명확히 할 것.
- \(M_9\) budget 효과의 실제 크기와 추가 학습·선택 비용을 고려한 배포 기준을 더 구체적으로 제시할 것.

## Overall Merit

**4 / 5 — Accept**

이 논문의 강점은 ZPDPatch가 보편적으로 더 높은 repair rate를 달성한다는 데 있지 않다. 오히려 APR 연구에서 supervision, 후보 수, checkpoint seed, validation selection이 쉽게 혼동된다는 문제를 세심한 matched design으로 분해하고, 예상과 다른 결과까지 투명하게 보고한 데 있다. Candidate breadth 효과는 여러 모델 규모와 도메인에서 강하게 반복되며, current-only prompt가 더 낫다는 결과도 실용적이고 연구적으로 중요하다. 실행 비회귀 보장, hidden-test 확인, cross-fitting, 외부 Java 반복, 통계적 의존성 처리는 FSE 수준에 부합한다.

반면 관계별 trajectory supervision의 고유 효과는 unrestricted 설정에서 작고 불확실하며, 편집 예산 효과도 절대 크기가 작고 Unseen 및 1.5B에서 일반화되지 않는다. 교육적 ZPD 동기 역시 학습 효과로 검증된 것은 아니다. 따라서 strong accept까지는 어렵다. 그럼에도 논문이 이러한 한계를 숨기지 않고 정확한 범위의 결론을 내리며, 후속 LLM 기반 APR 연구의 실험 설계에 유용한 교훈을 제공한다는 점에서 장점이 단점보다 크다고 판단한다.
