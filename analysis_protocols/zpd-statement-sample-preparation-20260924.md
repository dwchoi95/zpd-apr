# Generator-visible statement-sample preparation boundary

Prospective engineering specification,2026-09-24. No new outcome execution,
feedback-feature fit, scientific gate change or experimental release is granted
by this document. Freeze extraction before inspecting empirical descriptions.

## Why this bounded next step

Directed-history Newton-v2 completed numerically but failed both scientific
gates. Most available nominal feedback does not distinguish within-WA progress.
The full evaluation suite and the legacy mixed Progress cache are NOT eligible
inference feedback: public/sample roles and exact historical provenance are
unestablished. Do not open their bodies for this preparation.

An independently useful prerequisite is to identify explicit sample input/output
already present in the problem statements used by the frozen candidate generator.
Call these **generator-visible statement samples**, not original student feedback
or a fresh hidden evaluation set. Availability and useful feedback variation are
unknown. All320 recipients and all historical observations remain in scope even
when extraction or later execution is unavailable.

## Exact input boundary

Reuse only the already reviewed observed-source join, its sealed source-only
support and the frozen train64+256 requests/manifests. Preserve the full current,
prior and pre-certified donor contexts and the same five problem folds. Do not
read original-valid32 outcomes, successor targets, mixed outcome caches or
candidate evaluation vectors. The inherited source reader can verify original96
generation/source metadata, but only its selected train64 rows enter outputs.

Problem descriptions may be read only from the fixed canonical problem-data
root, for the exact23 selected problems, as `<problem_id>/description.html`.
Their expected SHA must come from the already sealed preparation manifest's
`data_sha256`, agree across preparations when shared, and be checked before
parsing. No testcase/expected-output bundle or arbitrary sibling file is read.
The exact data-root identity must be recovered from source/metadata before a
production release; it is not an arbitrary user-supplied fallback path.

Decode strict UTF-8, with no replacement. Applying the original frozen
`_DescriptionParser` text projection to the entire HTML must exactly equal every
selected frozen request's `problem_description` for that problem. This binds the
HTML to the statement used for generation. It does not make raw HTML bytes
identical to the serialized prompt: the original projection collapsed whitespace
and discarded tag structure. Using those original public-document formatting
boundaries is an explicit representation addition shared by every later control,
not an inferred reconstruction from normalized text or an extra private oracle.

## Predeclared conservative extraction

Use a pure, non-network HTML parser, not the legacy testcase-bundle loader.
Recognize only `h3` headings whose whitespace-normalized text matches, ignoring
case, `Sample Input`, `Sample Output`, or either followed by a positive decimal
index. An absent index means1. Consume the subsequent explicit `pre` block for
that heading; an intervening heading, another pending sample, premature EOF,
duplicate kind/index or mismatched input/output indexes invalidates extraction
for that entire problem. Do not retain only a convenient subset of pairs.

Preserve the `pre` data exactly after one standard HTML entity decoding; do not
strip whitespace, append a newline, collapse blank lines or infer missing bytes.
No double `html.unescape`. Nested tags inside an active sample `pre` are
ambiguous and invalidate the problem, including `br`; there is no heuristic
reconstruction. Comments and declarations inside the active block are likewise
ambiguous. Mark malformed nested/unclosed heading/pre structures unavailable.
Explicit empty input/output is distinguishable from a missing block and is
retained as an empty byte string. Ignore unrelated content, script/style data
and nonmatching headings. A document with no recognized sample is unavailable,
not a zero-test successful observation.

Order pairs by numeric index, retain exact UTF-8 input/output and their separate
SHA256s, and bind the complete ordered sample-set identity. Preserve duplicates
with different sample indexes; never deduplicate or select by execution outcome.
Output parse reason and counts for every problem and coverage for every recipient.
No result-dependent parser patches, manually repaired examples, fallback expected
outputs, generated tests or dynamic network fetches are permitted by this stage.

## Observed-source request roster

Produce a separate source-only roster from the reviewed exact joins. Bind each
source's problem, full/raw submission IDs, original bytes/SHA, declared language
and timestamp. Context entries retain recipient/bank/user/fold, current cutoff,
role(current/prior/donor), position and donor identity. Deduplicate execution
identity only; never shorten a history, silently remove non-Python sources, or
drop recipients. An identical source ID with conflicting bytes, time or language
fails closed. Donor sources remain strictly before the already certified donor
cutoff and recipient cutoff; donor current/future code is never requested.

The roster is NOT permission to execute submitted code. Python eligibility can
be reported from original language provenance, while all other languages stay
explicitly unavailable. Missing sample/byte identity/access coverage must not be
turned into all-failed, zero progress or complete feedback.

## Verification and release conditions

First implement pure extraction/roster functions and synthetic positive/negative
tests. Obtain an independent code/boundary review. Then freeze a clean source
snapshot, full source/input SHA closure and fixed input/output paths before a
single source-only preparation. Recheck bindings after preparation, independently
verify exact membership/sample provenance, and retain any failure without repair
in place. No subprocess running submitted code is part of this stage.

Later observed-only sample replay needs its own prospective sandbox/runtime,
stability, timeout, memory and unknown-handling contract and release. A later
fit additionally needs useful source/feedback variation, a matched-current-
feedback control and the existing actual-repair/history-mechanism comparisons.
Do not use hidden scoring cases, candidate labels or original-valid32 as feature
inputs. Do not label a public-sample repair result as private-test generalization
or evidence that a participant saw or learned from this reconstructed feedback.
