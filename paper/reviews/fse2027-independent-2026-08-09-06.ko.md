### 논문 요약

이 논문은 학생의 실제 제출 궤적에서 Progress, Strict, Answer 관계를 자동 추출해 QLoRA 체크포인트를 학습하고, 검증 실행 결과로 세 체크포인트를 선택하는 프로그램 수리 시스템 ZPDPatch를 제안한다. 핵심 실험은 \(A_1 \rightarrow A_3 \rightarrow A_9 \rightarrow M_9\) 비교를 통해 반복 호출, 독립 학습 시드, 검증 선택, 혼합 관계 타깃의 효과를 분리하려는 것이다.

결과는 논문의 최초 직관보다 더 미묘하다. 무제약 수리율 향상의 대부분은 제출 이력이나 관계별 타깃이 아니라 독립 체크포인트 다양성에서 발생한다. 혼합 관계 타깃은 선택 기회가 동일한 Answer-only 풀보다 무제약 수리율에서 안정적인 우위를 보이지 않지만, Seen 데이터의 AST 편집 예산과 소스 보존 측면에서는 작은 이점을 보인다.

### 판정 근거

이 논문의 가장 큰 장점은 기대한 가설을 과장하지 않고, 강한 대조군을 추가해 실제 효과의 원인을 분해했다는 점이다. 특히 \(A_3-A_1\), \(A_9-A_3\), \(M_9-A_9\) 사다리, 문제 단위 부트스트랩, 독립 테스트 분할, Java 데이터 재학습은 일반적인 LLM 수리 논문보다 훨씬 엄격하다.

그러나 현재 원고가 전면에 내세우는 “trajectory supervision”의 독립적 효과는 충분히 입증되지 않는다. 직렬화된 과거 제출의 효과는 null이며, 혼합 타깃의 주된 양의 결과는 작고 선택 방식에 민감하다. 더구나 원고가 기여로 명시한 1.5B 모델 및 exercise-held-out Java replication은 방법만 기술되고 결과가 제시되지 않는다. 핵심 Seen 결과의 검증 문제와 시험 문제 정체성 중복도 관계 타깃의 작은 효과를 해석하는 데 상당한 위험을 준다. 따라서 아이디어와 실험 자산은 유망하지만, 현 상태에서 FSE Research Paper로 채택하기에는 핵심 주장과 제시된 증거 사이의 간격이 남아 있다고 판단한다.

## 기준별 평가

### 1. 독창성

독창성은 중상 수준이다.

- 실제 제출 궤적을 실행 결과의 부분순서로 형식화한 점은 흥미롭다.
- 관계별 체크포인트의 단순 앙상블이 아니라 검증 실행의 set-union coverage로 포트폴리오를 선택한다는 구성도 명확하다.
- 무엇보다 독립 시드 다양성과 관계 타깃 다양성을 직접 분리한 실험 설계가 좋은 방법론적 기여다.
- 반면 QLoRA 기반 다중 체크포인트, 실행 기반 후보 선택, 원본 프로그램 fallback, 편집 거리 gate는 각각 기존 개념의 조합에 가깝다.
- 직렬화된 궤적 정보 자체의 효과가 검증되지 않았기 때문에 “trajectory-conditioned repair”를 핵심 알고리즘적 진보로 보기 어렵다.

### 2. 중요성

중요성은 중간 수준이다.

독립 체크포인트 다양성이 복잡한 정책 설계보다 수리율을 더 많이 설명한다는 결과는 LLM 기반 APR 평가 관행에 유익하다. 또한 무제약 정확도와 작은 패치의 coverage frontier를 분리한 점은 실제 배포 판단에 도움이 된다.

다만 최종적으로 확립된 새로운 효과가 제한적이다.

- \(M_9-A_9\) 무제약 Seen 차이는 +1.71점이며 신뢰구간이 0을 포함한다.
- Unseen에서는 차이가 0이다.
- Java student-held-out에서도 +0.55점으로 불확정적이다.
- 편집 예산 평균 차이는 Seen에서 +1.22점으로 경계적으로 양수이지만, 문제 정체성을 분리해 선택하면 평균 신뢰구간이 다시 0을 포함한다.
- TED와 소스 보존이 교육적 유용성, 이해 가능성, 학습 효과를 뜻하지 않는다는 점은 저자도 인정한다.

따라서 “관계 타깃이 실질적으로 더 좋은 수리를 학습한다”는 강한 결론보다는, “무제약 coverage는 시드 다양성이 설명하며 관계 타깃은 일부 편집 제약에서만 작은 차이를 보인다”는 진단 연구로 위치시키는 편이 타당하다.

### 3. 건전성

전체적으로 매우 신중하지만 핵심적인 우려가 있다.

첫째, Seen 포트폴리오 선택에 사용된 461개 문제 중 323개가 최종 Seen test의 328개 문제와 겹친다. 궤적은 다르더라도 동일 과제의 구현 패턴, 난이도, 테스트 구조가 포트폴리오 선택에 반영될 수 있다. 실제로 시험 문제를 선택 집합에서 배제하면 \(M_9\)과 \(A_9\)의 우열이 뒤집히고, \(A_9-M_9=+2.91\)로 Answer-only 풀이 유의하게 앞선다. 이 결과는 단순한 위협 분석이 아니라 핵심 target-composition 주장에 직접 영향을 준다.

둘째, Answer 체크포인트는 단일 현재 제출만 포함한 입력으로 학습하지만, 검증·시험에서는 전체 제출 궤적을 받는다. 동일한 평가 정보를 제공한다는 의미에서는 대칭적이지만, Answer-only 통제군에만 학습-추론 프롬프트 분포 차이가 생긴다. 혼합 타깃의 두 관계는 다중 제출 prefix로 학습되므로, 현재 비교만으로 관계 타깃과 입력 형식 적합성을 완전히 분리했다고 보기 어렵다.

셋째, Progress/Strict/Answer 데이터는 예제 수, 타깃까지의 거리, prefix 길이, 타깃 분포가 함께 달라진다. \(M_9\) 대 \(A_9\)는 “전체 관계별 데이터 구성 패키지”의 효과는 측정하지만, 실행 관계의 의미론 자체가 패치 범위를 만들었다는 인과 해석은 어렵다.

넷째, verdict severity 순서에 대한 사후 label audit은 있지만 대안 순서로 실제 재학습한 민감도 실험은 없다. Progress와 Strict의 정의가 이 임의적 순서에 의존하므로, 적어도 대표적인 대안 순서에 대한 모델 수준 확인이 필요하다.

### 4. 평가

평가는 논문의 가장 강한 부분이다.

- 997개 Seen, 250개 problem-held-out Unseen 사례를 사용한다.
- 동일한 생성 예산과 기반 모델을 사용한다.
- Answer-only 9-checkpoint 풀과 동일한 84개 포트폴리오 선택 기회를 제공한다.
- 문제 단위 군집 부트스트랩과 문제 균등 가중 추정치를 함께 보고한다.
- LSGen과의 무제약 coverage 및 편집 예산 frontier를 모두 제시한다.
- 관측/숨은 테스트 분할과 Java student-held-out 데이터 재학습을 포함한다.
- 부정적 결과와 불안정한 selector를 숨기지 않는다.

그러나 다음 결함이 크다.

- 서론의 기여 목록은 “second model scale”과 “student- and exercise-held-out Java replications”를 명시한다. 5.4절에도 1.5B 모델과 10/3/4 exercise-held-out split이 기술되어 있지만, 결과 절에는 이 두 실험의 결과가 없다.
- 하나의 기존 테스트 스위트를 해시로 절반 나눈 hidden confirmation은 후보 선택과 성공 평가의 분리에는 유용하지만, 독립적으로 제작된 숨은 테스트나 의미적 정확성 검증과 동등하지 않다.
- 편집 예산 5, 10, 20, 40, 80, 160의 실무적 의미가 충분히 정당화되지 않는다. 특히 AST 종류와 프로그램 크기가 다양한 상황에서 절대 TED의 해석이 어렵다.
- post-hoc 크기 정규화 분석과 다수의 포트폴리오·예산·추정치가 함께 제시되므로, 사전 선언된 분석과 탐색적 분석의 경계를 더 명확히 해야 한다.

### 5. 표현

표현 품질은 대체로 높다.

- 핵심 비교 구조가 명시적이고, 과도한 인과·교육적 주장을 스스로 제한한다.
- 표와 그림은 읽기 쉽고 렌더링 오류도 발견되지 않았다.
- 18쪽 본문과 3쪽 참고문헌으로 분량 제한도 충족한다.
- 익명화 역시 외견상 적절하다.

반면 원고가 매우 조밀하며, 같은 부정적 결론과 수치가 초록, 결과, Discussion, Conclusion에서 반복된다. 이 공간을 누락된 replication 결과나 실험별 데이터 흐름 설명에 사용하는 편이 낫다. “ZPD”라는 명칭도 실제 학습·도움 효과를 측정하지 않는다는 논문의 범위와 긴장을 만든다.

### 6. 재현성

재현성에 대한 기술은 강한 편이다.

- 데이터 필터링, split, seed, 학습 파라미터, runner, timeout, 메모리 제한, 포트폴리오 탐색, 통계 절차가 상세하다.
- AI 도구가 연구 과정에 사용된 방식도 구체적으로 공개한다.
- 해시로 고정된 선택과 revision-bound manifest를 언급한다.

그러나 PDF만으로는 artifact를 실제로 찾거나 검증할 수 없다. 결론 끝의 “Data availability.” 한 문장은 FSE CFP가 요구하는, Conclusion 뒤의 `Data Availability`라는 이름의 독립 섹션으로 보기 어렵다. 익명 artifact 접근 방법, 환경 고정 정보, 실행 명령, 결과-표 매핑이 명시되어야 한다.

## 강점

- 예상과 다른 결과를 정직하게 보고하고 주장을 좁혔다.
- 독립 학습 시드와 관계 타깃 다양성을 구분하는 \(A_1/A_3/A_9/M_9\) 설계가 훌륭하다.
- Answer-only 9-checkpoint 통제군은 이 분야에서 드물게 강한 비교다.
- 실행 기반 fallback은 관측 테스트 비회귀를 명확한 불변식으로 보장한다.
- 문제 단위 의존성을 통계 분석에 반영했다.
- 무제약 coverage와 edit-constrained coverage를 분리했다.
- problem-held-out Python과 student-held-out Java를 포함해 범위가 넓다.
- 선택 불안정성, 사용자 중복, ZPD 해석 한계를 숨기지 않는다.

## 약점

- 논문의 이름과 동기는 궤적의 중요성을 강조하지만, 직접적인 history serialization 효과는 안정적으로 나타나지 않는다.
- 핵심 관계 타깃 효과가 작고, Unseen·Java·문제 분리 selector에서 일관되게 재현되지 않는다.
- Seen validation과 test의 문제 정체성 중복이 포트폴리오 선택 효과를 낙관적으로 만들 수 있다.
- Answer-only 통제군은 학습 때 보지 않은 다중 제출 프롬프트를 추론 때 받아 완전히 공정한 target-composition 통제가 아니다.
- 광고된 1.5B 및 exercise-held-out 결과가 누락되어 있다.
- TED/source retention이 실제로 더 유용하거나 이해 가능한 학생 피드백이라는 근거는 없다.
- LSGen보다 무제약 수리율이 크게 낮으며, 제안법의 실용적 우위는 특정 편집 예산 구간에 국한된다.
- Data Availability 형식과 artifact 접근성이 불충분하다.

## 필수 개선 사항

1. **누락된 결과를 제시해야 한다.** 1.5B scale replication과 exercise-held-out Java 결과를 완전한 표, 불확실성 구간, 선택 절차와 함께 보고하거나, 서론·방법·기여 목록에서 해당 replication 주장을 삭제해야 한다.

2. **문제 정체성이 분리된 선택을 주 분석으로 승격해야 한다.** Seen 문제에 대해 train/validation/test 문제를 완전히 분리하거나 nested cross-fitting을 사용해 \(M_9-A_9\)와 budget frontier를 다시 추정해야 한다. 현재의 138개 disjoint-selector 분석은 감사가 아니라 핵심 결과에 가깝다.

3. **Answer 통제군의 프롬프트 분포 차이를 통제해야 한다.** 예를 들어 history-format Answer 모델, current-only inference, history-masked inference를 교차 비교해 관계 타깃 효과와 입력 형식 적합성을 분리해야 한다.

4. **핵심 주장을 재정렬해야 한다.** 제출 이력이 수리를 개선한다는 인상을 줄이고, 주요 확립 결과를 “checkpoint diversity가 무제약 coverage를 설명한다”로 명시해야 한다. 관계 타깃은 Seen의 일부 edit-constrained operating point에서만 제한적으로 지지된다고 표현해야 한다.

5. **편집 예산의 실용적 의미를 보강해야 한다.** 프로그램 크기로 정규화된 사전 지정 지표, 의미 보존/가독성에 대한 사람 평가, 또는 실제 교육 환경에서의 수용성 평가 중 적어도 하나가 필요하다.

6. **분석의 confirmatory/exploratory 경계를 명시해야 한다.** 각 가설군, Holm 보정 범위, 사전 지정 예산, post-hoc 분석을 한 표에서 구분하고, 예산별 원시 paired count도 제공해야 한다.

7. **독립된 `Data Availability` 섹션을 Conclusion 뒤에 추가해야 한다.** 익명 artifact 위치, manifest hash, 환경과 실행 절차, 표별 원자료 경로를 명시해야 한다.

### 최종 의견

이 논문은 실험적 정직성, 통제군 설계, 통계적 신중함 면에서 매우 인상적이다. 특히 “복잡한 궤적 정책의 효과처럼 보이는 향상이 실제로는 독립 체크포인트 다양성에서 왔다”는 결과는 출판 가치가 있다. 하지만 현재 원고는 입증되지 않은 궤적 효과를 명칭과 기여의 중심에 유지하며, 핵심 관계 타깃 효과는 선택 문제 중복에 민감하다. 더구나 명시적으로 약속한 두 replication 결과가 누락되어 있다. 이 문제들이 수정되면 채택 가능한 논문이 될 가능성이 높으므로, 단순 Reject보다는 **Major Revision**이 가장 적절하다.
