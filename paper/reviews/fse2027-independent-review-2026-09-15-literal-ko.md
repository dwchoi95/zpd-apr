## 논문 요약

ZPDPatch는 제출 궤적에서 Progress, Strict, Answer 관계로 학습 쌍을 만들고, 실행 결과에 따라 여러 생성 후보 중 수리 결과 또는 원본을 선택한다. 논문은 이 시스템의 성능 증가를 하나의 궤적 효과로 묶지 않고, 반복 샘플링, 독립 학습 시드, 검증 기반 풀 선택, 타깃 종류, 학습 타깃의 출처, 입력 이력의 효과를 나누어 조사한다.

동일 소스·동일 개수의 학습 쌍을 사용하는 대조에서 Answer는 Progress보다 Python Seen/Unseen 수리율이 19.2/11.2%p 높지만, 공동 성공 사례에서 Progress는 더 작은 AST 편집과 더 높은 원문 보존을 보인다. 학생 분리 Java에서도 수리율 85.6% 대 50.8%, 공동 성공 사례의 토큰 보존 차이 4.8%p로 방향이 재현된다. 한편 이력 입력과 혼합 타깃 풀의 일반적 수리율 우위는 성립하지 않으며, 같은 디코더에서 반복 추출하는 효과는 분명하지만 서로 다른 체크포인트의 추가 이득은 견고하지 않다.

## 주요 강점

1. **핵심 비교의 통제가 상당히 충실하다.** 단순히 Zero-shot 대비 성능 증가를 궤적의 효과라고 해석하지 않는다. 동일 후보를 재사용하는 T1–S3 대조, 동일 풀 크기와 검증 선택 기회를 부여한 M9–A9 대조, 동일 소스와 개수의 Progress–Answer 학습이 서로 다른 질문을 다룬다. 처음의 S3–A3 대조가 디코더까지 바뀐다는 사실을 명시하고 별도의 디코딩 일치 실험을 추가한 것도 중요하다(6–7, 10–12, 15–16쪽).

2. **가장 중요한 타깃 결과는 직접적인 외부 재현을 갖는다.** Java의 단순 혼합 풀 재현과, 동일 소스의 Progress/Answer를 다시 학습한 직접 재현을 구별한 점이 좋다. 후자는 언어뿐 아니라 학생 분리 설정도 바꾸며, 수리율과 원문 보존의 양쪽 방향을 재현한다(Table 11, 17–18쪽). 따라서 Python의 한 성공 부분집합에서만 나타난 우연한 패치 크기 차이보다 강한 증거다.

3. **실패한 가설을 결과의 일부로 다룬다.** 혼합 타깃의 보편적 수리율 이득 부재, 이력 제거 후의 개선, peer 타깃의 우위, 1.5B에서의 부호 반전, vLLM에서의 성능 변화가 모두 본문에 남아 있다. 통계적 비유의성을 효과가 정확히 0이라는 결론으로 바꾸지 않는 점도 적절하다. ZPD나 작은 패치를 학습 효과의 대리 증거로 주장하지 않는 절제도 신뢰도를 높인다.

4. **평가의 의존성과 선택을 신경 썼다.** 문제 클러스터 부트스트랩, 문제 기반 교차 적합, Java 학생·과제별 클러스터 분석, 공동 수리 사례의 패치 비교, 관측 테스트만으로 프롬프트를 재생성한 withheld-slice 감사가 있다. 각 감사가 해결하지 못하는 문제도 대체로 명시한다. 같은 테스트 모음의 분할이 독립적인 의미적 오라클이 아니라는 인정은 특히 적절하다.

5. **제약된 배포 문제를 측정 가능한 형태로 정의한다.** 원본을 후보에 포함시키고 실행 통과율과 편집 예산을 기준으로 선택하는 계약은 명료하다. 구문 오류 입력의 AST 거리가 정의되지 않는 경우까지 처리한다. LSGen의 무제한 수리율 우위와 유한 TED 예산에서의 다른 양상을 함께 보여 주어, 정확성과 변경량을 섞어 평가하지 않는다.

## 주요 약점 및 우려

1. **독창성과 중요성은 알고리즘보다 실험 설계에 집중되어 있다.** 식 (4)의 후보 합집합 이득, 84개 조합의 전수 탐색, 원본 fallback을 통한 관측 통과율 비감소는 유용한 명세이지만 강한 새 이론으로 보기는 어렵다. 여덟 편의 목적 표집 감사 역시 광범위한 분야 전체의 보고 관행을 입증하지 않는다. 논문은 대체로 이 한계를 인정하지만, 시스템 설명과 여러 대조실험의 분량에 비해 “이 연구가 없었다면 연구자가 어떤 잘못된 결론을 내리게 되는가”에 대한 종합 설명은 짧다. 새로운 학습 타깃 설계에 대한 실증적 교훈을 더 전면에 놓는 편이 기여를 선명하게 만든다.

2. **배포 및 편집 예산 비교가 최신의 가장 단순한 경쟁 조건까지 닫혀 있지는 않다.** Table 10의 vLLM current-only 설정에서는 단일 체크포인트 3회 추출이 greedy 3체크포인트보다 수리율이 높다(Seen 66.8 대 62.9). 그러나 Table 5의 예산 전선에는 이 current-only stochastic 단일 체크포인트 기준선이 없다. 현재 Table 5는 해당 ZPDPatch와 LSGen 및 historical current A3의 비교를 뒷받침하지만, “작은 변경을 원할 때 혼합 궤적 포트폴리오가 가장 합리적이다”라는 일반적 선택까지 뒷받침하지는 않는다. 원고가 이를 보편적 최적해로 단정하지는 않으므로 핵심 타깃 결과를 무효화하는 문제는 아니지만, 배포 권고의 근거는 아직 불완전하다.

3. **추론 스택에 따른 변화가 크고, 서로 다른 실험 묶음의 연결이 어렵다.** 같은 current-only greedy 세 체크포인트의 Seen 수리율이 historical Transformers에서는 72.0%, vLLM에서는 62.9%다. 이를 숨기지 않는 것은 좋지만, 독자는 어떤 주장을 어느 스택에서 재현해야 하는지 여러 절을 왕복해야 한다. 동일 가중치라도 양자화·토크나이저·프롬프트 렌더링·종료 조건 등이 어느 수준으로 일치했는지, 차이가 backend 자체인지 다른 설정과 묶인 차이인지 PDF만으로 충분히 판단하기 어렵다. 이 민감도가 Progress–Answer와 peer 대조에도 적용되는지 알 수 없다. 따라서 현재 증거를 다른 추론 환경으로 일반화하는 것은 이르다.

4. **원문 보존이라는 핵심 측정량의 정의와 실용적 해석이 부족하다.** §5.6은 AST TED를 비교적 상세하게 설명하지만, token/line retention의 정확한 분모, 정렬 방식, 반복 토큰 처리, 정규화 규칙은 제시하지 않는다. Table 11과 초록에서 핵심 결론을 담당하는 지표인 만큼 본문에서 재구현 가능한 정의가 필요하다. 또한 공동 성공 사례의 비교는 같은 입력에서 패치 크기를 비교한다는 장점이 있지만, Progress가 실패하고 Answer만 성공하는 사례의 비용을 포함한 전체 사용자의 이익은 아니다. 이 조건부 성격은 표에 명시되어 있으나, 대표적인 실제 패치 쌍이 없어 5%p 안팎의 보존 증가가 어떤 종류의 변경을 뜻하는지 직관적으로 확인하기 어렵다. 학습 효과를 주장하지 않으므로 사용자 실험을 채택의 필수 조건으로 요구하는 것은 아니다.

5. **모집단과 검정 불확실성은 더 명료하게 제시할 필요가 있다.** 결국 성공한 궤적만 포함하고, Python은 자주 등장하는 사용자와 문제를 선별하며, Seen의 최종 평가가 1,754개 궤적에서 997개 입력으로 줄어든다. 범위 제한은 명시되어 있지만 재실행 탈락 사유별 수와 분포가 없다. peer 분석도 학습 Progress 소스의 24.4%라는 선택된 overlap population에 한정된다. 이 결과를 모든 실패나 임의의 peer 대체로 확대하면 안 된다. 아울러 제시된 클러스터 구간은 고정된 학습 결과의 테스트 표본 불확실성을 주로 반영한다. 세 시드를 사용했다는 사실과 학습 시드를 바꿨을 때 타깃 효과 자체가 얼마나 변하는지는 별개이므로, 시드별 대조 결과를 보완하면 더 설득력 있다.

6. **재현 가능성의 실행 경로가 아직 제출본에 없다.** Data Availability는 익명 배포를 계획한다고만 쓰고 실제 링크나 제공 위치를 제시하지 않는다. 이 리뷰에서는 저장된 결과와 프로토콜 동결·감사에 관한 주장을 검증할 수 없었다. 공개 archival identifier가 없는 것 자체는 핵심 문제가 아니며, 제출 시 심사자가 접근할 수 있는 익명 패키지와 claim–evidence 대응이 필요하다. 공식 안내도 심사용 replication package 제공 또는 제공할 수 없는 이유의 설명을 요청한다. ## FSE 기준별 판단

- **Originality:** 중간. 개별 구성 요소의 새로움은 제한적이지만, 학습 소스와 타깃 출처까지 연결한 분해 평가와 직접 Java 재현은 의미 있는 실증적 차별점이다.
- **Importance of contribution:** 중간 이상. 후보 수 증가를 궤적·앙상블·학습 타깃 효과로 오인하지 않도록 하는 교훈과, 타깃 설계에 따른 수리율–보존성 교환관계가 APR 평가에 유용하다. 단, 교육적·산업적 효용의 크기는 아직 측정되지 않았다.
- **Soundness:** 대체로 양호. 주요 대조와 주장 범위는 잘 맞으며 부정적 결과를 적절히 해석한다. provenance를 사용자 정체성만의 인과 효과로 해석하지 않는 점도 타당하다. 스택 이질성, 조건부 locality, 고정 시드 결과의 일반화가 남는 제한이다.
- **Evaluation:** 강한 편. 단순 비교를 넘어 여러 통제와 두 종류의 Java 분할을 제공한다. 현재 코드만 사용하는 샘플링의 유한 예산 전선, 핵심 지표 정의, 탈락 흐름과 시드별 결과가 보강되면 완성도가 높아진다.
- **Quality of presentation:** 중간. 확인한 렌더링에서 주요 표·그림의 잘림이나 겹침은 없고, 본문 18쪽과 참고문헌 3쪽은 공개된 초기 제출 분량 범위에 들어간다. 다만 historical/canonical/current-only/follow-up 실험이 누적된 구조라 핵심 결론을 추적하기 어렵다. 초록에도 서로 다른 설정의 숫자가 지나치게 많이 들어 있다.
- **Comparison to related work:** 대체로 적절하나 깊이는 제한적. LSGen의 추가 정보 접근 권한과 Unseen 제외 이유를 명시하고, pass@k 자체의 새로움을 주장하지 않는 것은 좋다. 문헌 감사의 사례별 판정 근거와 동결 규칙은 실제 패키지에서 확인 가능해야 하며, 이 리뷰는 인용된 논문 원문까지 검증하지 않았다.

## 수정 필요사항과 저자 질문

1. 핵심 주장마다 입력 형태, 학습 데이터, 체크포인트, 디코더, 추론 backend, 선택 규칙, 평가 모집단을 한눈에 연결하는 설정 표를 추가하라. 특히 Table 6의 72.0%와 Table 10의 62.9%가 어떤 설정 차이에서 나온 것인지 정확히 분리해 설명해야 한다.
2. token/line retention을 수식이나 짧은 알고리즘으로 정의하고, 실제 공동 성공 패치 예시를 제시하라. Progress의 보존 이점이 반복문 구조 유지인지, 이름 유지인지, 보일러플레이트 차이인지 보여 주면 효과의 의미가 더 분명해진다.
3. 편집 예산 배포 권고를 유지하려면 current-only 단일 체크포인트 stochastic 3-draw 조건도 동일 예산에서 비교하는 것이 가장 직접적이다. 추가 평가가 없다면 현재 비교한 정책 집합 내의 결과로 명확히 한정하라.
4. Source-matched Progress–Answer 및 peer 대조의 시드별 효과와 학습 타깃의 길이·거리 분포를 제공하라. 핵심 효과가 특정 학습 실행 하나나 소수의 긴 타깃에 의해 좌우되는지 판단하는 데 도움이 된다.
5. 1,754→997 및 259→250의 실행 필터링 사유별 수와, peer 매칭으로 남은 소스의 기본 분포를 보고하라. 기존 효과를 전 모집단의 효과로 바꿀 필요는 없으며, 어디에 적용되는지만 더 명료하게 하면 된다.
6. 익명 아티팩트 접근 경로, 실행 명령, 환경 고정 정보, 표별 근거 위치를 제출본에서 제공하라. 증거를 읽기 어려운 historical/canonical/post-review 명칭은 독립적으로 이해 가능한 설정 명칭으로 정리하는 편이 좋다.

## 최종 의견

나는 제한적인 채택을 지지한다. 가장 설득력 있는 기여는 “궤적을 넣으면 더 잘 고친다”가 아니라, 그 가설을 공정한 대조로 분해하여 반복 생성의 이득, 입력 이력의 불확실한 가치, 타깃 구성의 수리율–원문 보존 교환관계를 구별한 점이다. 직접 Java 재현 덕분에 마지막 결과는 단일 벤치마크의 관찰을 넘어선다. 다만 새로운 범용 수리 알고리즘이나 교육적 개인화의 성공으로 과장해서는 안 되며, 재현 설정의 정리와 locality 측정 정의, 배포 비교의 범위 명확화가 필요하다.
