\begin{abstract}
우리는 accepted solution이 아니라 실행 증거로 target을 구성해 수리 피드백을 학생 자신의 코드에 맞추는 trajectory-supervised 기법 \textsc{ZPDPatch}를 제시한다. 학생에게 돌아가는 수리는 그 자체가 피드백이므로, 테스트를 통과하는지와 함께 그 수리가 학생의 프로그램을 얼마나 대체하는지가 중요하다. 우리는 supervision이 그 이력에 의존하는 수리를 \emph{trajectory-conditioned}라 부르는데, 이력을 쓰는 시스템은 후보를 더 많이 생성하기만 해도 좋아지고 target 규칙을 바꾸면 학습 모집단도 함께 바뀌므로 어떤 단일 비교도 그 이득을 입증하지 못한다. 우리 목표는 target 규칙의 효과를 추가 후보와 직렬화된 이력의 효과에서 분리하는 것이다. \textsc{ZPDPatch}는 세 가지 실행 증거 관계를 mine하고, adapter를 독립적으로 학습하며, 회귀 대신 제출물을 그대로 반환하는 gate 뒤에서 validation으로 고정한 portfolio를 선택한다. 181개 student-held-out Introductory Programming (CS1) Java trajectory에서 source와 개수를 맞춘 학습 하에 terminal target은 155개를, progress target은 92개를 수리하며, 17개 exercise 중 15개에서 terminal이 앞선다. 두 규칙이 모두 수리한 90개 trajectory에서 progress 규칙의 retention 이득은 학생의 63.3\%에서 0이고 31.1\%에서 양, 5.6\%에서 음이다. 학습에서 본 문제의 997개 입력과 보류된 문제의 250개 입력으로 이루어진 online-judge 코퍼스도 같은 트레이드오프를 재현하며, coverage는 19.2와 11.2 퍼센트포인트 낮고 보존된 source token은 5.6과 6.5 포인트 많다. 고정된 후보 draw 세 번만으로 수리율이 15.1 포인트 더해지며, 이 수치들은 피드백을 기술하고 학습 효과를 말하지 않는다. 따라서 우리는 current-only terminal portfolio를 유지한다.
% We present \textsc{ZPDPatch}, a trajectory-supervised technique that aims repair feedback at a student's own code by constructing targets from execution evidence rather than from accepted solutions. A repair returned to a student is feedback, so how much of their program it replaces matters alongside whether the tests pass. We call repair whose supervision depends on that history \emph{trajectory-conditioned}, and no single comparison establishes a benefit for it, because more candidates alone improve a history-aware system and a new target rule also changes the training population. Our goal is to separate the target rule's effect from those of extra candidates and serialized history. \textsc{ZPDPatch} mines three execution-evidence relations, trains independent adapters, and selects a validation-frozen portfolio behind a gate that returns the submission unchanged rather than a regression. On 181 student-held-out Introductory Programming (CS1) Java trajectories under source- and count-matched training, terminal targets repair 155 and progress targets 92, leading on 15 of 17 exercises. On the 90 trajectories both rules repair, the retention advantage is zero for 63.3\% of students, positive for 31.1\%, and negative for 5.6\%. An online-judge corpus of 997 inputs from problems seen in training and 250 from held-out problems reproduces the tradeoff, with 19.2 and 11.2 percentage points less coverage and 5.6 and 6.5 points more retained tokens. Three fixed candidate draws alone add 15.1 points of repair rate, and these numbers describe the feedback, not learning. We therefore retain the current-only terminal portfolio.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

Automated Program Repair (APR)는 테스트를 통과하지 못하는 프로그램에 가할 변경을 찾아 통과하는 것을 남긴다~\cite{gazzola2019automatic,monperrus2018automatic,weimer2009automatically,legoues2012genprog}. 과목은 자동 채점기를 통과하지 못한 제출마다 이것을 돌릴 수 있어서, 수리는 모든 실패한 시도에 닿는 피드백이 된다~\cite{keuning2018systematic}. 연습문제에서 학생은 한 번만 제출하지 않는다. 같은 문제에 반복해 제출하고 매번 어떤 테스트가 실패했는지를 돌려받으므로, 수리 도구가 마주하는 것은 버기 프로그램 하나가 아니라 한 학생이 그 문제를 풀어 온 순서열이고, 그중 어느 제출에 피드백을 줄지는 과목이 정한다~\cite{duan2024tiktoc}. 버기 제출과 그 연습문제의 테스트가 주어지면 기법은 그 테스트를 모두 통과하는 프로그램을 반환하므로, 학생이 받는 것은 판정만이 아니라 자기 연습문제가 동작하는 한 판본이다~\cite{joshi2023repair,zhang2024pydex}. 그 한 판본을 만들려면 기법은 제출물의 어디가 틀렸고 그 자리에 무엇이 서야 하는지를 골라야 하며, 그 자리를 채울 코드는 교수자의 해답에서, 다른 학생의 통과한 프로그램에서, 또는 코드로 학습된 모델에서 온다.
% Automated Program Repair (APR) searches for a change to a program that fails its tests and keeps one that passes them~\cite{gazzola2019automatic,monperrus2018automatic,weimer2009automatically,legoues2012genprog}. A course can run it on every submission the autograder rejects, which turns repair into feedback that reaches every failed attempt~\cite{keuning2018systematic}. On an exercise a student does not submit once. They submit repeatedly to the same problem and are told each time which tests failed, so what a repair tool faces is not one buggy program but the sequence in which one student has worked at that problem, and the course decides which submission in it gets feedback~\cite{duan2024tiktoc}. Given a buggy submission and the tests of its exercise, a technique returns a program that passes all of them, so what the student receives is not only a verdict but a working version of their own exercise~\cite{joshi2023repair,zhang2024pydex}. To produce that version, a technique has to choose where the submission is wrong and what should stand in its place, and the code that fills that place comes from an instructor's solution, from other students' passing programs, or from a model trained on code.

학생 프로그램을 수리할 때의 핵심 설계 결정은 그 자리를 무엇으로 채우느냐, 곧 수리를 무엇을 향해 supervise하느냐다. 선행 기법들은 바로 그 출처로 갈린다. alignment 기반 기법은 제출물을 다른 학생의 통과한 프로그램이나 교수자의 해답과 정렬하고~\cite{gulwani2018automated,wang2018search,hu2020re,heo2023referent,choi2021automated,choi2025automated}, 언어 모델 기반 기법은 버기 프로그램과 문제 설명에서 패치를 생성하며~\cite{joshi2023repair,zhang2024pydex,phung2023generating,liu2024fastfixer,yang2024cref,zhao2024peer,orvalho2025counterexample}, retrieval 기반 기법은 학습자별 해답을 찾아 생성을 유도한다~\cite{dai2026learner}. next-step hint 생성 기법은 완성된 프로그램 대신 편집 한 건을 반환하며, 그 편집을 과거의 올바른 프로그램들로 지은 해답 공간에서 끌어낸다~\cite{piech2015embeddings,rivers2017datadriven,price2017isnap,roest2024next}. 이 기법들은 학생 제출의 repair rate를 크게 높여 왔고, 조교가 볼 수 있는 것보다 많은 학생에게 다음 한 걸음이 닿게 했다~\cite{keuning2018systematic,koutcheme2024benchmarking}.
% The key design decision in repairing student programs is what fills that place, that is, what the repair is supervised toward. Prior techniques part ways over exactly that source. Alignment-based techniques align the submission with other students' passing programs or an instructor's solution~\cite{gulwani2018automated,wang2018search,hu2020re,heo2023referent,choi2021automated,choi2025automated}; language-model-based techniques generate a patch from the buggy program and the problem statement~\cite{joshi2023repair,zhang2024pydex,phung2023generating,liu2024fastfixer,yang2024cref,zhao2024peer,orvalho2025counterexample}; and retrieval-based techniques look up a learner-specific solution to steer that generation~\cite{dai2026learner}. Next-step hint generators return one edit instead of a complete program, drawn from a solution space built out of past correct programs~\cite{piech2015embeddings,rivers2017datadriven,price2017isnap,roest2024next}. These techniques have raised the repair rate for student submissions considerably, and put a next step within reach of more students than a tutor can see~\cite{keuning2018systematic,koutcheme2024benchmarking}.

그러나 기존 기법은 학생이 안내를 받으면 어디까지 갈 수 있는지를 알지 못한다. 반환물이 무엇을 향할지는 accepted solution이나 해답 공간 안의 위치로 정해지며, 학생이 지금 어떤 테스트를 통과하는지는 그 결정에 들어가지 않는다. 피드백은 학습자 자신의 작업에 구체적일 때 효과적이고~\cite{hattie2007power,shute2008focus}, 학생은 반환된 프로그램이 자기 프로그램의 무엇을 바꾸었는지 찾아내야 하며 그 변경을 따라갈 수 있는 만큼만 도움이 된다~\cite{narciss2008feedback,aleven2000limitations}. 근접발달영역(ZPD)은 학습자의 능력을 혼자서 해낼 수 있는 것, 안내를 받으면 해낼 수 있는 것, 안내를 받아도 닿지 않는 것으로 나누며, 학습자를 다음 걸음으로 옮기려면 지원이 가운데 영역에 놓여야 한다~\cite{cole1978mind}. 제출물은 학생이 혼자서 만들어 낸 것이므로 첫 영역이 어디서 끝나는지를 보여 주고, 수준을 고려하지 않고 고른 피드백은 그 경계 너머 어디에나 놓일 수 있다. 그 영역들을 짚어내려면 그 자체로 별도의 측정이 필요하지만~\cite{murray2002toward,chounta2017grey,schulze2024beyond}, 반환물과 제출물 사이의 거리는 관측할 수 있다. 가장 강한 선행 baseline의 반환물은 제출물에서 평균 88.27 AST 편집 떨어져 있다(Section~\ref{sec:experiment}). 즉, 기존 기법은 학생이 다음에 밟을 한 걸음이 아니라 완성된 남의 해답을 돌려준다. 이 연구에서 우리는 supervision이나 생성된 변경이 현재 제출에 이르는 순서열에 의존하는 수리를 \emph{trajectory-conditioned repair}로 정의하고, 그 target이 반드시 그 학생 자신의 것이어야 하는지를 따로 묻는다. 세 범주 모두 대체 코드를 이 제출물 밖에서, 즉 완성된 해답이나 과거 cohort의 경로에서 가져오므로, 반환물이 겨냥하는 지점은 이 학생이 지금 어디까지 왔는지와 무관하게 정해진다. 우리가 측정하는 것은 반환된 프로그램이 제출물에서 무엇을 남기는지이며, 어떤 학생의 영역도 재지 않는다.
% However, existing techniques do not know how far a student can get with guidance. What a return aims at is settled by an accepted solution or by a position in a solution space, and which tests the student currently passes does not enter that decision. Feedback works better when it is specific to the learner's own work~\cite{hattie2007power,shute2008focus}, and the student has to find what the returned program changed in theirs, which helps only as far as they can follow that change~\cite{narciss2008feedback,aleven2000limitations}. The Zone of Proximal Development divides a learner's ability into what they can already do unaided, what they can do with guidance, and what stays out of reach even with it, and support has to land in the middle region to move the learner forward~\cite{cole1978mind}. A submission is what the student produced unaided, so it marks where that first region ends, and feedback chosen without regard to the student's level can land anywhere beyond it. Locating those regions takes measurement of its own~\cite{murray2002toward,chounta2017grey,schulze2024beyond}, but the distance between a return and the submission is observable. The returns of the strongest prior baseline sit 88.27 AST edits from the submission on average (Section~\ref{sec:experiment}). That is, existing techniques hand back somebody else's finished solution rather than the next step the student could take. In this work we define \emph{trajectory-conditioned repair} as repair whose supervision or generated change depends on the sequence leading to the current submission, and we ask separately whether that target has to be this student's own. All three categories draw the replacement from outside this submission, from a finished solution or from the paths of a past cohort, so where a return aims is fixed independently of how far this student has got. What we measure is what the returned program keeps of the submission, and we measure no student's regions.

이 논문에서는 버기 제출을 학생이 안내를 받으면 도달할 수 있는 다음 걸음을 향해 수리하는 trajectory 기반 기법 \textsc{ZPDPatch}를 제안한다. 핵심 아이디어는 학생 자신의 trajectory가 그 걸음을 이미 기록하고 있다는 것이다. 실제로 다음에 온 제출은 그 학생이 머지않아 혼자서 도달한 프로그램이고, 그것이 어떤 테스트를 새로 통과했는지는 실행 증거가 말해 준다. 다만 이 target만 따로 갈아 끼울 수는 없다. target을 짓는 규칙을 바꾸면 학습 예제 수와 source 출현 빈도가 함께 바뀌고, 생성 후보를 더 주는 것만으로도 수리율이 오른다(Section~\ref{sec:limitation}). 따라서 \textsc{ZPDPatch}는 source와 예제 수, 후보 예산을 고정하고, target을 맞춘 동료의 것으로 바꿔 끼워 그것이 반드시 그 학생 자신의 것이어야 하는지를 따로 묻는다. 이를 위해 \textsc{ZPDPatch}는 Mine, Train, Select의 세 단계로 동작한다. Mine 단계는 버기 제출이나 trajectory의 보존된 prefix를 이후 제출과 세 규칙으로 짝짓는다. Progress는 판정이 나아지거나 판정은 같아도 통과 테스트가 늘어난 다음 상태를, Strict는 판정이 나아진 다음 상태를, Answer는 trajectory가 도달한 accepted 제출을 취하는데, Answer는 관례적 target을 비교 기준으로 둔다. 같은 시간순 짝을 캐어 제출물에 맞는 해답을 찾아 쓰는 retrieval 기반 기법~\cite{dai2026learner}과 달리, 이 짝들은 supervision 신호 자체가 된다. Train 단계는 규칙마다 adapter를 독립적으로 적합시킨다. Select 단계는 학습 손실이 아니라 실행된 validation 수리를 기준으로 checkpoint 세 개의 조합을 고정하며, 이어서 실행 gate가 과목이 선언한 edit budget 안에서 수리를 반환하거나 버기 프로그램을 유지한다. 그 결과 학생이 받는 것은 서술된 편집이 아니라 완성된 프로그램이므로 그것이 자기 제출물을 얼마나 대체하는지를 재고 제한할 수 있으며, 제출물의 관측된 통과율을 낮추는 수리를 과목이 받는 일은 없다.
% In this paper, we present \textsc{ZPDPatch}, a trajectory-supervised technique that repairs a buggy submission toward the next step the student could reach with guidance. Our key idea is that the student's own trajectory already records that step. The submission that actually came next is a program the student reached unaided soon after, and the execution evidence says which tests it newly passed. This target, however, cannot be swapped in on its own. Exchanging the rule that builds it changes the number of training examples and the source frequencies together, and extra generated candidates raise the repair rate by themselves (Section~\ref{sec:limitation}). \textsc{ZPDPatch} therefore holds the sources, the example counts, and the candidate budget fixed, and replaces the target with a matched peer's to ask separately whether it has to be this student's own. To this end, \textsc{ZPDPatch} operates in three stages, Mine, Train, and Select. The Mine stage pairs a buggy submission, or a retained prefix of the trajectory, with a later submission under three rules. Progress takes the next state that improves the verdict or passes more tests at an unchanged verdict, Strict the next better-verdict state, and Answer the accepted submission the trajectory reached, which holds the conventional target for comparison. Unlike retrieval-based techniques that mine the same chronological pairs to look up a solution for the submission~\cite{dai2026learner}, these pairs supply the supervision signal itself. The Train stage fits an independent adapter per rule. The Select stage freezes a triple of checkpoints by their executed validation repairs rather than by training loss, and an execution gate then returns a repair or retains the buggy program within the edit budget a course declares. As a result, what a student receives is a complete program rather than a described edit, so how much of their own submission it replaces can be measured and bounded, and a course never receives a repair that lowers the submission's observed pass rate.

실험 결과는 \textsc{ZPDPatch}가 비교한 기법들 가운데 학생의 프로그램을 가장 적게 바꾸고, 편집량을 제한하면 가장 최신의 선행 기법보다 더 많은 제출을 고침을 보여 준다. 우리는 Project CodeNet~\cite{puri2021project}의 382개 문제에서 모은 1,247개 버기 제출과 CodeWorkout~\cite{duan2024tiktoc}의 CS1 exercise 17개에서 모은 181개 제출로 \textsc{ZPDPatch}를 평가하였으며, 각 입력은 이후 성공한 trajectory의 마지막 실패 제출이다. 비교 대상은 가장 최신의 선행 기법 LSGen~\cite{dai2026learner}과 미세조정하지 않은 같은 기반 모델 Zero-shot이다. AST 연산 20개의 edit budget에서 \textsc{ZPDPatch}는 Python 제출의 44.0\%를 고쳐 LSGen(13.9\%)보다 많이 고쳤고, 사전에 지정한 여섯 budget 전체에서 평균 14.7 포인트 더 고쳤다. \textsc{ZPDPatch}의 패치는 평균 21.05개의 AST 노드를 바꾸어 LSGen(88.27)과 Zero-shot(27.25)보다 적게 바꾸었다. source를 맞춘 조건에서 Progress target은 두 규칙이 모두 고친 입력에서 학생의 token을 5.6과 6.5 퍼센트포인트 더 유지했지만, 19.2와 11.2 포인트를 덜 고쳤다. student-disjoint CS1 Java 재학습은 두 방향을 모두 재현했고, Answer target이 17개 exercise 중 15개에서 앞섰다. 다만 제한을 없애면 우리의 어떤 구성도 LSGen의 80.2\%를 넘지 못했으므로, 우리는 current-only Answer 3개 조합을 유지하고 Progress 규칙은 locality가 제약일 때의 선택지로 보고한다(Section~\ref{sec:experiment}).
% Experimental results demonstrate that \textsc{ZPDPatch} changes the least of a student's program among the techniques we compare, and under a bounded edit repairs more submissions than the most recent prior technique. We evaluated \textsc{ZPDPatch} on 1,247 buggy submissions from 382 problems of Project CodeNet~\cite{puri2021project} and 181 from 17 CS1 exercises of CodeWorkout~\cite{duan2024tiktoc}, each the last failing submission of a trajectory that later succeeded. We compared it with the most recent prior technique, LSGen~\cite{dai2026learner}, and with the same base model used zero-shot. At an edit budget of 20 AST operations, \textsc{ZPDPatch} fixed 44.0\% of the Python submissions, more than LSGen (13.9\%), and 14.7 points more on average across six prespecified budgets. Its patches changed 21.05 AST nodes on average, less than those of LSGen (88.27) and Zero-shot (27.25). Under matched sources, Progress targets kept 5.6 and 6.5 percentage points more of the student's tokens on the inputs both rules fixed, although they fixed 19.2 and 11.2 points fewer. Retraining on student-disjoint CS1 Java reproduced both directions, with Answer targets leading on 15 of 17 exercises. Unrestricted, however, no configuration of ours exceeded LSGen's 80.2\%, so we retain the current-only Answer triple and report the Progress rule as the option for when locality binds (Section~\ref{sec:experiment}).

문제 \(p\)에 대해 제출 상태는 튜플 \(s=(c,v,o)\)이며, 여기서 \(c\)는 완전한 소스 코드, \(v\)는 기록된 online-judge 판정, \(o\)는 사용 가능한 각 testcase 식별자를 재실행 결과로 대응시킨다. 문제 맥락 \(d_p\)는 문제 설명과 자원 제한을 담고, \(\mathcal E_p\)는 사용 가능한 테스트 묶음이다. trajectory \(\tau=[s_1,\ldots,s_n]\)은 한 사용자가 한 문제에 제출한 것들을 순서대로 놓는다. 정본 데이터셋은 각 trajectory를 처음 기록된 acceptance에서 끊는다. 이 끝점은 보존된 trajectory 내의 마지막 accepted 제출이며, acceptance 이후의 수정이 아니다. 기록된 판정과 재실행 결과는 별도 필드로 남는데, 런타임 버전과 실행 변동성이 프로그램의 관측된 거동을 바꿀 수 있기 때문이다.
% For a problem \(p\), a submission state is a tuple \(s=(c,v,o)\), where \(c\) represents complete source code, \(v\) denotes the recorded online-judge verdict, and \(o\) maps each available testcase identifier to its re-executed outcome. The problem context \(d_p\) contains the statement and resource limits, and \(\mathcal E_p\) is the available test suite. A trajectory \(\tau=[s_1,\ldots,s_n]\) orders submissions by one user on one problem. The canonical dataset ends each trajectory at its first recorded acceptance; this endpoint is the final accepted submission within the retained trajectory, not a later post-acceptance revision. Recorded verdicts and replayed outcomes remain distinct fields, because runtime versions and execution variability can change a program's observed behavior.

학습 예제는 입력 \(x=(d_p,h_i)\)와 이후 코드 \(y\)를 짝지으며, \(h_i\)는 현재 상태에서 끝나는 허용된 제출 prefix다. target constructor는 보존되는 prefix와 그 target을 함께 결정한다. 추론 시 현재 프로그램은 항상 주어지며, history-conditioned prompt는 관측된 더 앞선 제출들도 포함하지만 current-only prompt는 포함하지 않는다. 미래의 accepted 프로그램은 학습 target이거나 오프라인 평가 기준일 뿐, 추론 prompt의 일부가 되는 일은 없다. \emph{terminal target}은 Accepted(AC) 끝점이다. \emph{progress target}은 실행 증거 규칙에 따라 보존된 다음 상태이며 그 자체가 accepted일 수도 있다. \emph{intermediate target}은 보존된 비종단 상태를 가리키는 용어로 남겨 두며, Progress 데이터셋이 그런 상태로만 제한되는 것은 아니다.
% A training example pairs input \(x=(d_p,h_i)\) with later code \(y\), where \(h_i\) is the permitted submission prefix ending at the current state. A target constructor determines both the retained prefix and its target. At inference, the current program is always available; a history-conditioned prompt also includes earlier observed submissions, whereas a current-only prompt does not. The future accepted program is a training target or an offline assessment reference, never part of the inference prompt. A \emph{terminal target} is the Accepted (AC) endpoint. A \emph{progress target} is the next retained state under an execution-evidence rule and can itself be accepted. We reserve \emph{intermediate target} for a retained nonterminal state; the Progress dataset is not restricted to such states.

Here \(q\) is the fraction of tests passed, and \(\mathrm{ted}^{\dagger}\) is Abstract Syntax Tree (AST) edit distance when both changed programs parse, zero for unchanged code, and infinity otherwise. An unrestricted budget bypasses the distance check, allowing syntax repair; a finite budget rejects changes whose source distance is undefined.

이 controller는 generator 구성, 입력 맥락, 기회 수를 분리한다. reference 기반, 학습 기반, 반복적 수리는 이 선택들을 서로 다르게 구체화한다~\cite{gulwani2018automated,tufano2019empirical,yang2024cref}. 우리의 통제는 특정 구현들을 비교하는 것이며, 선행 방법이 모두 accepted 끝점으로 학습한다는 가정이 아니다.
% The controller separates generator construction, input context, and opportunity count. Reference-based, learned, and iterative repair instantiate these choices differently~\cite{gulwani2018automated,tufano2019empirical,yang2024cref}. Our controls compare specific implementations, not an assumption that all prior methods train on accepted endpoints.

\subsection{Mine}
Mine의 목표는 모든 supervision 짝이 관측된 source와 이후 제출로 추적되도록 만드는 것이다. 제출들은 문제와 사용자로 묶이고, 시간순으로 정렬되며, 첫 acceptance에서 끊긴다. 정본 정규화는 연속 중복을 제거하면서 생성과 실행에 쓰인 소스 코드는 보존한다. 빌더는 history 길이나 전이 수에 상한을 두지 않는다. 대신 whole-trajectory 필터가, 필요한 prompt--target 구성 중 하나라도 4,096 토큰을 넘으면 분할 전에 그 trajectory를 제외한다. 제외는 평가 모집단을 바꾸는 것이며, 프로그램이나 history를 잘라낸 뒤 그 조각을 완전한 것처럼 제시하는 일은 없다.
% The goal of Mine is to make every supervision pair traceable to an observed source and a later submission. Submissions are grouped by problem and user, chronologically ordered, and cut at the first acceptance. Canonical normalization removes consecutive duplicates while preserving the source code used for generation and execution. The builder imposes no maximum history or transition count. A whole-trajectory filter instead excludes a trajectory before splitting if any required prompt--target configuration exceeds 4,096 tokens. Exclusion changes the evaluated population; it never cuts off a program or history and presents the fragment as complete.

거친 severity 함수는 Accepted(AC)에 0, Wrong Answer(WA)에 1, Time 또는 Memory Limit Exceeded(TLE/MLE)에 2, Runtime Error(RE)에 3, Compile Error(CE)에 4를 부여하며, 인식되지 않은 결과와 내부 오류는 가장 심각한 범주에 둔다. 이는 운용상의 순서이며 정확성까지의 의미적 거리가 아니다. Strict는 기록된 판정을 비교한다. Progress는 기록된 판정 문자열이 같을 때 재실행 결과까지 비교한다. 그 캐시는 완전해야 하고, 비교되는 벡터들은 비어 있지 않은 동일한 testcase 키를 가져야 한다. provenance에는 문제, 코드, 테스트, 실행 구성이 포함된다. 이후 개발에서의 인프라 불확실성은 unknown으로 보고하며, 수리에 유리한 라벨로 바꾸지 않는다.
% The coarse severity function assigns 0 to Accepted (AC), 1 to Wrong Answer (WA), 2 to Time or Memory Limit Exceeded (TLE/MLE), 3 to Runtime Error (RE), and 4 to Compile Error (CE); unrecognized and internal outcomes occupy the most severe category. This is an operational ordering, not semantic distance to correctness. Strict compares recorded verdicts. Progress additionally compares replayed outcomes when the recorded verdict strings agree. Its cache must be complete, and compared vectors must have equal, nonempty testcase keys. Provenance includes problem, code, tests, and execution configuration. Infrastructure uncertainty in later development is reported as unknown, not converted into a favorable repair label.

testcase 전체 집합이 같을 때, \(o_t\prec_\times o_r\)는 \(o_t\)의 모든 테스트가 \(o_r\)의 대응 테스트보다 severity가 크지 않고 적어도 하나에서 엄격히 감소할 때 성립한다. 개선 술어는 다음과 같다:
% For equal testcase universes, \(o_t\prec_\times o_r\) holds when every test in \(o_t\) has severity no greater than its counterpart in \(o_r\), with a strict decrease on at least one. The improvement predicates are:
\begin{equation}
\begin{aligned}
\mathsf{Improves}_S(r,t)&\iff \mathrm{sev}(v_t)<\mathrm{sev}(v_r),\\
\mathsf{Improves}_P(r,t)&\iff \mathsf{Improves}_S(r,t)\\
 &\quad\lor\ (v_t=v_r\land o_t\prec_\times o_r).
\end{aligned}
\label{eq:progress}
\end{equation}
직관적으로 Equation~\eqref{eq:progress}는 거친 개선과, 판정이 바뀌지 않아 가려진 progress를 함께 보존한다. RE에서 WA로의 severity 개선이 반드시 통과 비율을 높이지는 않으며, 판정을 개선하는 간선이 테스트 단위 우위를 요구하지도 않는다. mine된 관계는 supervision을 제공하는 것이며 배포 안전성을 보장하지 않는다.
% Intuitively, Equation~\eqref{eq:progress} retains coarse improvements and progress hidden by an unchanged verdict. A severity improvement such as RE to WA need not increase the pass fraction, and a verdict-improving edge does not require test-wise dominance. The mined relation supplies supervision, not a deployment-safety guarantee.

Answer는 AC가 아닌 각 source와 accepted 끝점에 대해 독립적인 짝을 낸다. 따라서 \([s_1,\ldots,s_9]\)는 \(([s_1],c_9),\ldots,([s_8],c_9)\)를 만들며, 누적된 prefix를 Answer 학습에 노출하지 않는다. Strict와 Progress는 \(R=[s_1]\)에서 시작해 이후 각 상태를 \emph{마지막으로 보존된} 상태와 비교하고, 술어가 성립할 때만 덧붙인다. \(s_t\)를 덧붙이기 전에 빌더는 \((R,c_t)\)를 낸다. WA, 개선된 WA, AC의 경우 Strict는 \(([s_1],c_3)\)을 내고 Progress는 \(([s_1],c_2)\)와 \(([s_1,s_2],c_3)\)을 낸다. accepted 끝점은 두 규칙에서 모두 적격으로 남는다. Strict의 쌍별 술어가 Progress의 것에 포함되더라도, 독립적으로 훑어 얻은 간선 집합이 포함 관계일 필요는 없다.
% Answer emits an independent pair for each non-AC source and the accepted endpoint. Thus \([s_1,\ldots,s_9]\) yields \(([s_1],c_9),\ldots,([s_8],c_9)\); it does not expose accumulated prefixes to Answer training. Strict and Progress start with \(R=[s_1]\), compare each later state with the \emph{last retained} state, and append it only when the predicate holds. Before appending \(s_t\), the builder emits \((R,c_t)\). For WA, improved WA, AC, Strict emits \(([s_1],c_3)\), whereas Progress emits \(([s_1],c_2)\) and \(([s_1,s_2],c_3)\). The accepted endpoint remains eligible in both rules. Although Strict's pairwise predicate is contained in Progress's, their independently scanned edge sets need not be nested.

시간순 인덱스는 엄격히 증가하므로 구성은 순환 없이 종료한다. 키가 고정된 증거에서는 보존된 간선이 해당 판정/테스트 severity 순위도 낮춘다. 이는 빌더의 불변식이며, 학습된 ZPD 효과의 증거가 아니다. accepted/non-accepted 이진 mining은 Strict 짝 16,973개 중 14,027개, Progress 짝 21,416개 중 18,009개를 보존한다. 그 라벨로 재학습한 모델은 Seen 수리 결정의 84.6\%와 87.5\%에서 정본 모델과 일치하므로(Section~\ref{sec:generality}), 우리는 이 순서를 보편적인 것이 아니라 운용적인 것으로 읽는다.
% Chronological indices strictly increase, so construction terminates without cycles. With fixed-key evidence, retained edges also decrease the appropriate verdict/test severity rank. These are builder invariants, not evidence of a learned ZPD effect. Binary accepted/non-accepted mining retains 14,027 of 16,973 Strict pairs and 18,009 of 21,416 Progress pairs. Models retrained on them agree with the canonical ones on 84.6\% and 87.5\% of Seen repair decisions (Section~\ref{sec:generality}), so we read the ranking as operational rather than universal.

\subsection{Train}
Train의 목표는 모델과 최적화를 비교 가능하게 유지하면서 각 관계를 독립적으로 학습하는 것이다. 구현은 Qwen2.5-Coder-7B-Instruct를 4-bit 양자화 Low-Rank Adaptation(QLoRA)으로 미세조정한다~\cite{hui2024qwen2,dettmers2023qlora}. adapter는 rank 16, scaling 32, dropout 0.05이며 attention과 feed-forward projection을 대상으로 한다. 정본 학습은 1 epoch, 학습률 \(2\times10^{-4}\), seed 2027--2029를 쓴다. cross-entropy 손실은 assistant target 토큰에서만 계산한다. 역할 중립 prompt는 문제 설명, 제한, 허용된 제출들, 실행/편집 요약, 완전한 해답 요청을 담는다. 규칙 이름도 선호하는 패치 크기도 적지 않으므로, 특화는 명시적 지시가 아니라 데이터에서 나와야 한다.
% The goal of Train is to learn each relation independently while keeping model and optimization comparable. The implementation fine-tunes Qwen2.5-Coder-7B-Instruct with 4-bit Quantized Low-Rank Adaptation (QLoRA)~\cite{hui2024qwen2,dettmers2023qlora}. Adapters have rank 16, scaling 32, and dropout 0.05, targeting attention and feed-forward projections. Canonical training uses one epoch, learning rate \(2\times10^{-4}\), and seeds 2027--2029. Assistant target tokens supply cross-entropy loss. The role-neutral prompt contains the statement, limits, permitted submissions, execution/edit summaries, and a request for a complete solution. It names neither the rule nor a preferred patch size, so specialization must come from the data rather than explicit instructions.

target은 오프라인에서 이용 가능한 미래 제출이며, 추론 입력은 관측된 상태만 담는다. current-only 통제는 위치를 재설정하고 더 앞선 항목을 제거해, 위치 라벨을 통한 길이 누출을 막는다. Answer 학습은 이미 단일 source이므로 추론 시 history를 주면 분포 변화가 생긴다. 반면 history 제거 재학습 통제는 target을 고정하고 더 앞선 제출의 직렬화만 바꾼다. source를 맞춘 target 학습은 현재 입력과 개수를 고정한다. 이 설계들은 서로 다른 질문에 답하므로, history에 관한 하나의 주장으로 합치지 않는다.
% Targets are future submissions available offline; inference inputs contain only observed states. Current-only controls reset positions and remove earlier entries, preventing length leakage through position labels. Answer training is already single-source, so supplying history at inference creates a distribution change. The history-removal retraining control instead holds targets fixed and changes earlier-submission serialization. Source-matched target training holds current input and count fixed. These designs answer different questions and are not pooled into one claim about history.

paired-target 통제는 문제, 사용자, 제출 식별자, 정확히 같은 버기 프로그램으로 레코드를 내부 결합하고, Answer target과 Progress target이 서로 다른 source만 남긴다. 조건마다 학습 7,389개와 validation 931개 예제가 동일한 current-only 입력을 쓴다. 별도의 peer 통제는 같은 문제, 같은 split의 다른 사용자를 요구하며 target의 실행 증거가 정확히 같아야 한다. 같은 사용자의 target을 \(y_u\), 그 동료 교체본을 \(y_v\)라 하면, semantic-token diff 거리 \(d\)에 대해 불일치 \(\delta=|d(c,y_v)-d(c,y_u)|\)가 \(\delta\le2\) 또는 \(\delta/\max(1,d(c,y_u))\le0.1\)을 만족해야 한다. 증거가 희소한 집단을 먼저 방문하며, 동점일 때는 거리 불일치, 재사용, 식별자 순으로 우선하고 donor 재사용은 3회로 제한한다. 이 그리디 규칙은 조건마다 학습 5,231개와 validation 306개 예제를 만든다. 결과가 같고 거리가 가깝다는 것이 구조나 스타일의 동일성을 뜻하지는 않으므로, 측정된 효과는 교체 규칙 전체에 속하며 provenance만 떼어낸 것이 아니다.
% The paired-target control inner-joins records by problem, user, submission identifier, and the exact buggy program, retaining sources with distinct Answer and Progress targets. Its 7,389 training and 931 validation examples per condition use identical current-only inputs. The separate peer control requires another user on the same problem and in the same split, with exactly equal target execution evidence. Writing \(y_u\) for the same-user target and \(y_v\) for its peer replacement, for semantic-token diff distance \(d\) the discrepancy \(\delta=|d(c,y_v)-d(c,y_u)|\) must satisfy \(\delta\le2\) or \(\delta/\max(1,d(c,y_u))\le0.1\). Scarce evidence groups are visited first; ties prioritize distance discrepancy, reuse, and identifier, with donor reuse capped at three. This greedy rule yields 5,231 training and 306 validation examples per condition. Equal outcomes and nearby distances do not equate structure or style, so its measured effect belongs to the entire replacement rule, not isolated provenance.

\subsection{Select}
Select의 목표는 최종 테스트 결과를 보지 않고 고른, 크기가 제한된 portfolio를 배포하는 것이다. validation 입력 \(U\)에 대해 \(R_v^B\)를 checkpoint \(v\)가 edit budget \(B\) 안에서 수리한 입력이라고 하자. 선택은 다음을 최대화한다:
% The goal of Select is to deploy a bounded portfolio chosen without final-test outcomes. For validation inputs \(U\), let \(R_v^B\) be inputs repaired by checkpoint \(v\) within edit budget \(B\). Selection maximizes:
\begin{equation}
 f_B(S)=\frac{1}{|U|}\left|\bigcup_{v\in S} R_v^B\right|,\qquad |S|=3.
\label{eq:portfolio}
\end{equation}
직관적으로 Equation~\eqref{eq:portfolio}는 낮은 학습 손실이나 모든 관계의 포함이 아니라 서로 보완되는 성공을 보상한다. validation은 적격한 461개 문제마다 해시로 고정한 trajectory 하나를 쓴다. mixed pool은 checkpoint 9개와 84개 조합을 갖고, 관계마다 하나씩 요구하면 대신 27개가 된다. 제한 없는 기본 mixed 선택은 Answer2027, Answer2028, Progress2027이다. 관계 제약을 둔 선택은 별개의 조건이다. Answer-9Choose3은 terminal checkpoint 9개와 동일한 84개 조합 탐색을 받는다. 동점은 기록된 pass-rate, improvement, 결정적 식별자 우선순위로 처리한다. budget 지정 선택은 \(B\in\{5,10,20,40,80,160\}\)에서 선언된 목적식을 반복하며, 테스트 결과를 보고 budget을 고르지 않는다.
% Intuitively, Equation~\eqref{eq:portfolio} rewards complementary successes, not low training loss or the presence of every relation. Validation uses one fixed-hash trajectory from each of 461 eligible problems. The mixed pool has nine checkpoints and 84 triples; requiring one checkpoint per relation instead permits 27. The primary unconstrained mixed choice is Answer2027, Answer2028, and Progress2027. The relation-constrained choice is a different condition. Answer-9Choose3 receives nine Answer checkpoints and the same 84-triple search. Ties use recorded pass-rate, improvement, and deterministic identifier priorities. Budget-indexed selection repeats the declared objective at \(B\in\{5,10,20,40,80,160\}\), without choosing a budget from test results.

선택된 checkpoint와 그 순서는 고정된다. 각각은 독립적인 후보를 최대 하나 내며, 처음 관측된 acceptance에서 생성을 멈춘다. 모든 테스트를 통과하는 것이 없으면 Figure~\ref{alg:generic}은 통과 비율을 먼저, 그다음 더 작은 거리를 우선한다. 바뀌지 않은 코드가 항상 가능하므로, 동일한 고정 실행 측정에서는 반환된 통과 비율이 낮아질 수 없고 유한한 edit budget을 넘을 수도 없다. 이는 테스트 단위 비회귀가 아니다: 비율이 같아도 서로 다른 테스트에서의 이득과 손실이 가려질 수 있다. 또한 새로운 실행, 보지 못한 테스트 묶음, 자원 변동성 하에서의 비회귀를 보장하지도 않는다. 개발 과정은 이런 더 강한 실패 양상을 명시적으로 측정한다.
% Selected checkpoints and order are frozen. Each emits at most one independent candidate, and the first observed acceptance stops generation. If none passes all tests, Figure~\ref{alg:generic} prioritizes pass fraction and then smaller distance. Because unchanged code is feasible, for the same fixed execution measurements the returned pass fraction cannot decrease, and a finite edit budget cannot be exceeded. This is not per-test non-regression: equal fractions can conceal gains and losses on different tests. It also does not guarantee non-regression under fresh execution, an unseen suite, or resource variability. Development explicitly measures these stronger failure modes.

후보가 고정되고 독립적이면, 순서는 호출 수와 패치의 정체를 바꾸지만 적격한 acceptance의 존재 여부는 바꾸지 않는다. 저장된 후보는 선택을 정확히 재생할 수 있게 하지만 생성 품질을 보장하지는 않는다. terminal 짝짓기는 trajectory 길이에 선형이며, \(n\)개 제출을 \(m\)개 테스트로 재실행하려면 \(O(nm)\)의 실행과 증거 저장이 필요하다. 84개 조합 탐색은 우리 pool 크기에서 한정된 것이며, 임의 크기 pool로 확장되는 최적화기가 아니다.
% For fixed independent candidates, order changes calls and patch identity but not the existence of an eligible acceptance. Stored candidates permit exact selection replay, not a guarantee of generation quality. Terminal pairing is linear in trajectory length; replaying \(n\) submissions on \(m\) tests requires \(O(nm)\) executions and evidence storage. The 84-triple search is bounded at our pool size, not a scalable optimizer for arbitrary pools.

Repair Rate(RR)는 반환된 프로그램이 모든 테스트를 통과한 적격 입력의 비율이다. Pass Rate(PR)는 통과 테스트 비율의 평균이고, Improvement Rate(IR)는 그 비율이 증가한 경우를 센다. AST 사이의 Tree Edit Distance(TED)는 현재 코드에서 반환 코드까지의 변경을 측정하며~\cite{zhang1989simple,pawlik2016tree}, 어느 한쪽이 파싱되지 않으면 정의되지 않는다. 정의되지 않는 경우는 제한 없는 RR에는 남지만 TED 요약에는 들어가지 않으며, 유한한 gate는 거리가 정의되지 않는 변경을 거부한다. 짝짓지 않은 TED는 성공하고 파싱 가능한 반환물의 평균이고, 짝지은 locality는 공동 성공만 쓴다. retention은 \texttt{SequenceMatcher}(autojunk 해제)가 일치시킨 토큰 또는 공백을 제거한 비어 있지 않은 줄을 source 개수로 나눈다. Python 토큰화는 레이아웃 토큰을 빼고 주석은 유지하며, Java는 단어와 구두점을 분리한다. retention 차이는 퍼센트포인트(pp)이며 토큰 수나 학습 측정치가 아니다.
% Repair Rate (RR) is the fraction of eligible inputs whose returned program passes every test. Pass Rate (PR) averages passed-test fractions; Improvement Rate (IR) records an increased fraction. Tree Edit Distance (TED) between ASTs measures current-to-returned change~\cite{zhang1989simple,pawlik2016tree} and is undefined when either program does not parse. Undefined cases remain in unrestricted RR but not TED summaries; finite gates reject undefined-distance changes. Unpaired TED averages successful, parseable returns; paired locality uses joint successes. Retention divides tokens or nonempty stripped lines matched by \texttt{SequenceMatcher} (autojunk disabled) by the source count. Python tokenization omits layout tokens but keeps comments; Java separates words and punctuation. Retention differences are percentage points (pp), not token counts or learning measures.

따로 언급하지 않으면 대괄호는 복원추출한 10,000회 problem-cluster 재표집에서 얻은 95\% percentile bootstrap 구간이며, 표집된 각 cluster에서 짝지은 입력을 모두 보존한다~\cite{efron1979bootstrap}. Java는 학생과 exercise를 따로 재표집한다. instance 가중 추정치는 합산 차이를 표집 입력 수로 나누고, equal-problem 추정치는 문제별 평균을 평균한다. 정확 양측 McNemar 검정은 입력 짝의 독립성을 가정하므로 cluster를 고려한 구간을 대체하지 않고 보조할 뿐이다~\cite{mcnemar1947note}. Holm 보정은 history 제거 재학습 4개 검정(Strict/Progress $\times$ Seen/Unseen)에 적용되며 모든 탐색적 대비에 적용되는 것이 아니다~\cite{holm1979simple}. 개별 비율의 Wilson 구간은 따로 보고한다~\cite{wilson1927probable}. 프로토콜은 통제가 언제 고정되었는지 밝히지만, 확장된 연구가 외부에 사전등록된 것은 아니다. 적응적으로 들여다본 개발은 탐색적으로 남는다. 공백에 민감한 보정과 원래 집계는 따로 보존한다.
% Unless stated otherwise, brackets give 95\% percentile bootstrap intervals from 10,000 problem-cluster resamples with replacement, preserving all paired inputs in each sampled cluster~\cite{efron1979bootstrap}. Java separately resamples students and exercises. Instance-weighted estimates divide pooled differences by sampled inputs; equal-problem estimates average problem means. Exact two-sided McNemar tests assume independent input pairs and are supplementary to cluster-aware intervals, not substitutes for them~\cite{mcnemar1947note}. Holm adjustment covers the four history-removal retraining tests (Strict/Progress $\times$ Seen/Unseen), not every exploratory contrast~\cite{holm1979simple}; individual-rate Wilson intervals are reported separately~\cite{wilson1927probable}. Protocols identify when controls were frozen, but the extended study was not externally preregistered. Adaptively inspected development remains exploratory. We retain whitespace-sensitive corrections and original counts separately.

The paired population is restricted to sources with distinct targets, however, and does not estimate an effect for all CodeNet submissions. Moreover, a Progress target can itself be accepted. The intervention is the retained-evidence target rule, not a clean contrast between exclusively incorrect and exclusively correct targets. A returned program can move a submission forward without finishing it. Under the matched inputs the Progress rule repairs 34.0\% of Seen inputs and improves 43.4\%, so a further 9.4 points receive a program that advances without passing, against 53.2\% and 65.0\% for the Answer rule. The same two gaps are 6.4 and 7.6 points on Unseen, and 9.4 against 2.2 on Java, where Answer targets already repair 85.6\% outright. Part of the coverage the Progress rule gives up therefore returns as partial progress, counted by test execution and not by comprehension.

Progress의 locality 이점은 공동 성공에서 드러난다. 공동 수리된 Seen 299개와 Unseen 154개 중 278개와 134개가 두 방법 모두에서 source에서 수리까지의 TED가 정의된다. Answer에서 Progress를 뺀 평균 TED는 10.08 [7.53, 12.99]와 6.83 [4.58, 9.39]이다. token retention은 5.6 [4.29, 6.94]와 6.5 [4.26, 8.95] 포인트, line retention은 8.9 [6.64, 11.16]와 10.4 [6.95, 14.25] 포인트 개선된다. TED가 정의되지 않는 21개와 20개는 RR에 남아 있으며 수리 불가로 선언되지 않는다. 이 측정치들은 성공한 출력이 source를 더 많이 보존한다는 점을 일관되게 기술하지만, 이해가 더 쉬움을 입증하거나 특정 학생에게 어느 방법이 가장 도움이 될지 설명하지는 않는다.

\noindent\textbf{Peer targets.} 결과와 거리를 맞춘 별도의 교체는 RR을 Seen에서 50.4\%에서 54.7\%로, Unseen에서 78.4\%에서 84.4\%로 올린다. 같은 사용자에서 동료를 뺀 구간은 [-7.71, -0.84]와 [-11.79, -0.41]이고, 정확 McNemar \(p=0.005\)와 \(p=0.032\)이다. 매칭은 정본 Progress 학습 레코드 21,416개 중 5,231개(24.4\%)와 validation 2,685개 중 306개(11.4\%)를 덮는다. 이 결과는 이 caliper, donor 상한, source 모집단, 교체 규칙에 관한 것이다. 결과가 같고 edit distance가 가깝더라도 target의 구조, 스타일, 길이는 다를 수 있으므로 이 대비가 사용자 정체성을 분리하지는 않는다. 여기서는 맞춘 동료 target이 coverage를 개선하며, 이 통제 하에서 자기 자신의 trajectory가 유일하게 필요한 것은 아니다.
% \noindent\textbf{Peer targets.} The separate outcome- and distance-matched replacement raises RR from 50.4\% to 54.7\% on Seen and from 78.4\% to 84.4\% on Unseen. Matches cover 5,231/21,416 canonical Progress training records (24.4\%) and 306/2,685 validation records (11.4\%). % \noindent\textbf{Operational locality.} A declared structural budget gives patch size an explicit engineering meaning: the deployment admits only changes within it. Per-budget Seen rates are 16.9/22.5/4.8\% at TED 5, 28.5/32.4/8.0 at 10, 40.3/44.0/13.9 at 20, 51.4/50.9/30.4 at 40, 61.0/56.0/50.8 at 80, and 66.8/57.9/67.6 at 160 for current-only Answer-3Seed/Mixed/LSGen, each over 997 inputs. \noindent\textbf{Answer to RQ2.} target 구성은 맞춘 입력 하에서 coverage와 locality를 서로 반대 방향으로 바꾸며, student-held-out Java에서도 같은 방향이고, 두 효과 모두 exercise나 학생에 걸쳐 균일하지 않다. 맞춘 동료 target이 coverage를 개선하므로 이 효과는 개인에게 고유한 supervision이 아니며, 교육적 이득은 측정되지 않은 채로 남는다.
% \noindent\textbf{Answer to RQ2.} Target construction changes coverage and locality in opposite directions under matched inputs, with the same direction on student-held-out Java, and neither effect is uniform across exercises or students. Matched peer targets improve coverage, so the effect is not uniquely personal supervision; pedagogical benefit remains unmeasured.

\subsection{RQ3: Component Efficacy}
\noindent\textbf{Fixed candidate breadth.} 성공 지시자 \(a_{ij}\)를 갖는 저장된 draw 세 개에 대해, 입력 \(i\)에서 균일하게 고른 단일 draw의 기대 성공은 \(\frac{1}{3}\sum_j a_{ij}\)이고, 세 draw의 합집합은 \(\max_j a_{ij}=1\)일 때 성공한다. 두 값의 짝지은 차이는 동일한 후보 집합 안에서 추가 기회만을 분리한다. greedy decoding을 단일 stochastic draw로 바꾸면 7.6 포인트 [-9.81, -5.41]를 잃지만, 동일한 고정 draw 세 개를 실행으로 선택하면 Seen에서 15.1 포인트 [13.48, 16.76]를 얻는다. 이는 저장된 실행에 대한 기술적 분해이며, 미래의 draw 세 번이 성공을 보장하거나 오류가 독립이라는 주장이 아니다. 이 결과는 portfolio를 adapter 하나와만 비교하면 그 특화된 학습 신호의 증거가 과장되는 이유를 직접 보여 준다.
% \noindent\textbf{Fixed candidate breadth.} For three stored draws with success indicators \(a_{ij}\), the expected uniformly selected one-draw success for input \(i\) is \(\frac{1}{3}\sum_j a_{ij}\), whereas the three-draw union succeeds when \(\max_j a_{ij}=1\). Their paired difference isolates additional opportunities within the identical candidate set. Replacing greedy decoding by one stochastic draw costs 7.6 points [-9.81, -5.41], whereas execution-selecting three of those identical fixed draws contributes 15.1 points [13.48, 16.76] on Seen. This is a descriptive decomposition of stored executions, not a claim that three future draws have guaranteed success or independent errors. It directly demonstrates why comparing a portfolio only with one adapter overstates evidence for its specialized training signal.

temperature sweep은 대표 수치에 유리한 조건만 고르지 않고 선언된 모든 조건을 보존한다. \(T=1.0\)까지 단일 draw 비율은 Seen에서 41.1--43.1\% 범위에 머물고, 세 draw 합집합은 60.0/75.2\%에 이르며, \(T=1.5\)에서 decoder는 15.8/35.2\%로 붕괴한다. \(T=0.8\)에서의 별도 20-draw 스트림은 Seen 74.8\%와 Unseen 84.0\%에 도달하며 early stopping 하에서 평균 7.44회와 5.08회를 호출한다. 이 더 높은 비율들은 다른 생성 예산을 쓰므로 3회 호출 기본 결과를 대체하지 않는다. 미세조정도 중요하다: 맞춘 base model의 세 draw 합집합은 30.4/65.6\%에 그쳐, 적응이 Seen에서 27.2 포인트 [22.99, 31.41], Unseen에서 6.4 포인트 [1.19, 11.34]를 더한다. 따라서 폭만으로 base model 대비 개선 전체가 설명되지는 않는다.
% The temperature sweep retains all declared conditions instead of selecting the best one for the headline. Through \(T=1.0\) the one-draw rate stays within 41.1--43.1\% on Seen, the three-draw union reaches 60.0/75.2\%, and at \(T=1.5\) the decoder collapses to 15.8/35.2\%. A separate 20-draw stream at \(T=0.8\) reaches 74.8\% Seen and 84.0\% Unseen, using on average 7.44 and 5.08 calls under early stopping. Those higher rates spend a different generation budget and do not replace the three-call primary results. Fine-tuning also matters: the matched base-model three-draw union reaches only 30.4/65.6\%, so adaptation adds 27.2 points [22.99, 31.41] on Seen and 6.4 points [1.19, 11.34] on Unseen. Breadth alone therefore does not explain all improvement over the base model.

temperature를 맞춘 조건에서, 한 checkpoint의 draw 세 개를 서로 다른 checkpoint 세 개의 draw 하나씩으로 바꾸면 RR이 Seen에서 -0.1 포인트 [-2.00, 1.80], Unseen에서 2.4 포인트 [-0.41, 5.31] 변한다. 이 구간들은 checkpoint 다양성의 일관된 이점을 확립하지 않는다. 동등성을 보이는 것도 아니다: 불확실성은 실용적으로 의미 있는 이득과 손해를 여전히 허용한다. 결정적 다중 seed 이득이 이 결과와 공존할 수 있는데, 한 checkpoint에서 표집하는 것만으로도 이미 다양성이 공급되기 때문이다.
% At matched temperature, replacing three draws of one checkpoint by one draw from each of three checkpoints changes RR by -0.1 points [-2.00, 1.80] on Seen and 2.4 points [-0.41, 5.31] on Unseen. These intervals do not establish a consistent advantage from checkpoint diversity. They also do not show equivalence: the uncertainty still admits benefits and harms of practical interest. A deterministic multi-seed gain can coexist with this result because sampling from one checkpoint already supplies diversity.

한 추론 스택에서의 current-only factorial이 이 설명을 검정한다. greedy checkpoint 세 개는 하나보다 9.8 [7.85, 11.92]와 10.8 [7.23, 14.64] 포인트를 얻지만, stochastic decoder를 맞추면 서로 다른 checkpoint는 2.1 포인트 [0.00, 4.16]와 1.2 포인트 [-2.93, 5.93]만 더한다. equal-problem Seen 구간은 0을 포함하므로, 반올림된 instance 가중 하한이 견고한 checkpoint 이점을 확립하지는 않는다. 그 스택에서의 절대 Seen/Unseen 비율은 greedy checkpoint 하나 53.1/67.2\%, greedy checkpoint 세 개 62.9/78.0\%, 같은 checkpoint의 stochastic 3개 조합 66.8/79.6\%, 서로 다른 checkpoint의 3개 조합 68.9/80.8\%이며, 과거 스택의 72.0/81.2\%와 대비된다. backend 민감도가 실질적이므로, 배포 권고는 평가된 스택으로 한정되며 backend와 무관한 우월성으로 주장하지 않는다.
% A current-only factorial on one inference stack tests this explanation. Three greedy checkpoints gain 9.8 [7.85, 11.92] and 10.8 [7.23, 14.64] points over one, but under the matched stochastic decoder distinct checkpoints add only 2.1 points [0.00, 4.16] and 1.2 points [-2.93, 5.93]. The equal-problem Seen interval includes zero, so the rounded instance-weighted lower bound does not establish a robust checkpoint benefit. Absolute Seen/Unseen rates on that stack are 53.1/67.2\% for one greedy checkpoint, 62.9/78.0\% for three greedy checkpoints, 66.8/79.6\% for a same-checkpoint stochastic triple, and 68.9/80.8\% for a distinct-checkpoint triple, against 72.0/81.2\% on the historical one. Backend sensitivity is material, and the deployment recommendation is restricted to the evaluated stack rather than asserted as backend-independent superiority.

\noindent\textbf{Serialized history.} 고정된 3개 조합에서 더 앞선 제출들을 제거하면 두 pool 모두 수리가 늘어난다. 그 이득은 Mixed와 Answer에 대해 Seen 8.8/11.1 포인트, Unseen 7.6/6.0 포인트이며 모든 구간이 0을 제외한다. target은 같게 두고 그 맥락만 없앤 재학습은 Holm 보정 후 유의한 차이를 내지 않으며 보정된 최소 \(p\)는 0.313이므로, 직렬화된 이력은 측정된 이점의 일부가 아니고 배포 구성은 current-only prompt를 쓴다.
% \noindent\textbf{Serialized history.} Removing earlier submissions from the frozen triples raises repair for both pools. The gains are 8.8/11.1 Seen points and 7.6/6.0 Unseen points for Mixed/Answer, with all intervals excluding zero. Matched retraining without that context shows no significant difference after Holm correction, with smallest adjusted \(p=0.313\), so serialized history is not part of the measured advantage and the deployed configuration uses current-only prompts.

선택 공간 통제도 이질적 target의 일반적 이점을 확립하지 못한다. Answer-9Choose3은 Mixed와 동일한 9개 checkpoint pool 크기와 84개 부분집합 기회를 받는다. 기본 5-fold cross-fitted mixed에서 terminal을 뺀 대비는 +2.2 포인트 [-0.19, 4.63]이고, cross-fitting을 하지 않은 추정치는 +1.7 [-0.79, 4.29]이다. 이 추정치들은 양수지만 불확실하다. 고정된 3개 조합의 여섯 순서를 정확히 재생하는 것은 독립 후보 controller를 확인하는 것이며 학습된 다양성의 가치를 확인하는 것이 아니다.
% Selection-space controls also fail to establish a general heterogeneous-target benefit. Answer-9Choose3 receives the same nine-checkpoint pool size and 84-subset opportunity as Mixed. The primary five-fold cross-fitted mixed-minus-Answer contrast is +2.2 points [-0.19, 4.63], compared with the non-cross-fitted +1.7 [-0.79, 4.29]. These estimates are positive but uncertain. Exact replay of the six orders of a fixed triple checks the independent-candidate controller, not the value of learned diversity.

\noindent\textbf{Answer to RQ3.} 후보 폭과 적응은 각각 측정 가능한 이득을 기여한다. stochastic decoder를 맞추고 나면 서로 다른 checkpoint는 일관된 이점을 더하지 않으며, 직렬화된 history가 필요한 입력이라는 근거도 없다. target 이질성은 동일하게 탐색된 terminal pool에 대해 작고 불확실한 제한 없는 대비를 보인다.
% \noindent\textbf{Answer to RQ3.} Candidate breadth and adaptation each contribute measured gains. Distinct checkpoints add no consistent advantage once the stochastic decoder is matched, and serialized history is not supported as a necessary input. Target heterogeneity has a small, uncertain unrestricted contrast against the equally searched Answer pool.

\subsection{RQ4: Generality}
\label{sec:generality}
\noindent\textbf{Problems and execution suites.} Unseen 안에서 Mixed는 Zero-shot을 12.8 포인트 [6.83, 18.75] 앞서며, 배타적 성공은 45개 대 13개, 정확 McNemar \(p=3.01\times10^{-5}\)이다. 공동 수리 142개 중 122개가 두 방법 모두에서 TED가 정의되며, 그 122개에서 TED를 6.41 [3.43, 9.89] 줄인다. Unseen의 절대 RR이 Seen보다 높은 것은 더 강한 일반화의 증거가 아니다: 두 분할은 trajectory 가용성과 문제 구성이 다르다. Unseen 54개 문제 전부를 수리 전 난이도 공변량 여섯 개로 서로 다른 Seen 문제에 매칭하면 원래 격차가 -4.6 equal-problem 포인트 [-14.18, 5.30]로 바뀐다. 그래서 우리는 분할 간 원시 차이의 방향이 아니라 분할 내 짝지은 대비에 의존한다. 매칭은 측정된 불균형을 줄이지만 관측되지 않은 난이도까지 맞출 수는 없다.
% \noindent\textbf{Problems and execution suites.} Within Unseen, Mixed exceeds Zero-shot by 12.8 points [6.83, 18.75], with 45 versus 13 exclusive successes and exact McNemar \(p=3.01\times10^{-5}\). Among 142 joint repairs, 122 have defined TED for both methods; on those 122 it reduces TED by 6.41 [3.43, 9.89]. The higher absolute Unseen than Seen RR is not evidence of stronger generalization: the partitions differ in trajectory availability and problem composition. Matching all 54 Unseen problems to distinct Seen problems on six pre-repair difficulty covariates changes the raw gap into -4.6 equal-problem points [-14.18, 5.30]. We therefore rely on within-split paired contrasts, not the direction of the raw cross-split difference. Matching reduces measured imbalance but cannot balance unobserved difficulty.

보완적인 observed/hidden slice 검사는 기존의 작성된 테스트 묶음을 분할한다. Unseen에서 Mixed와 Answer-9Choose3은 observed slice와 보류 slice를 각각 250개 중 189개와 184개 입력에서 함께 통과한다. observed 묶음 성공 중 조건부 확인율은 192개 중 189개(98.4\%)와 186개 중 184개(98.9\%)이며, 배타적 공동 성공 13개 대 8개로 \(p=0.383\)이다. 다른 seed로 Seen 328개 문제 전체에 같은 절차를 반복하면 확인율은 97.8\%와 97.9\%이지만 공동 성공은 997개 중 452개 대 469개다. 따라서 높은 확인율이 Mixed가 이긴다는 것을 보여 주지는 않는다. 이들은 같은 작성 테스트의 보류 slice이며 독립적으로 작성된 명세가 아니므로, 큰 조건부 백분율이 전체 분모 기준 수리율을 대체해서는 안 된다.
% A complementary observed/hidden-slice check partitions the existing authored suite. On Unseen, Mixed and Answer-9Choose3 jointly pass observed and held-back slices on 189/250 and 184/250 inputs, respectively. Conditional confirmation among observed-suite successes is 189/192 (98.4\%) and 184/186 (98.9\%); 13 versus 8 exclusive joint successes yield \(p=0.383\). Repeating the procedure on all 328 Seen problems with a distinct seed yields 97.8\% and 97.9\% confirmation, but joint success is 452/997 versus 469/997. High confirmation thus does not demonstrate that Mixed wins. These are held-back slices of the same authored tests, not independently authored specifications, and the large conditional percentage must not replace the full-denominator repair rate.

\noindent\textbf{Earlier prefixes.} 결국 성공한 trajectory의 실행 가능한 prefix 가운데 Seen 2,770개와 Unseen 674개에서 current-only Answer-3Seed는 RR 69.6\%와 80.1\%에 이른다. 앞·중간·마지막 3분의 1은 Seen에서 70.0\%, 67.6\%, 71.4\%, Unseen에서 82.9\%, 77.3\%, 81.8\%다. 이는 평가를 마지막 실패 제출 너머로 확장하며 단순한 단조 위치 효과를 찾지 못한다. 끝내 acceptance에 이르지 못한 trajectory는 포함하지 않고, 한 trajectory에서 나온 여러 prefix는 서로 종속적이다. 2,770개 prefix 비율은 997개 입력 결과에 더해지지도, 새 사용자에 대한 독립적 재현으로 보고되지도 않는다.
% \noindent\textbf{Earlier prefixes.} Across 2,770 Seen and 674 Unseen executable prefixes of eventually successful trajectories, current-only Answer-3Seed reaches 69.6\% and 80.1\% RR. The early, middle, and last thirds reach 70.0\%, 67.6\%, and 71.4\% on Seen and 82.9\%, 77.3\%, and 81.8\% on Unseen. This extends evaluation beyond the last failed submission and finds no simple monotonic position effect. It does not cover trajectories that never reach acceptance, and multiple prefixes from one trajectory are dependent. The 2,770-prefix rate is neither added to the 997-input result nor reported as an independent replication on new users.

\noindent\textbf{Model scale and classroom data.} 1.5B 파라미터에서도 checkpoint 세 개는 하나보다 13.4 포인트 [11.16, 15.92]를 얻지만, mixed에서 terminal을 뺀 값은 -0.8 [-2.62, 1.07]이다. Seen에서 Mixed는 50.25\%, 9개 checkpoint terminal 통제는 51.05\%에 이른다. 이 더 작은 모델은 복수 기회의 유용성을 재현하지만 제한 없는 mixed-target 이점을 재현하지는 않는다. 이는 한 모델 계열 안의 한 번의 규모 변화이며 모델 계열 전반의 포괄이 아니다. 독점 frontier 모델과의 비교는 완료되지 않았다.
% \noindent\textbf{Model scale and classroom data.} At 1.5B parameters three checkpoints still gain 13.4 points over one [11.16, 15.92], but mixed-minus-Answer is -0.8 [-2.62, 1.07]. Mixed reaches 50.25\% and the nine-checkpoint Answer control 51.05\% on Seen. This smaller model reproduces the utility of multiple opportunities, not an unrestricted mixed-target advantage. It is one scale change within a model family, not broad model-family coverage. No proprietary frontier model comparison was completed.

Java portfolio 결과는 RQ2의 직접적인 맞춘 target 재학습과 다르다. Mixed에서 Answer-9Choose3을 뺀 값은 보류된 exercise 네 개에서 양수(3.9 포인트 [2.99, 5.11])이고 보류된 학생에서는 결론을 내릴 수 없다(0.6 [-1.20, 2.59]). 절대 RR은 exercise-held-out trajectory 304개에서 56.25\% 대 52.30\%, student-held-out trajectory 181개에서 83.98\% 대 83.43\%다. exercise 추정치는 cluster 네 개에만 기대고 있다: exercise 하나를 빼고 다시 적합시키면 대비가 3.6과 4.4 포인트 사이에 머물고, 개별 exercise는 2.5에서 5.5 포인트 범위다. 이 민감도 검사는 그 exercise들에서 부호를 보존하지만, cluster 네 개로는 폭넓은 교실 모집단 주장을 뒷받침할 수 없다. 맞춘 target 트레이드오프는 보편적 portfolio 이점보다 모집단 간 뒷받침이 더 분명하다.
% The Java portfolio results differ from RQ2's direct matched-target retraining. Mixed-minus-Answer-9Choose3 is positive on four held-out exercises (3.9 points [2.99, 5.11]) and inconclusive on held-out students (0.6 [-1.20, 2.59]). Absolute RR is 56.25\% versus 52.30\% over 304 exercise-held-out trajectories and 83.98\% versus 83.43\% over 181 student-held-out trajectories. The exercise estimate rests on four clusters only: refitting with one exercise left out keeps the contrast between 3.6 and 4.4 points, and single exercises range from 2.5 to 5.5 points. This sensitivity check preserves the sign on those exercises, but four clusters cannot support a broad classroom-population claim. The matched-target tradeoff has clearer cross-population support than a universal portfolio benefit.

\noindent\textbf{Representation and overlap.} accepted/non-accepted 이진 mining은 세밀한 severity 순서를 없애지만 target 집합도 함께 바꾼다. 재학습은 정본에서 대안을 뺀 방향으로 Progress RR을 Seen에서 +2.3, Unseen에서 -2.8 포인트 변화시킨다. 변화가 균일하지 않다는 점은 이 순서가 무해한 구현 세부가 아님을 보여 준다. Mixed와 Answer-9Choose3에서 반환된 수리가 학습 시점의 accepted 프로그램과 정확히 일치하는 경우는 선택의 0.6\%와 1.3\%이고, 0.90 토큰 유사도 임계값을 넘는 근접 중복은 3.8\%와 5.3\%이며, 같은 문제의 학습 target에 대한 최대 유사도의 중위수는 66.7\%와 68.6\%다. 낮은 정확 복사율이 구조적 재사용, 사전학습 오염, 사용자 수준 중복을 배제하지는 않는다~\cite{allamanis2019adverse}.
% \noindent\textbf{Representation and overlap.} Binary accepted/non-accepted mining removes the fine severity ordering but also changes the target set. Retraining changes Progress RR by +2.3 Seen and -2.8 Unseen points in the canonical-minus-alternative direction. The nonuniform changes show that the ordering is not an innocuous implementation detail. For Mixed and Answer-9Choose3, exact matches between a returned repair and a training-time accepted program occur in 0.6\% and 1.3\% of selections, near-duplicates above a 0.90 token-similarity threshold in 3.8\% and 5.3\%, and median maximum similarity to a same-problem training target is 66.7\% and 68.6\%. Low exact-copy rates do not exclude structural reuse, pretraining contamination, or user-level overlap~\cite{allamanis2019adverse}.

\noindent\textbf{Answer to RQ4.} 맞춘 target 트레이드오프는 실제 student-held-out Java에서 재현되고, 후보 폭은 더 작은 모델 규모에서도 유용하다. mixed-target의 제한 없는 우월성은 일관되게 재현되지 않는다. prefix, 난이도, 중복, 판정 순서, hidden slice 검사는 특정 위협을 좁히지만, CodeNet을 교실 연구로 만들거나 acceptance를 정확성의 증명으로 만들지는 않는다.
% \noindent\textbf{Answer to RQ4.} The matched-target tradeoff replicates on authentic student-held-out Java, and candidate breadth remains useful at smaller model scale. Mixed-target unrestricted superiority does not replicate consistently. Prefix, difficulty, overlap, verdict-order, and hidden-slice checks narrow specific threats, but they do not make CodeNet a classroom study or acceptance a proof of correctness.

\subsection{Threats to Validity}
\noindent\textbf{Internal validity.} 런타임 변동성, 정의되지 않는 source AST, Python 공백이 라벨과 거리에 영향을 준다. 우리는 unknown, 분모, 공백에 민감한 보정을 보존하며, 해시는 provenance를 확립하지만 정확성을 확립하지는 않는다. source와 동료 매칭이 모든 target의 의미나 스타일을 같게 만들지는 않는다.
% \noindent\textbf{Internal validity.} Runtime variability, undefined source ASTs, and Python whitespace affect labels and distances. We retain unknowns, denominators, and whitespace-sensitive corrections; hashes establish provenance, not correctness. Source and peer matching do not equate all target semantics or styles.

\noindent\textbf{Construct validity.} acceptance는 의미적 정확성의 증명이 아니며~\cite{smith2015cure}, 같은 묶음에서 떼어낸 slice는 독립적인 명세가 아니다. TED와 retention은 인지 부하나 이후 학습을 측정하지 않는다. CodeNet은 초보자를 식별하거나 숙달을 측정하지 않는다. Java는 교실 제출물을 제공하지만 피드백 사용을 관찰하는 개입은 아니다. exercise별·학생별 분해는 어떤 학생이 다른 수리를 받게 되는지를 기술하며 어떤 학생이 이득을 얻는지를 기술하지 않고, Figure~\ref{fig:case}는 추정치를 담지 않는 사후 사례 하나다. 과목 데이터 사용 조건이 학생 제출물의 재배포를 허용하지 않으므로 우리는 CodeNet 프로그램을 보여 준다. 이런 구별들이 교육적 해석과 target 품질 해석을 제한한다.
% \noindent\textbf{Construct validity.} Acceptance is not proof of semantic correctness~\cite{smith2015cure}; same-suite slices are not independent specifications. TED and retention do not measure cognitive load or subsequent learning. CodeNet does not identify novices or measure mastery. Java supplies classroom submissions, not an intervention observing feedback use. The per-exercise and per-student resolution describes which students would receive a different repair, not which students benefit, and Figure~\ref{fig:case} is one post-hoc case that carries no estimate. We display a CodeNet program because the course data terms do not permit redistributing student submissions. These distinctions limit educational and target-quality interpretations.

\noindent\textbf{External and conclusion validity.} 필터링은 짧고 결국 성공하는 Python trajectory를 선호하며 Seen 내 사용자 중복을 허용한다. Java는 과목 맥락 하나와 보류된 exercise 네 개만 더한다. cluster bootstrap과 equal-problem 추정치는 작은 cluster의 불확실성, 다중성, 앞선 결과를 본 뒤 고른 분석의 편향을 없애지 못한다.
% \noindent\textbf{External and conclusion validity.} Filtering favors short, eventually successful Python trajectories and permits Seen user overlap. Java adds one course context and only four held-out exercises. Cluster bootstrap and equal-problem estimates do not eliminate small-cluster uncertainty, multiplicity, or the bias of analyses chosen after earlier results.

\section{Related Work}
\label{sec:related}
\noindent\textbf{Repair and generation budgets.} generate-and-validate 수리는 탐색, 학습된 변환, 언어 모델에 걸쳐 있다~\cite{gazzola2019automatic,monperrus2018automatic,weimer2009automatically,legoues2012genprog}. 탐색 분석~\cite{qi2014strength}과 실행 기반 평가~\cite{haque2023fixeval,chen2021evaluating}는 후보 품질과 노출을 분리한다. 신경망 패치, ensemble, 합성 손상, 실행 정보를 쓰는 자기지도는 서로 다른 학습 신호를 제공하며~\cite{tufano2019empirical,lutellier2020coconut,yasunaga2021break,ye2022selfapr}, zero-shot 연구는 과제 적응 없는 수리를 검토한다~\cite{xia2022less,jiang2023impact}. 독립 ensemble과 가중치 평균은 다양성의 또 다른 개념을 제공한다~\cite{lakshminarayanan2017simple,wortsman2022model}. 우리는 portfolio 수리를 새로 제안하지 않는다. 동일 target seed, 동일한 탐색 공간, 고정된 draw, current-only 통제로 trajectory target만 분리한다.
% \noindent\textbf{Repair and generation budgets.} Generate-and-validate repair spans search, learned transformations, and language models~\cite{gazzola2019automatic,monperrus2018automatic,weimer2009automatically,legoues2012genprog}. Search analyses~\cite{qi2014strength} and execution-based evaluation~\cite{haque2023fixeval,chen2021evaluating} separate candidate quality from exposure. Neural patches, ensembles, synthetic corruption, and execution-informed self-supervision provide different training signals~\cite{tufano2019empirical,lutellier2020coconut,yasunaga2021break,ye2022selfapr}; zero-shot studies examine repair without task adaptation~\cite{xia2022less,jiang2023impact}. Independent ensembles and weight averaging supply other notions of diversity~\cite{lakshminarayanan2017simple,wortsman2022model}. We do not introduce portfolio repair; we isolate trajectory targets with same-target seeds, equal search spaces, fixed draws, and current-only controls.

\noindent\textbf{Programming-exercise feedback.} 교육용 수리는 군집화, 정렬, 리팩터링으로 올바른 프로그램을 활용하고~\cite{gulwani2018automated,wang2018search,hu2020re}, 관련 표현과 튜터링 시스템은 피드백을 전파하고 힌트를 생성한다~\cite{piech2015embeddings,glassman2015overcode,rivers2017datadriven,price2017isnap}. 언어 모델은 수리, 구문 피드백, 대화, 동료, 반례를 뒷받침한다~\cite{joshi2023repair,zhang2024pydex,phung2023generating,liu2024fastfixer,yang2024cref,zhao2024peer,orvalho2025counterexample}. 과제를 고려한 피드백과 다양화된 피드백은 또 다른 참조 전략을 쓴다~\cite{heo2023referent,choi2021automated,choi2025automated}. LSGen도 시간순으로 틀린 제출과 이후 올바른 제출의 짝을 retrieval용으로 mine하므로~\cite{dai2026learner} trajectory 자체가 우리의 새로움은 아니며, 여기서도 LSGen은 강한 Seen 우위를 유지한다. 다만 LSGen은 이력의 기여를 추가 후보의 기여에서 분리하지 않으므로, 우리가 이력과 후보 예산을 함께 고정하는 이유가 남는다. next-step 힌트 생성기는 안내를 무엇에 맞추는가에서 이 연구와 갈린다. 데이터 기반 힌트는 해답 공간이나 과거 cohort의 경로를 읽고 제출물을 그 위에 투영하므로, 그 공간에서 같은 위치에 있는 두 학생은 각자의 코드가 지금 어떤 테스트를 통과하는지와 무관하게 같은 다음 단계를 받는다~\cite{rivers2017datadriven,price2017isnap,roest2024next}. 우리의 target 규칙은 대신 제출물 자신의 실행 증거를 읽고, 텍스트 힌트가 아니라 완성된 프로그램을 반환한다. 두 산출물은 서로 다른 척도에서 측정되며 서로를 대신하지 않는다. 벤치마킹과 설문 연구는 모집단과 프로토콜 차이를 강조한다~\cite{yi2017feasibility,koutcheme2024benchmarking,keuning2018systematic}. 이 방법들이 모두 terminal target으로 학습하는 것은 아니다: 우리의 더 좁은 개입은 맞춘 source에 대해 target을 교체하여 coverage--locality 트레이드오프를 드러내며, 피드백 전략 전반에 대한 우월성을 드러내는 것이 아니다.
% \noindent\textbf{Programming-exercise feedback.} Educational repair exploits correct programs through clustering, alignment, and refactoring~\cite{gulwani2018automated,wang2018search,hu2020re}; related representations and tutoring systems propagate feedback and generate hints~\cite{piech2015embeddings,glassman2015overcode,rivers2017datadriven,price2017isnap}. Language models support repair, syntax feedback, conversations, peers, and counterexamples~\cite{joshi2023repair,zhang2024pydex,phung2023generating,liu2024fastfixer,yang2024cref,zhao2024peer,orvalho2025counterexample}. Assignment-aware and diversified feedback use further reference strategies~\cite{heo2023referent,choi2021automated,choi2025automated}. LSGen also mines chronological wrong-to-later-correct submission pairs for retrieval~\cite{dai2026learner}, so trajectories are not our novelty, and it retains its strong Seen advantage here. It does not separate the history's contribution from that of extra candidates, however, which is why we hold the history and the candidate budget fixed together. Next-step hint generators differ from this work in what their guidance is fitted to. Data-driven hints read a solution space or a past cohort's paths and project the submission onto it, so two students at the same position in that space receive the same next step independently of which tests their own code currently passes~\cite{rivers2017datadriven,price2017isnap,roest2024next}. Our target rule reads the submission's own execution evidence instead, and returns a complete program rather than a textual hint. The two kinds of output are measured on different scales and do not substitute for each other. Benchmarking and surveys emphasize population and protocol differences~\cite{yi2017feasibility,koutcheme2024benchmarking,keuning2018systematic}. These methods do not uniformly train on Answer targets. Our narrower intervention replaces the target for matched sources and exposes a coverage--locality tradeoff, not dominance over feedback strategies.

\noindent\textbf{History and learner evidence.} ZPD와 scaffolding은 지원받는 수행에 관한 것이며 프로그램 edit distance에 관한 것이 아니다~\cite{cole1978mind,murray2002toward,chounta2017grey,schulze2024beyond}. knowledge tracing은 상호작용에서 숙련도를 모형화하고~\cite{corbett1994knowledge,piech2015deep,ghosh2020context}, TIKTOC은 testcase 증거를 포함한다~\cite{duan2024tiktoc}. next-step 힌트, 피드백 사다리, 초보자 반응 연구는 안내를 더 직접적으로 검토하며~\cite{roest2024next,heickal2024generating,xiao2024exploring}, 피드백 이론은 그 해석과 사용을 강조한다~\cite{narciss2008feedback,hattie2007power,shute2008focus,aleven2000limitations}. 이 논문은 학습자의 직렬화된 history를 조건으로 쓰면 생성된 수리가 개선된다고 주장하지 않는다. 배포 구성은 현재 제출물만으로 prompt를 구성하며, 그 선택의 근거가 된 맞춘 재학습과 prompt 통제는 부정적 결과를 포함해 보충자료에 보고한다. 교육적 주장에는 실행 가능한 출력만이 아니라 이해, 전이, 자력 수정에 대한 측정이 추가로 필요하다.
% \noindent\textbf{History and learner evidence.} ZPD and scaffolding concern supported performance, not program edit distance~\cite{cole1978mind,murray2002toward,chounta2017grey,schulze2024beyond}. Knowledge tracing models proficiency from interactions~\cite{corbett1994knowledge,piech2015deep,ghosh2020context}; TIKTOC incorporates testcase evidence~\cite{duan2024tiktoc}. Next-step hints, feedback ladders, and novice-response studies examine guidance more directly~\cite{roest2024next,heickal2024generating,xiao2024exploring}, while feedback theory emphasizes its interpretation and use~\cite{narciss2008feedback,hattie2007power,shute2008focus,aleven2000limitations}. This paper does not claim that conditioning on a learner's serialized history improves generated repairs. Our deployed configuration prompts with the current submission alone, and the supplement reports the matched retraining and prompt controls behind that choice, including their negative outcomes. Educational claims additionally require comprehension, transfer, and independent-correction measurements, not only executable outputs.

\section{Conclusion}
\label{sec:conclusion}
우리는 accepted solution 대신 제출물 자신의 실행 증거에서 수리 target을 구성하는 Mine--Train--Select 기법인 \textsc{ZPDPatch}를 제시했다. 맞춘 Python 실험과 student-held-out Java 실험은 같은 coverage--locality 트레이드오프를 보인다. Progress target은 공동 성공에서 학생의 source를 더 많이 보존하면서 더 적은 입력을 수리하고, 수리하지 못한 입력의 일부에는 그래도 전진한 프로그램을 돌려준다. 남은 개선에서 측정 가능한 부분은 후보 폭과 모델 적응이 설명하며, 맞춘 동료 target도 coverage를 올리므로 보존 증거 기반 target이 개인에게 고유한 supervision은 아니다. exercise별·학생별로 분해하면 그 트레이드오프는 균일하지 않다. coverage 비용은 특정 exercise에 집중되고, retention 이득은 어느 규칙에서든 수리를 받은 학생의 약 3분의 1에 도달하며, 바로 그 지점에서 과목이 선택을 해야 한다. 그래서 우리는 current-only Answer 3개 조합을 유지하고, Progress 규칙은 locality가 제약일 때의 선택지로 보고한다. 교육적 이득과 더 넓은 모델 계열에 대한 일반성은 측정되지 않은 채로 남는다.
% We presented \textsc{ZPDPatch}, a Mine--Train--Select technique that constructs repair targets from a submission's own execution evidence instead of from an accepted solution. Matched Python and student-held-out Java experiments show the same coverage--locality tradeoff. Progress targets preserve more of the student's source on joint successes while repairing fewer inputs, and on part of what they fail to repair they still return a program that has moved forward. Candidate breadth and model adaptation account for the measurable part of the remaining improvement, and matched peer targets also raise coverage, so the retained-evidence target is not uniquely personal supervision. Resolved per exercise and per student, that tradeoff is uneven. The coverage cost concentrates on particular exercises, and the retention gain reaches about a third of the students who receive a repair from either rule, which is where a course would have to choose. We therefore retain the current-only Answer triple and report the Progress rule as the option for when locality binds. Educational benefit and broader model-family generality remain unmeasured.
