\begin{abstract}
우리는 accepted solution이 아니라 실행 증거로 target을 구성해 수리 피드백을 학생 자신의 코드에 맞추는 trajectory-supervised 기법 \textsc{ZPDPatch}를 제시한다. 학생에게 돌아가는 수리는 그 자체가 피드백이므로, 테스트를 통과하는지와 함께 그 수리가 학생의 프로그램을 얼마나 대체하는지가 중요하다. 우리는 supervision이 그 이력에 의존하는 수리를 \emph{trajectory-conditioned}라 부르는데, 이력을 쓰는 시스템은 후보를 더 많이 생성하기만 해도 좋아지고 target 규칙을 바꾸면 학습 모집단도 함께 바뀌므로 어떤 단일 비교도 그 이득을 입증하지 못한다. 우리 목표는 target 규칙의 효과를 추가 후보와 직렬화된 이력의 효과에서 분리하는 것이다. \textsc{ZPDPatch}는 세 가지 실행 증거 관계를 mine하고, adapter를 독립적으로 학습하며, 회귀 대신 제출물을 그대로 반환하는 gate 뒤에서 validation으로 고정한 portfolio를 선택한다. 181개 student-held-out Introductory Programming (CS1) Java trajectory에서 source와 개수를 맞춘 학습 하에 terminal target은 155개를, progress target은 92개를 수리하며, 17개 exercise 중 15개에서 terminal이 앞선다. 두 규칙이 모두 수리한 90개 trajectory에서 progress 규칙의 retention 이득은 학생의 63.3\%에서 0이고 31.1\%에서 양, 5.6\%에서 음이다. 학습에서 본 문제의 997개 입력과 보류된 문제의 250개 입력으로 이루어진 online-judge 코퍼스도 같은 트레이드오프를 재현하며, coverage는 19.2와 11.2 퍼센트포인트 낮고 보존된 source token은 5.6과 6.5 포인트 많다. 고정된 후보 draw 세 번만으로 수리율이 15.1 포인트 더해지며, 이 수치들은 피드백을 기술하고 학습 효과를 말하지 않는다. 따라서 우리는 current-only terminal portfolio를 유지한다.
% We present \textsc{ZPDPatch}, a trajectory-supervised technique that aims repair feedback at a student's own code by constructing targets from execution evidence rather than from accepted solutions. A repair returned to a student is feedback, so how much of their program it replaces matters alongside whether the tests pass. We call repair whose supervision depends on that history \emph{trajectory-conditioned}, and no single comparison establishes a benefit for it, because more candidates alone improve a history-aware system and a new target rule also changes the training population. Our goal is to separate the target rule's effect from those of extra candidates and serialized history. \textsc{ZPDPatch} mines three execution-evidence relations, trains independent adapters, and selects a validation-frozen portfolio behind a gate that returns the submission unchanged rather than a regression. On 181 student-held-out Introductory Programming (CS1) Java trajectories under source- and count-matched training, terminal targets repair 155 and progress targets 92, leading on 15 of 17 exercises. On the 90 trajectories both rules repair, the retention advantage is zero for 63.3\% of students, positive for 31.1\%, and negative for 5.6\%. An online-judge corpus of 997 inputs from problems seen in training and 250 from held-out problems reproduces the tradeoff, with 19.2 and 11.2 percentage points less coverage and 5.6 and 6.5 points more retained tokens. Three fixed candidate draws alone add 15.1 points of repair rate, and these numbers describe the feedback, not learning. We therefore retain the current-only terminal portfolio.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

Automated Program Repair (APR)~\cite{gazzola2019automatic,monperrus2018automatic,weimer2009automatically,legoues2012genprog}은 과목이 손으로 써 줄 수 없는 피드백을 거절된 제출마다 주는 방법으로 프로그래밍 과제에서 널리 연구되어 왔다~\cite{keuning2018systematic}. 버기 제출과 그 문제의 테스트 묶음이 주어지면 기법은 패치, 즉 모든 테스트를 통과하는 프로그램을 반환하므로, 학생이 받는 것은 자기 과제가 동작하는 한 판본이다~\cite{joshi2023repair,zhang2024pydex}. 이를 위해 기법은 제출물의 어느 부분을 바꿀지 정하고, 주어진 재료에서 대체물을 합성하며, 테스트가 받아들이는 후보만 반환한다. 학생은 같은 과제에 반복해 제출하므로 기법이 마주하는 것은 버기 프로그램 하나가 아니라 순서열이다~\cite{duan2024tiktoc}.
% Automated Program Repair (APR)~\cite{gazzola2019automatic,monperrus2018automatic,weimer2009automatically,legoues2012genprog} has been widely studied for programming assignments as a way to give every rejected submission feedback that a course cannot write by hand~\cite{keuning2018systematic}. Given a buggy submission and the problem's test suite, a technique returns a patch, that is, a program that passes every test, so the student receives a working version of their own assignment~\cite{joshi2023repair,zhang2024pydex}. To this end, a technique decides which part of the submission to change, synthesizes a replacement from the material it is given, and returns only a candidate that the tests accept. A student submits repeatedly to the same assignment, so the technique faces a sequence rather than one buggy program~\cite{duan2024tiktoc}.

핵심 설계 결정은 그 재료가 무엇이냐, 곧 수리를 무엇을 향해 supervise하느냐다. 프로그래밍 과제를 위한 기존 기법은 그 재료를 어디서 가져오는지에 따라 세 범주로 나뉜다. alignment 기반 기법은 제출물을 다른 학생의 통과한 프로그램이나 교수자의 해답과 정렬하고~\cite{gulwani2018automated,wang2018search,hu2020re,heo2023referent,choi2021automated,choi2025automated}, 언어 모델 기반 기법은 버기 프로그램과 문제 설명에서 패치를 생성하며~\cite{joshi2023repair,zhang2024pydex,phung2023generating,liu2024fastfixer,yang2024cref,zhao2024peer,orvalho2025counterexample}, retrieval 기반 기법은 학습자별 해답을 찾아 생성을 유도한다~\cite{dai2026learner}. 여기에 더해 next-step hint 생성 기법은 과거의 올바른 프로그램들로 지은 해답 공간에서 편집 한 건을 끌어낸다~\cite{piech2015embeddings,rivers2017datadriven,price2017isnap,roest2024next}. 이 기법들은 학생 제출의 repair rate를 크게 높여 왔고, 조교가 볼 수 있는 것보다 많은 학생에게 다음 한 걸음이 닿게 했다~\cite{keuning2018systematic,koutcheme2024benchmarking}.
% The key design decision is what that material is, that is, what the repair is supervised toward. Existing techniques for programming assignments fall into three groups by where they take it from. Alignment-based techniques align the submission with other students' passing programs or an instructor's solution~\cite{gulwani2018automated,wang2018search,hu2020re,heo2023referent,choi2021automated,choi2025automated}; language-model-based techniques generate a patch from the buggy program and the problem statement~\cite{joshi2023repair,zhang2024pydex,phung2023generating,liu2024fastfixer,yang2024cref,zhao2024peer,orvalho2025counterexample}; and retrieval-based techniques look up a learner-specific solution to steer that generation~\cite{dai2026learner}. In addition, next-step hint generators draw one edit from a solution space built out of past correct programs~\cite{piech2015embeddings,rivers2017datadriven,price2017isnap,roest2024next}. These techniques have raised the repair rate for student submissions considerably, and put a next step within reach of more students than a tutor can see~\cite{keuning2018systematic,koutcheme2024benchmarking}.

그러나 기존 기법은 학생이 안내를 받으면 어디까지 갈 수 있는지를 알지 못한다. 반환물이 무엇을 향할지는 학생이 지금 어떤 테스트를 통과하는지와 무관하게 정해진다. 피드백은 학습자 자신의 작업에 구체적일 때 효과적이며~\cite{hattie2007power,shute2008focus}, 학생이 반환된 프로그램의 변경을 따라갈 수 있는 만큼만 도움이 된다~\cite{narciss2008feedback,aleven2000limitations}. 근접발달영역(ZPD)은 학습자의 능력을 혼자서 해낼 수 있는 것, 안내를 받으면 해낼 수 있는 것, 안내를 받아도 닿지 않는 것으로 나누며, 지원은 가운데 영역에 놓여야 한다~\cite{cole1978mind}. 제출물은 학생이 혼자서 만들어 낸 것이므로 첫 영역이 어디서 끝나는지를 보여 주고, 수준을 고려하지 않고 고른 피드백은 그 경계 너머 어디에나 놓일 수 있다. 그 영역들을 짚어내려면 그 자체로 별도의 측정이 필요하지만~\cite{murray2002toward,chounta2017grey,schulze2024beyond}, 반환물과 제출물 사이의 거리는 관측할 수 있다(Section~\ref{sec:limitation}). 가장 최신 기법인 LSGen~\cite{dai2026learner}의 평균 반환물은 학생의 평균 한 걸음의 2.5배이고, 중위 학생이 혼자 밟은 가장 큰 걸음보다도 크다. 따라서 기존 기법은 학생이 다음에 밟을 한 걸음이 아니라 완성된 남의 해답을 돌려준다. 이 연구에서, 우리는 supervision이 현재 제출에 이르는 순서열에 의존하는 수리를 \emph{trajectory-conditioned repair}로 정의하고, 그 순서열이 반드시 그 학생 자신의 것이어야 하는지를 따로 묻는다.
% However, existing techniques do not know how far a student can get with guidance. Where a return aims is settled without reference to which tests the student currently passes. Feedback works better when it is specific to the learner's own work~\cite{hattie2007power,shute2008focus}, and it helps only as far as the student can follow what the returned program changed in theirs~\cite{narciss2008feedback,aleven2000limitations}. The Zone of Proximal Development divides a learner's ability into what they can already do unaided, what they can do with guidance, and what stays out of reach even with it, and support has to land in the middle region~\cite{cole1978mind}. A submission is what the student produced unaided, so it marks where that first region ends, and feedback chosen without regard to the student's level can land anywhere beyond it. Locating those regions takes measurement of its own~\cite{murray2002toward,chounta2017grey,schulze2024beyond}, but the distance between a return and the submission is observable (Section~\ref{sec:limitation}). An average return of the most recent technique, LSGen~\cite{dai2026learner}, is 2.5 times an average student step and larger than the biggest step the median student took alone. Consequently, existing techniques hand back somebody else's finished solution rather than the next step the student could take. In this work, we define \emph{trajectory-conditioned repair} as repair whose supervision depends on the sequence leading to the current submission, and we ask separately whether that sequence has to be this student's own.

이 논문에서는 버기 제출을 학생이 안내를 받으면 도달할 수 있는 다음 걸음을 향해 수리하는 새로운 trajectory 기반 기법 \textsc{ZPDPatch}를 제안한다. 핵심 아이디어는 학생 자신의 trajectory가 그 걸음을 이미 기록하고 있다는 것이다. 실제로 다음에 온 제출은 그 학생이 머지않아 혼자서 도달한 프로그램이다. 다만 이 target만 따로 갈아 끼울 수는 없다(Section~\ref{sec:limitation}). 따라서 \textsc{ZPDPatch}는 source와 예제 수, 후보 예산을 고정하고, target을 맞춘 동료의 것으로 바꿔 끼우는 통제군을 둔다. 이를 위해 \textsc{ZPDPatch}는 Mine, Train, Select의 세 단계로 동작한다. Mine 단계는 버기 제출이나 trajectory의 보존된 prefix를 이후 제출과 세 규칙으로 짝짓는다. Progress는 판정이 나아지거나 판정은 같아도 통과 테스트가 늘어난 다음 상태를, Strict는 판정이 나아진 다음 상태를, Answer는 trajectory가 도달한 accepted 끝점을 취한다. Answer는 관례적 target을 비교 기준으로 남겨 둔 것이다. 같은 시간순 짝을 캐어 제출물에 맞는 해답을 찾아 쓰는 retrieval 기반 기법과 달리, 이 짝들은 supervision 신호 자체가 된다. Train 단계는 규칙마다 adapter를 독립적으로 학습한다. Select 단계는 학습 손실이 아니라 실행된 validation 수리를 기준으로 checkpoint 세 개의 조합을 고정한다. 그 결과 학생이 받는 것은 완성된 프로그램이므로 그것이 자기 제출물을 얼마나 대체하는지를 재고 제한할 수 있다.
% In this paper, we present \textsc{ZPDPatch}, a new trajectory-supervised technique that repairs a buggy submission toward the next step the student could reach with guidance. Our key idea is that the student's own trajectory already records that step, since the submission that actually came next is a program the student reached unaided soon after. This target, however, cannot be swapped in on its own (Section~\ref{sec:limitation}). \textsc{ZPDPatch} therefore holds the sources, the example counts, and the candidate budget fixed, and adds a matched-peer target control. To this end, \textsc{ZPDPatch} operates in three stages, Mine, Train, and Select. The Mine stage pairs a buggy submission, or a retained prefix of the trajectory, with a later submission under three rules. Progress takes the next state that improves the verdict or passes more tests at an unchanged verdict, Strict the next better-verdict state, and Answer the accepted endpoint, the conventional target we keep for comparison. Unlike retrieval-based techniques that mine the same chronological pairs to look up a solution for the submission, these pairs supply the supervision signal itself. The Train stage trains an independent adapter per rule. The Select stage freezes a triple of checkpoints by their executed validation repairs rather than by training loss. As a result, what a student receives is a complete program, so how much of their own submission it replaces can be measured and bounded.

실험 결과는 \textsc{ZPDPatch}가 비교한 기법들 가운데 학생의 프로그램을 가장 적게 바꾸고, 편집량을 제한하면 LSGen보다 더 많은 제출을 고침을 보여 준다. 우리는 CodeNet~\cite{puri2021project}의 382개 문제에서 모은 Python 제출 1,247개와 Introductory Programming (CS1) exercise 17개에서 모은 Java 제출 181개~\cite{duan2024tiktoc}로, 가장 최신의 선행 기법 LSGen~\cite{dai2026learner}과 미세조정하지 않은 같은 기반 모델 Zero-shot을 상대로 평가하였다. 제한된 편집 아래의 repair rate에서, \textsc{ZPDPatch}는 Abstract Syntax Tree (AST) 연산 20개의 edit budget에서 Python 제출의 44.0\%를 고쳐 LSGen(13.9\%)보다 많이 고쳤고, 사전에 지정한 여섯 budget 전체에서 평균 14.7 포인트 더 고쳤다. 패치 크기에서는 \textsc{ZPDPatch}가 평균 21.05개의 AST 노드를 바꾸어 LSGen의 88.27의 4분의 1에 못 미친다. source를 맞춘 조건에서 Progress target은 두 규칙이 모두 고친 입력에서 학생의 token을 5.6과 6.5 퍼센트포인트 더 유지했지만, 19.2와 11.2 포인트를 덜 고쳤다. 우리는 같은 두 방향을 student-disjoint CS1 Java에서 다시 보이고(Answer target이 17개 exercise 중 15개에서 앞섬), 고정 후보 draw 세 개만으로 수리율 15.1 포인트가 설명됨을 보인다. 다만 제한을 없애면 우리의 어떤 구성도 LSGen의 80.2\%를 넘지 못했으므로, 우리는 current-only Answer 3개 조합을 유지하고 Progress 규칙은 locality가 제약일 때의 선택지로 보고한다(Section~\ref{sec:experiment}).
% Experimental results demonstrate that \textsc{ZPDPatch} changes the least of a student's program among the techniques we compare, and under a bounded edit repairs more submissions than LSGen. We evaluated it on 1,247 Python submissions from 382 CodeNet problems~\cite{puri2021project} and 181 Java submissions from 17 Introductory Programming (CS1) exercises~\cite{duan2024tiktoc}, against LSGen~\cite{dai2026learner}, the most recent prior technique, and the same base model used zero-shot. In terms of repair rate under a declared edit budget, \textsc{ZPDPatch} fixed 44.0\% of the Python submissions at a budget of 20 Abstract Syntax Tree (AST) operations, more than LSGen (13.9\%), and 14.7 points more on average across six prespecified budgets. Regarding patch size, its patches changed 21.05 AST nodes on average, less than a quarter of LSGen's 88.27. Under matched sources, Progress targets kept 5.6 and 6.5 percentage points more of the student's tokens on the inputs both rules fixed, although they fixed 19.2 and 11.2 points fewer. We further show the same two directions on student-disjoint CS1 Java, where Answer targets lead on 15 of 17 exercises, and that three fixed candidate draws alone account for 15.1 points of the repair rate. Unrestricted, however, no configuration of ours exceeded LSGen's 80.2\%, so we retain the current-only Answer triple and report the Progress rule as the option for when locality binds (Section~\ref{sec:experiment}).

\subsection{Automated Program Repair for Programming Assignments}
\label{sec:formulation}

프로그래밍 과제를 수리하는 기존 기법들의 목표는 버기 제출을 그 문제의 테스트를 모두 통과하는 프로그램으로 바꾸는 것이다. 문제 \(p\)는 online judge가 내든 과목이 내든, 문제 설명과 자원 제한으로 이루어진 문제 맥락 \(d_p\)와 사용 가능한 테스트 묶음 \(\mathcal E\)를 함께 갖는다. 그 목표는 반환물이 테스트를 통과하는지만 묻고 학생이 무엇을 제출했는지는 묻지 않는다. 우리는 나머지 설정을 학생의 제출물 자체 위에 정의한다. \(p\)를 푸는 학생은 반복해 제출한다. 우리는 제출 하나를 삼중쌍 \(s=(c,v,o)\)로 정의하는데, \(c\)는 그 소스 코드를 나타내고, \(v\)는 플랫폼이 기록한 판정을 뜻하며, \(o\)는 \(\mathcal E\)의 각 테스트를 재실행 결과로 보내는 실행 증거를 가리킨다. 기록된 판정과 재실행 결과는 서로 다른 필드로 남기는데, 런타임 버전과 실행 변동성이 프로그램의 관측된 거동을 바꿀 수 있기 때문이다. \emph{trajectory} \(\tau=[s_1,\ldots,s_n,s_{\mathit{ac}}]\)는 그 상태들을 시간순으로 놓은 것으로, \(s_1,\ldots,s_n\)은 버기 제출이고 \(s_{\mathit{ac}}\)은 첫 accepted 제출이며 평가 기준으로만 쓰여 기법에 주어지지 않는다. 수리 대상은 마지막 버기 제출이고, 우리는 그것을 \emph{버기 프로그램} \(b=s_n\)이라 부른다. 각 \(\tau\)를 처음 기록된 acceptance에서 끊으면 \emph{정본} 데이터셋과 그 고정된 분할이 되고, 이후의 모든 측정은 그 위에서 이루어진다.
% Existing techniques for repairing programming assignments aim to turn a buggy submission into a program that passes every test of its problem. A problem \(p\), whether an online judge poses it or a course assigns it, comes with a problem context \(d_p\), its statement and resource limits, and an available test suite \(\mathcal E\). That aim asks only whether a return passes the tests, and nothing about what the student submitted. We define the rest of the setting on the student's submissions themselves. A student working on \(p\) submits repeatedly. We define a submission as a triple \(s=(c,v,o)\), where \(c\) represents its source code, \(v\) denotes the verdict the platform recorded, and \(o\) indicates execution evidence that sends each test of \(\mathcal E\) to its re-executed outcome. The recorded verdict and the replayed outcome stay in separate fields, because runtime versions and execution variability can change what a program is observed to do. The \emph{trajectory} \(\tau=[s_1,\ldots,s_n,s_{\mathit{ac}}]\) orders those states chronologically, with \(s_1,\ldots,s_n\) buggy and \(s_{\mathit{ac}}\) the first accepted submission, which serves only as evaluation ground truth and never reaches a technique. The submission to be repaired is the latest buggy one, and we call it the \emph{buggy program} \(b=s_n\). Cutting each \(\tau\) at its first recorded acceptance yields the \emph{canonical} dataset and its frozen split, on which every measurement below is taken.

\begin{algorithm}[h]
\caption{APR for Programming Assignments}
\label{alg:generic}
\footnotesize
\begin{algorithmic}[1]
\Require Buggy program $b$, Context $x$, Ordered generators $S$, Tests $\mathcal E$, Edit budget $B$
\Ensure Returned program $f$
\State $f\gets b$; $q^*\gets\textsc{Execute}(b,\mathcal E)$
\For{$g\in S$}
 \State $z\gets\mathsf{Generate}(g,x)$
 \If{$B<\infty$ and $\mathrm{ted}^{\dagger}(b,z)>B$}
  \State \textbf{continue}
 \EndIf
 \State $q\gets\textsc{Execute}(z,\mathcal E)$
 \If{$q=1$} \State \Return $z$ \EndIf
 \If{$(q,-\mathrm{ted}^{\dagger}(b,z))>(q^*,-\mathrm{ted}^{\dagger}(b,f))$}
  \State $f\gets z$; $q^*\gets q$
 \EndIf
\EndFor
\State \Return $f$
\end{algorithmic}
\end{algorithm}

Algorithm~\ref{alg:generic}은 기존 기법들의 방식에 따라 프로그래밍 과제를 위한 일반적인 수리 절차를 기술한다~\cite{gulwani2018automated,wang2018search,hu2020re}. 이 절차는 버기 프로그램 \(b\), 맥락 \(x\), 순서가 정해진 generator 집합 \(S\), 테스트 묶음 \(\mathcal E\), edit budget \(B\)를 입력으로 받아 프로그램 \(f\) 하나를 반환한다. 1번째 줄은 버기 프로그램 \(b\)를 반환물 \(f\)의 fallback으로 두고, \(\textsc{Execute}\)로 \(b\)가 통과한 테스트의 비율 \(q\)를 재어 \(q^*\)에 기록한다. 2--3번째 줄은 순서가 정해진 generator 묶음 \(S\)의 각 generator \(g\)를 차례로 돌며, \(\mathsf{Generate}\)가 맥락 \(x\)로부터 완전한 후보 \(z\) 하나를 만든다. 4--5번째 줄은 \(b\)로부터의 \(\mathrm{ted}^{\dagger}\)가 edit budget \(B\)를 넘는 후보를 건너뛴다. \(\mathrm{ted}^{\dagger}\)는 두 프로그램이 모두 파싱될 때의 AST edit distance이고 코드가 같으면 0, 그 밖에는 무한이다. 따라서 제한 없는 \(B\)는 구문 오류 수리를 허용하고 유한한 \(B\)는 거리가 정의되지 않는 변경을 받지 않는다. 6번째 줄은 후보를 실행하고, 7--8번째 줄은 모든 테스트를 통과하면 즉시 그 후보를 반환한다. 9--10번째 줄은 통과 비율이 더 높거나 같은 비율에서 \(b\)에 더 가까운 후보로 \(f\)를 갱신하며, 어떤 후보도 통과하지 못하면 11번째 줄이 \(f\)를 반환한다. 맥락 \(x\)가 무엇을 담는지와 \(S\)·\(B\)가 어디서 오는지는 당장은 미뤄 두자. 셋 모두 Section~\ref{sec:approach}에서 정해진다.
% Algorithm~\ref{alg:generic} describes a generic repair procedure for programming assignments in the style of existing techniques~\cite{gulwani2018automated,wang2018search,hu2020re}. It takes five inputs, a buggy program \(b\), a context \(x\), an ordered set \(S\) of generators, a test suite \(\mathcal E\), and an edit budget \(B\), and returns one program \(f\). Line~1 makes the buggy program \(b\) the fallback for the return \(f\) and uses \(\textsc{Execute}\) to record in \(q^*\) the fraction \(q\) of tests that \(b\) passes. Lines~2--3 take each generator \(g\) of the ordered set \(S\) in turn, and \(\mathsf{Generate}\) builds one complete candidate \(z\) from the context \(x\). Lines~4--5 skip a candidate whose \(\mathrm{ted}^{\dagger}\) from \(b\) exceeds the edit budget \(B\). Here \(\mathrm{ted}^{\dagger}\) is AST edit distance when both programs parse, zero for unchanged code, and infinity otherwise. An unrestricted \(B\) therefore admits syntax repair, whereas a finite one rejects changes whose distance is undefined. Line~6 executes the candidate and lines~7--8 return it as soon as every test passes. Lines~9--10 replace \(f\) with a candidate that passes a larger fraction, or the same fraction from closer to \(b\), and line~11 returns \(f\) when no candidate passes. For now, let us set aside what the context \(x\) holds and where \(S\) and \(B\) come from; all three are fixed in Section~\ref{sec:approach}.

기존 기법들은 Algorithm~\ref{alg:generic}을 서로 다르게 구체화한다. alignment 기반 기법은 3번째 줄의 generator를 참조 프로그램과의 정렬로 대체한다. CLARA~\cite{gulwani2018automated}는 \(b\)와 제어 흐름이 같은 참조 군집의 식을 쓰고, Sarfgen~\cite{wang2018search}은 제어 흐름이 같은 참조를 AST 위에서 정렬하며, Refactory~\cite{hu2020re}는 참조를 \(b\)의 제어 흐름 쪽으로 리팩터링하고, 과제를 고려한 기법들은 참조를 고르는 방식을 달리한다~\cite{heo2023referent,choi2021automated,choi2025automated}. 언어 모델 기반 기법~\cite{joshi2023repair,zhang2024pydex,phung2023generating,liu2024fastfixer,yang2024cref,zhao2024peer,orvalho2025counterexample}은 3번째 줄과 흔히 2번째 줄의 generator 집합을 모델로 대체한다. retrieval 기반 기법인 LSGen~\cite{dai2026learner}은 그 모델을 그대로 두고 학습자별 해답을 맥락 \(x\)로 끌어온다. next-step hint 생성 기법~\cite{piech2015embeddings,rivers2017datadriven,price2017isnap,roest2024next}은 프로그램이 아니라 편집 한 건을 반환하므로 6번째 줄도 4번째 줄도 적용되지 않는다. 어느 경우든 generator가 향하는 곳은 accepted solution이나 해답 공간이며, 도움받는 학생의 이후 제출이 아니다.
% Existing techniques instantiate Algorithm~\ref{alg:generic} in different ways. Alignment-based techniques replace the generator at line~3 with an alignment against reference programs. CLARA~\cite{gulwani2018automated} uses the expressions of a reference cluster sharing the control flow of \(b\), Sarfgen~\cite{wang2018search} aligns same-control-flow references on their ASTs, Refactory~\cite{hu2020re} refactors references toward the control flow of \(b\), and assignment-aware techniques vary how references are chosen~\cite{heo2023referent,choi2021automated,choi2025automated}. Language-model-based techniques~\cite{joshi2023repair,zhang2024pydex,phung2023generating,liu2024fastfixer,yang2024cref,zhao2024peer,orvalho2025counterexample} replace line~3 and often the generator set at line~2 with a model. Retrieval-based LSGen~\cite{dai2026learner} keeps that model and retrieves a learner-specific solution into the context \(x\). Next-step hint generators~\cite{piech2015embeddings,rivers2017datadriven,price2017isnap,roest2024next} return one edit rather than a program, so neither line~6 nor line~4 applies to them. In every case the generator is steered toward an accepted solution or a solution space, never toward the later submissions of the student being helped.

\subsection{Limitation of Solution-Supervised Repair}
\label{sec:limitation}

\begin{figure}[h]
\centering
\includegraphics{Figures/icse-seet-student-reach.pdf}
\caption{Students' own steps and LSGen's returns within each budget}
\label{fig:reach}
\end{figure}

우리의 핵심 관찰은 해답을 향해 supervise된 수리가 학생이 서 있는 자리에서의 한 걸음을 돌려주지 않는다는 것이다. \(b\)의 대부분을 대체하는 반환물은, 학생이 안내를 받아 결국 그것에 닿을 수 있는지와 무관하게, \(b\)의 연속이 아니다. Section~\ref{sec:introduction}이 적었듯 학생의 영역을 직접 짚으려면 별도의 측정이 필요하므로, 우리는 연속과 대체를 가르는 양, 곧 반환물이 \(b\)를 얼마나 남기는지를 센다. 이를 Algorithm~\ref{alg:generic}의 \(\mathrm{ted}^{\dagger}\)와, 반환물이 보존한 \(b\)의 token 비율인 token retention으로 측정한다(Section~\ref{sec:experiment}). 더 정확히, \(b\)로부터의 거리가 선언된 budget \(B\) 이내인 반환물을 \emph{bounded step}이라 부른다. \(B\)는 과목이 한 수리에 내어 줄 학생 프로그램의 양이다.
% Our key observation is that solution-supervised repair does not return a step from where the student stands. A return that replaces most of \(b\) is not a continuation of it, whether or not the student could reach it with guidance. As Section~\ref{sec:introduction} notes, locating a student's regions takes measurement of its own, so we count what separates a continuation from a replacement, namely how much of \(b\) the return keeps. We measure it by the \(\mathrm{ted}^{\dagger}\) of Algorithm~\ref{alg:generic} and by token retention, the fraction of the tokens of \(b\) that the return preserves (Section~\ref{sec:experiment}). More precisely, we call a return whose distance from \(b\) is at most a declared budget \(B\) a \emph{bounded step}, where \(B\) is the amount of a student's program a course is willing to give up to one repair.

Figure~\ref{fig:reach}는 학생들 자신이 한 걸음을 얼마나 크게 밟는지와 LSGen이 그 걸음 안에서 무엇을 수리하는지를, Seen 평가 입력 997개의 저장된 trajectory에서 연속한 두 제출 사이의 거리로 재어 반환물과 같은 척도에 놓는다. Seen에서 거리가 정의된 2,581개 걸음의 중위수는 15이고, 한 걸음은 제출물 token의 중위수 96.1\%를 남긴다. 제한을 두지 않을 때 LSGen의 반환물은 88.27, Zero-shot은 27.25다. 한 학생이 한 문제에서 혼자 밟은 가장 큰 걸음을 그 학생이 \emph{입증한 도달 범위}라 한다. LSGen의 평균 반환물은 평균적인 학생 한 걸음의 2.5배이며, 중위 학생이 혼자 밟아 본 가장 큰 걸음보다도 크다. AST 연산 20개는 학생 한 걸음의 중위수에 가깝고 학생의 30.9\%가 그 안에 도달 범위를 두지만 LSGen은 13.9\%를 수리하며, 160은 학생의 90.3\%를 덮는다. 놀랍게도 LSGen이 수리해 낼 수 있는 제출물의 다섯 중 넷은 한 걸음 안에 들어오지 않는다. 제한이 없을 때는 80.2\%를 수리하기 때문이다. 이 측정은 학생이 한 번에 무엇을 바꾸는지를 세며, 어떤 걸음이 그 학생의 영역 안이었는지는 세지 않는다.
% Figure~\ref{fig:reach} measures how large a step the students themselves take, and what LSGen repairs within it, as the distance between consecutive submissions in the stored trajectories of the 997 Seen evaluation inputs, on the scale the returns are measured on. On Seen the 2,581 steps with a defined distance have a median of 15, and one step leaves a median of 96.1\% of the submission's tokens in place. Unrestricted, the returns of LSGen sit at 88.27 and those of the zero-shot model at 27.25. We call the largest step a student took unaided on a problem their \emph{demonstrated reach}. An average LSGen return is 2.5 times an average student step and larger than the biggest step the median student took alone. Twenty AST operations is close to the median student step and within the reach of 30.9\% of students, where LSGen repairs 13.9\%, and 160 covers the reach of 90.3\% of students. Surprisingly, four out of five of the submissions LSGen can repair are not repaired within one step, since it repairs 80.2\% of them when nothing bounds the step. This measurement counts what a student changes at once, not which steps lay inside that student's region.

선행 기법들도 이미 작은 변경을 요구한다. Refactory는 최소 수리를 합성하고~\cite{hu2020re}, LSGen은 모델에 최소 변경을 지시한다~\cite{dai2026learner}. 위에서 측정한 LSGen의 반환물이 그 지시의 결과다. 한 가지 대안은 기존 기법에 budget만 거는 것이다. 위의 13.9\%가 바로 그 결과이며, 수리 범위의 대부분을 잃는다. accepted solution을 향해 유도된 generator에게는 물러설 더 작은 후보가 없기 때문이다. 다른 대안은 target만 그 학생의 이후 제출로 갈아 끼우고 나머지를 그대로 두는 것이다. 그것은 한 변수만 바꾸는 개입이 아니다. 같은 trajectory에서 Answer 규칙은 40,454개의 예제를 내지만 Strict는 16,973개, Progress는 21,416개를 내고, 규칙이 긁어 오는 source의 출현 빈도도 함께 바뀐다. 규칙이 무엇을 보존하는지도 함께 바뀐다: 통과 벡터가 \((1,0,0)\), \((1,1,0)\), \((0,1,1)\)인 wrong-answer 제출 세 개에서, 판정만 보는 여과는 둘째와 셋째를 구별하지 못하지만, 테스트 단위 progress는 통과한 테스트를 모두 지키며 하나를 더 얻은 둘째를 남기고 하나를 얻었으나 다른 하나를 잃은 셋째는 남기지 않는다. 게다가 후보를 더 주는 것만으로도 수리율이 오르므로, 후보 예산을 고정하지 않은 비교는 target의 효과를 추정하지 않는다~\cite{zhang2024pydex,koutcheme2024benchmarking,yang2024cref,orvalho2025counterexample,dai2026learner}.
% Prior techniques already ask for a small change: Refactory synthesizes minimal repairs~\cite{hu2020re} and LSGen instructs the model to make minimal changes~\cite{dai2026learner}. The LSGen returns measured above are what that instruction produces. One alternative is to bound the step of an existing technique. The 13.9\% above is that alternative, and it costs most of the coverage, because a generator steered toward an accepted solution has no smaller candidate to fall back on. Another is to swap the target for the student's own later submission and leave everything else alone. That is not a one-variable intervention: from the same trajectories the Answer rule yields 40,454 examples but Strict and Progress yield 16,973 and 21,416, and the source frequencies move with the rule as well. What a rule retains moves with it too: among three wrong-answer submissions with pass vectors \((1,0,0)\), \((1,1,0)\), and \((0,1,1)\), verdict-only filtering cannot tell the second from the third, while test-wise progress retains the second, which keeps every passed test and gains one, and not the third, which gains one but loses another. Extra candidates also raise the repair rate on their own, so a comparison that does not hold the candidate budget fixed does not estimate the target's effect~\cite{zhang2024pydex,koutcheme2024benchmarking,yang2024cref,orvalho2025counterexample,dai2026learner}.

이러한 한계는 학생 자신의 trajectory를 길잡이로 삼는 우리의 접근을 동기화한다. 본 논문의 목표는 버기 프로그램을 테스트를 통과하면서 제출물을 최대한 남기는 프로그램으로 고치고, 그 이득이 target에서 왔음을 읽을 수 있게 하는 것이다. Algorithm~\ref{alg:generic}의 관점에서 우리는 generator를 accepted solution이나 해답 공간이 아니라 그 학생의 이후 제출을 향해 학습시킨다. 따라서 본 연구는 두 가지 난제를 다룬다. (1) 그 학생의 이후 제출이 다음 걸음을 거칠게만 짚으며 그 자체가 accepted일 수도 있다는 점, 그리고 (2) 이득을 target에 귀속시키려면 source와 예제 수, 후보 예산을 함께 고정해야 한다는 점이다.
% These limitations motivate our approach, which repairs under the guidance of the student's own trajectory. The goal of this paper is to repair a buggy program into one that passes the tests while keeping as much of the submission as possible, and to make the gain readable as the target's. In terms of Algorithm~\ref{alg:generic}, we train the generator toward the student's own later submission rather than toward an accepted solution or a solution space. Our work thus tackles two challenges, (1) that the student's later submission marks the next step only coarsely and may itself be accepted, and (2) that attributing a gain to the target requires holding the sources, the example counts, and the candidate budget fixed.

\section{Our Approach}
\label{sec:approach}

\subsection{Overview}

\begin{algorithm}[h]
\caption{\textsc{ZPDPatch}}
\label{alg:construct}
\footnotesize
\begin{algorithmic}[1]
\Require Trajectories $\mathcal T$, Execution evidence $\mathcal O$, Validation inputs $U$, Seeds $\Sigma$, Portfolio size $\eta_k$, Edit budget $B$
\Ensure Frozen ordered checkpoint portfolio $S$
\State /* Step 1. Mine the three target datasets */
\State $(D_A,D_S,D_P)\gets(\emptyset,\emptyset,\emptyset)$
\For{$\tau=[s_1,\ldots,s_n]\in\mathcal T$}
 \State $D_A\gets D_A\cup\mathsf{TerminalPairs}(\tau)$ \Comment{Answer}
 \For{$\rho\in\{S,P\}$}
  \State $R\gets[s_1]$ \Comment{retained prefix}
  \For{$s_t\in[s_2,\ldots,s_n]$}
   \If{$\mathsf{Improves}_{\rho}(R[-1],s_t;\mathcal O)$}
    \State $D_\rho\gets D_\rho\cup\{(R,c_t)\}$; $R\gets R\mathbin{\|}[s_t]$
   \EndIf
  \EndFor
 \EndFor
\EndFor
\State
\State /* Step 2. Train one adapter per rule and seed */
\State $V\gets\emptyset$
\For{$(\rho,\sigma)\in\{A,S,P\}\times\Sigma$}
 \State $V\gets V\cup\{\mathsf{Train}(D_\rho,\sigma)\}$
\EndFor
\State
\State /* Step 3. Select a portfolio by executed validation repairs */
\For{$g\in V$}
 \State $R_g^B\gets\mathsf{Validate}(g,U,B)$ \Comment{$R_g^B\subseteq U$}
\EndFor
\State $S\gets\mathsf{Select}(\{R_g^B\}_{g\in V},\eta_k)$ \Comment{$\eta_k=3$}
\State \Return $\mathsf{FreezeAndOrder}(S)$
\end{algorithmic}
\end{algorithm}

우리의 접근은 오프라인 구성과 온라인 수리를 분리한다. Mine은 데이터셋을 만들고, Train은 adapter를 적합시키며, Select는 학습 손실이 아니라 실행된 validation 수리를 기준으로 portfolio를 고정한다. checkpoint들은 동일한 허용 입력에서 후보를 주고받지 않고 독립적으로 생성한다. mixed pool은 관계마다 seed 3개를 담으며, Answer-only와 current-only 변형은 통제군이다. 세 단계는 코퍼스마다 한 번 실행되고, 이후 배포는 고정된 checkpoint로 수리를 제공하며 선택된 checkpoint마다 호출을 최대 한 번씩만 내므로 배포 예산은 세 번의 호출이다.
% Our approach separates offline construction from online repair. Mine constructs datasets, Train fits adapters, and Select freezes a portfolio using executed validation repairs rather than training loss. Checkpoints generate independently from the same permitted input, without exchanging candidates. The mixed pool contains three seeds per relation; Answer-only and current-only variants are controls. The three stages run once per corpus, after which deployment serves repairs from the frozen checkpoints and issues at most one call per selected checkpoint, so the deployed budget is three calls.

\subsection{Mine}
Mine의 목표는 모든 supervision 짝이 관측된 source와 이후 제출로 추적되도록 만드는 것이다. 제출들은 문제와 사용자로 묶이고, 시간순으로 정렬되며, 첫 acceptance에서 끊긴다. 정본 정규화는 연속 중복을 제거하면서 생성과 실행에 쓰인 소스 코드는 보존한다. 빌더는 history 길이나 전이 수에 상한을 두지 않는다. 대신 whole-trajectory 필터가, 필요한 prompt--target 구성 중 하나라도 4,096 토큰을 넘으면 분할 전에 그 trajectory를 제외한다. 제외는 평가 모집단을 바꾸지만, 프로그램이나 history를 잘라내지는 않는다.
% The goal of Mine is to make every supervision pair traceable to an observed source and a later submission. Submissions are grouped by problem and user, chronologically ordered, and cut at the first acceptance. Canonical normalization removes consecutive duplicates while preserving the source code used for generation and execution. The builder imposes no maximum history or transition count. A whole-trajectory filter instead excludes a trajectory before splitting if any required prompt--target configuration exceeds 4,096 tokens. Exclusion changes the evaluated population, but never truncates a program or history.

거친 severity 함수는 Accepted(AC)에 0, Wrong Answer(WA)에 1, Time 또는 Memory Limit Exceeded(TLE/MLE)에 2, Runtime Error(RE)에 3, Compile Error(CE)에 4를 부여하며, 인식되지 않은 결과와 내부 오류는 가장 심각한 범주에 둔다. Strict는 기록된 판정을 비교한다. Progress는 기록된 판정 문자열이 같을 때 재실행 결과까지 비교한다. 그 캐시는 완전해야 하고, 비교되는 벡터들은 비어 있지 않은 동일한 testcase 키를 가져야 한다. provenance에는 문제, 코드, 테스트, 실행 구성이 포함된다.
% The coarse severity function assigns 0 to Accepted (AC), 1 to Wrong Answer (WA), 2 to Time or Memory Limit Exceeded (TLE/MLE), 3 to Runtime Error (RE), and 4 to Compile Error (CE); unrecognized and internal outcomes occupy the most severe category. Strict compares recorded verdicts. Progress additionally compares replayed outcomes when the recorded verdict strings agree. Its cache must be complete, and compared vectors must have equal, nonempty testcase keys. Provenance includes problem, code, tests, and execution configuration.

testcase 전체 집합이 같을 때, \(o_t\prec_\times o_r\)는 \(o_t\)의 모든 테스트가 \(o_r\)의 대응 테스트보다 severity가 크지 않고 적어도 하나에서 엄격히 감소할 때 성립한다. 형식적으로, 개선 술어는 다음과 같다:
% For equal testcase universes, \(o_t\prec_\times o_r\) holds when every test in \(o_t\) has severity no greater than its counterpart in \(o_r\), with a strict decrease on at least one. Formally, the improvement predicates are:
\begin{equation}
\begin{aligned}
\mathsf{Improves}_S(r,t)&\iff \mathrm{sev}(v_t)<\mathrm{sev}(v_r),\\
\mathsf{Improves}_P(r,t)&\iff \mathsf{Improves}_S(r,t)\\
 &\quad\lor\ (v_t=v_r\land o_t\prec_\times o_r).
\end{aligned}
\label{eq:progress}
\end{equation}
직관적으로 Equation~\eqref{eq:progress}는 거친 개선과, 판정이 바뀌지 않아 가려진 progress를 함께 보존한다. RE에서 WA로의 severity 개선이 반드시 통과 비율을 높이지는 않으며, 판정을 개선하는 간선이 테스트 단위 우위를 요구하지도 않는다.
% Intuitively, Equation~\eqref{eq:progress} retains coarse improvements and progress hidden by an unchanged verdict. A severity improvement such as RE to WA need not increase the pass fraction, and a verdict-improving edge does not require test-wise dominance.

Answer는 AC가 아닌 각 source와 accepted 끝점에 대해 독립적인 짝을 낸다. 따라서 \([s_1,\ldots,s_9]\)는 \(([s_1],c_9),\ldots,([s_8],c_9)\)를 만들며, 누적된 prefix를 Answer 학습에 노출하지 않는다. Strict와 Progress는 \(R=[s_1]\)에서 시작해 이후 각 상태를 \emph{마지막으로 보존된} 상태와 비교하고, 술어가 성립할 때만 덧붙인다. \(s_t\)를 덧붙이기 전에 빌더는 \((R,c_t)\)를 낸다. WA, 개선된 WA, AC의 경우 Strict는 \(([s_1],c_3)\)을 내고 Progress는 \(([s_1],c_2)\)와 \(([s_1,s_2],c_3)\)을 낸다. accepted 끝점은 두 규칙에서 모두 적격으로 남는다. Strict의 쌍별 술어가 Progress의 것에 포함되더라도, 독립적으로 훑어 얻은 간선 집합이 포함 관계일 필요는 없다.
% Answer emits an independent pair for each non-AC source and the accepted endpoint. Thus \([s_1,\ldots,s_9]\) yields \(([s_1],c_9),\ldots,([s_8],c_9)\); it does not expose accumulated prefixes to Answer training. Strict and Progress start with \(R=[s_1]\), compare each later state with the \emph{last retained} state, and append it only when the predicate holds. Before appending \(s_t\), the builder emits \((R,c_t)\). For WA, improved WA, AC, Strict emits \(([s_1],c_3)\), whereas Progress emits \(([s_1],c_2)\) and \(([s_1,s_2],c_3)\). The accepted endpoint remains eligible in both rules. Although Strict's pairwise predicate is contained in Progress's, their independently scanned edge sets need not be nested.

시간순 인덱스는 엄격히 증가하므로 구성은 순환 없이 종료한다. 키가 고정된 증거에서는 보존된 간선이 해당 판정/테스트 severity 순위도 낮춘다. 이는 빌더의 불변식이며, 학습된 ZPD 효과의 증거가 아니다. accepted/non-accepted 이진 mining은 Strict 짝 16,973개 중 14,027개, Progress 짝 21,416개 중 18,009개를 보존한다. 그 라벨로 재학습한 모델은 Seen 수리 결정의 84.6\%와 87.5\%에서 정본 모델과 일치하므로(Section~\ref{sec:generality}), 우리는 이 순서를 보편적인 것이 아니라 운용적인 것으로 읽는다.
% Chronological indices strictly increase, so construction terminates without cycles. With fixed-key evidence, retained edges also decrease the appropriate verdict/test severity rank. These are builder invariants, not evidence of a learned ZPD effect. Binary accepted/non-accepted mining retains 14,027 of 16,973 Strict pairs and 18,009 of 21,416 Progress pairs. Models retrained on them agree with the canonical ones on 84.6\% and 87.5\% of Seen repair decisions (Section~\ref{sec:generality}), so we read the ranking as operational rather than universal.

\subsection{Train}
Train의 목표는 모델과 최적화를 비교 가능하게 유지하면서 각 관계를 독립적으로 학습하는 것이다. 구현은 Qwen2.5-Coder-7B-Instruct를 4-bit 양자화 Low-Rank Adaptation(QLoRA)으로 미세조정한다~\cite{hui2024qwen2,dettmers2023qlora}. adapter는 rank 16, scaling 32, dropout 0.05이며 attention과 feed-forward projection을 대상으로 한다. 정본 학습은 1 epoch, 학습률 \(2\times10^{-4}\), seed 2027--2029를 쓴다. cross-entropy 손실은 assistant target 토큰에서만 계산한다. 역할 중립 prompt는 문제 설명, 제한, 허용된 제출들, 실행/편집 요약, 완전한 해답 요청을 담는다. 규칙 이름도 선호하는 패치 크기도 적지 않으므로, 특화는 명시적 지시가 아니라 데이터에서 나와야 한다.
% The goal of Train is to learn each relation independently while keeping model and optimization comparable. The implementation fine-tunes Qwen2.5-Coder-7B-Instruct with 4-bit Quantized Low-Rank Adaptation (QLoRA)~\cite{hui2024qwen2,dettmers2023qlora}. Adapters have rank 16, scaling 32, and dropout 0.05, targeting attention and feed-forward projections. Canonical training uses one epoch, learning rate \(2\times10^{-4}\), and seeds 2027--2029. Assistant target tokens supply cross-entropy loss. The role-neutral prompt contains the statement, limits, permitted submissions, execution/edit summaries, and a request for a complete solution. It names neither the rule nor a preferred patch size, so specialization must come from the data rather than explicit instructions.

target은 오프라인에서 이용 가능한 미래 제출이며, 추론 입력은 관측된 상태만 담는다. current-only 통제는 위치를 재설정하고 더 앞선 항목을 제거해, 위치 라벨을 통한 길이 누출을 막는다. Answer 학습은 이미 단일 source이므로 추론 시 history를 주면 분포 변화가 생긴다. 반면 history 제거 재학습 통제는 target을 고정하고 더 앞선 제출의 직렬화만 바꾼다. source를 맞춘 target 학습은 현재 입력과 개수를 고정한다.
% Targets are future submissions available offline; inference inputs contain only observed states. Current-only controls reset positions and remove earlier entries, preventing length leakage through position labels. Answer training is already single-source, so supplying history at inference creates a distribution change. The history-removal retraining control instead holds targets fixed and changes earlier-submission serialization. Source-matched target training holds current input and count fixed.

paired-target 통제는 문제, 사용자, 제출 식별자, 정확히 같은 버기 프로그램으로 레코드를 내부 결합하고, Answer target과 Progress target이 서로 다른 source만 남긴다. 조건마다 학습 7,389개와 validation 931개 예제가 동일한 current-only 입력을 쓴다. 별도의 peer 통제는 같은 문제, 같은 split의 다른 사용자를 요구하며 target의 실행 증거가 정확히 같아야 한다. 같은 사용자의 target을 \(y_u\), 그 동료 교체본을 \(y_v\)라 하면, semantic-token diff 거리 \(d\)에 대해 불일치 \(\delta=|d(c,y_v)-d(c,y_u)|\)가 \(\delta\le2\) 또는 \(\delta/\max(1,d(c,y_u))\le0.1\)을 만족해야 한다. 증거가 희소한 집단을 먼저 방문하며, 동점일 때는 거리 불일치, 재사용, 식별자 순으로 우선하고 donor 재사용은 3회로 제한한다. 이 그리디 규칙은 조건마다 학습 5,231개와 validation 306개 예제를 만든다. 결과가 같고 거리가 가깝다는 것이 구조나 스타일의 동일성을 뜻하지는 않으므로, 측정된 효과는 교체 규칙 전체에 속하며 provenance만 떼어낸 것이 아니다.
% The paired-target control inner-joins records by problem, user, submission identifier, and the exact buggy program, retaining sources with distinct Answer and Progress targets. Its 7,389 training and 931 validation examples per condition use identical current-only inputs. The separate peer control requires another user on the same problem and in the same split, with exactly equal target execution evidence. Writing \(y_u\) for the same-user target and \(y_v\) for its peer replacement, for semantic-token diff distance \(d\) the discrepancy \(\delta=|d(c,y_v)-d(c,y_u)|\) must satisfy \(\delta\le2\) or \(\delta/\max(1,d(c,y_u))\le0.1\). Scarce evidence groups are visited first; ties prioritize distance discrepancy, reuse, and identifier, with donor reuse capped at three. This greedy rule yields 5,231 training and 306 validation examples per condition. Equal outcomes and nearby distances do not equate structure or style, so its measured effect belongs to the entire replacement rule, not isolated provenance.

\subsection{Select}
Select의 목표는 최종 테스트 결과를 보지 않고 고른, 크기가 제한된 portfolio를 배포하는 것이다. validation 입력 \(U\)에 대해 \(R_v^B\)를 checkpoint \(v\)가 edit budget \(B\) 안에서 수리한 입력이라고 하자. 형식적으로, 선택은 다음을 최대화한다:
% The goal of Select is to deploy a bounded portfolio chosen without final-test outcomes. For validation inputs \(U\), let \(R_v^B\) be inputs repaired by checkpoint \(v\) within edit budget \(B\). Formally, selection maximizes:
\begin{equation}
 f_B(S)=\frac{1}{|U|}\left|\bigcup_{v\in S} R_v^B\right|,\qquad |S|=3.
\label{eq:portfolio}
\end{equation}
직관적으로 Equation~\eqref{eq:portfolio}는 낮은 학습 손실이나 모든 관계의 포함이 아니라 서로 보완되는 성공을 보상한다. validation은 적격한 461개 문제마다 해시로 고정한 trajectory 하나를 쓴다. mixed pool은 checkpoint 9개와 84개 조합을 갖고, 관계마다 하나씩 요구하면 대신 27개가 된다. 제한 없는 기본 mixed 선택은 Answer2027, Answer2028, Progress2027이다. 관계 제약을 둔 선택은 별개의 조건이다. Answer-9Choose3은 terminal checkpoint 9개와 동일한 84개 조합 탐색을 받는다. 동점은 기록된 pass-rate, improvement, 결정적 식별자 우선순위로 처리한다. budget 지정 선택은 \(B\in\{5,10,20,40,80,160\}\)에서 선언된 목적식을 반복하며, 테스트 결과를 보고 budget을 고르지 않는다.
% Intuitively, Equation~\eqref{eq:portfolio} rewards complementary successes, not low training loss or the presence of every relation. Validation uses one fixed-hash trajectory from each of 461 eligible problems. The mixed pool has nine checkpoints and 84 triples; requiring one checkpoint per relation instead permits 27. The primary unconstrained mixed choice is Answer2027, Answer2028, and Progress2027. The relation-constrained choice is a different condition. Answer-9Choose3 receives nine Answer checkpoints and the same 84-triple search. Ties use recorded pass-rate, improvement, and deterministic identifier priorities. Budget-indexed selection repeats the declared objective at \(B\in\{5,10,20,40,80,160\}\), without choosing a budget from test results.

선택된 checkpoint와 그 순서는 고정된다. 각각은 독립적인 후보를 최대 하나 내며, 처음 관측된 acceptance에서 생성을 멈춘다. 모든 테스트를 통과하는 것이 없으면 Algorithm~\ref{alg:generic}은 통과 비율을 먼저, 그다음 더 작은 거리를 우선한다. 바뀌지 않은 코드가 항상 가능하므로, 동일한 고정 실행 측정에서는 반환된 통과 비율이 낮아질 수 없고 유한한 edit budget을 넘을 수도 없다. 이는 테스트 단위 비회귀가 아니다: 비율이 같아도 서로 다른 테스트에서의 이득과 손실이 가려질 수 있다. 또한 새로운 실행, 보지 못한 테스트 묶음, 자원 변동성 하에서의 비회귀를 보장하지도 않는다.
% Selected checkpoints and order are frozen. Each emits at most one independent candidate, and the first observed acceptance stops generation. If none passes all tests, Algorithm~\ref{alg:generic} prioritizes pass fraction and then smaller distance. Because unchanged code is feasible, for the same fixed execution measurements the returned pass fraction cannot decrease, and a finite edit budget cannot be exceeded. This is not per-test non-regression: equal fractions can conceal gains and losses on different tests. It also does not guarantee non-regression under fresh execution, an unseen suite, or resource variability.

후보가 고정되고 독립적이면, 순서는 호출 수와 패치의 정체를 바꾸지만 적격한 acceptance의 존재 여부는 바꾸지 않는다. terminal 짝짓기는 trajectory 길이에 선형이며, \(n\)개 제출을 \(m\)개 테스트로 재실행하려면 \(O(nm)\)의 실행과 증거 저장이 필요하다. 84개 조합 탐색은 우리 pool 크기에서 한정된 것이며 확장되는 최적화기가 아니다.
% For fixed independent candidates, order changes calls and patch identity but not the existence of an eligible acceptance. Terminal pairing is linear in trajectory length; replaying \(n\) submissions on \(m\) tests requires \(O(nm)\) executions and evidence storage. The 84-triple search is bounded at our pool size, not a scalable optimizer.

\noindent\textbf{Evaluation Metrics.} 우리는 세 종류의 결과를 측정한다. 반환물이 테스트를 통과하는지, 그 변경이 얼마나 큰지, 제출물을 얼마나 남기는지이다. Repair Rate(RR)는 반환된 프로그램이 모든 테스트를 통과한 적격 입력의 비율이다. Pass Rate(PR)는 통과 테스트 비율의 평균이고, Improvement Rate(IR)는 그 비율이 증가한 경우를 센다. AST 사이의 Tree Edit Distance(TED)는 현재 코드에서 반환 코드까지의 변경을 측정하며~\cite{zhang1989simple,pawlik2016tree}, 어느 한쪽이 파싱되지 않으면 정의되지 않는다. 정의되지 않는 경우는 제한 없는 RR에는 남지만 TED 요약에는 들어가지 않으며, 유한한 gate는 거리가 정의되지 않는 변경을 거부한다. 짝짓지 않은 TED는 성공하고 파싱 가능한 반환물의 평균이고, 짝지은 locality는 공동 성공만 쓴다. retention은 \texttt{SequenceMatcher}(autojunk 해제)가 일치시킨 토큰 또는 공백을 제거한 비어 있지 않은 줄을 source 개수로 나눈다. Python 토큰화는 레이아웃 토큰을 빼고 주석은 유지하며, Java는 단어와 구두점을 분리한다. retention 차이는 퍼센트포인트(pp)이며 토큰 수나 학습 측정치가 아니다.
% \noindent\textbf{Evaluation Metrics.} We measure three kinds of outcome: whether the returned program passes the tests, how large its change is, and how much of the submission it keeps. Repair Rate (RR) is the fraction of eligible inputs whose returned program passes every test. Pass Rate (PR) averages passed-test fractions; Improvement Rate (IR) records an increased fraction. Tree Edit Distance (TED) between ASTs measures current-to-returned change~\cite{zhang1989simple,pawlik2016tree} and is undefined when either program does not parse. Undefined cases remain in unrestricted RR but not TED summaries; finite gates reject undefined-distance changes. Unpaired TED averages successful, parseable returns; paired locality uses joint successes. Retention divides tokens or nonempty stripped lines matched by \texttt{SequenceMatcher} (autojunk disabled) by the source count. Python tokenization omits layout tokens but keeps comments; Java separates words and punctuation. Retention differences are percentage points (pp), not token counts or learning measures.

따로 언급하지 않으면 대괄호는 복원추출한 10,000회 problem-cluster 재표집에서 얻은 95\% percentile bootstrap 구간이며, 표집된 각 cluster에서 짝지은 입력을 모두 보존한다~\cite{efron1979bootstrap}. Java는 학생과 exercise를 따로 재표집한다. instance 가중 추정치는 합산 차이를 표집 입력 수로 나누고, equal-problem 추정치는 문제별 평균을 평균한다. 정확 양측 McNemar 검정은 cluster를 고려한 구간을 대체하지 않고 보조할 뿐이다~\cite{mcnemar1947note}. Holm 보정은 history 제거 재학습 4개 검정(Strict/Progress $\times$ Seen/Unseen)에 적용되며 모든 탐색적 대비에 적용되는 것이 아니다~\cite{holm1979simple}. 개별 비율의 Wilson 구간은 따로 보고한다~\cite{wilson1927probable}. 프로토콜은 통제가 언제 고정되었는지 밝히지만 연구가 외부에 사전등록된 것은 아니며, 적응적으로 들여다본 개발은 탐색적으로 남는다.
% Unless stated otherwise, brackets give 95\% percentile bootstrap intervals from 10,000 problem-cluster resamples with replacement, preserving all paired inputs in each sampled cluster~\cite{efron1979bootstrap}. Java separately resamples students and exercises. Instance-weighted estimates divide pooled differences by sampled inputs; equal-problem estimates average problem means. Exact two-sided McNemar tests are supplementary to the cluster-aware intervals, not substitutes for them~\cite{mcnemar1947note}. Holm adjustment covers the four history-removal retraining tests (Strict/Progress $\times$ Seen/Unseen), not every exploratory contrast~\cite{holm1979simple}; individual-rate Wilson intervals are reported separately~\cite{wilson1927probable}. Protocols identify when controls were frozen, but the study was not externally preregistered, and adaptively inspected development remains exploratory.

\subsection{RQ2: Target Construction and Locality}

\noindent\textbf{Matched targets.} Table~\ref{tab:targets}는 현재 입력과 학습 예제 수를 고정한 채 target만 바꾼다. Progress에서 Answer를 뺀 RR은 Seen에서 -19.2 포인트 [-22.96, -15.54], Unseen에서 -11.2 [-17.37, -4.88]이며, 정확 McNemar \(p=7.85\times10^{-34}\)와 \(p=6.17\times10^{-5}\)이다. 따라서 정본 terminal 데이터셋의 이점을 학습 레코드가 더 많다는 사실만으로 돌릴 수는 없다. 다만 짝지은 모집단은 target이 서로 다른 source로 제한되고 Progress target 자체가 accepted일 수도 있으므로, 개입은 보존 증거 기반 target 규칙이며 틀린 target과 맞는 target 사이의 깔끔한 대비가 아니다. 반환된 프로그램은 제출물을 완성하지 않고도 앞으로 옮길 수 있다. 맞춘 입력에서 Progress 규칙은 Seen 입력의 34.0\%를 수리하고 43.4\%를 개선하므로, 추가 9.4 포인트는 통과까지 가지 못한 채 전진한 프로그램을 받는데, Answer 규칙의 같은 두 값은 53.2\%와 65.0\%다. 같은 두 간격은 Unseen에서 6.4와 7.6 포인트, Java에서 9.4 대 2.2 포인트이며, Java에서는 Answer target이 이미 85.6\%를 바로 수리한다. 따라서 Progress 규칙이 내준 coverage의 일부는 부분적 전진으로 돌아오지만, 이는 테스트 실행으로 센 것이고 이해도로 센 것이 아니다.
% \noindent\textbf{Matched targets.} Table~\ref{tab:targets} changes the target while holding current inputs and training counts fixed. A returned program can move a submission forward without finishing it. Part of the coverage the Progress rule gives up therefore returns as partial progress, counted by test execution and not by comprehension.

\subsection{RQ3: Component Efficacy}
\noindent\textbf{Fixed candidate breadth.} 성공 지시자 \(a_{ij}\)를 갖는 저장된 draw 세 개에 대해, 입력 \(i\)에서 균일하게 고른 단일 draw의 기대 성공은 \(\frac{1}{3}\sum_j a_{ij}\)이고, 세 draw의 합집합은 \(\max_j a_{ij}=1\)일 때 성공한다. 두 값의 짝지은 차이는 동일한 후보 집합 안에서 추가 기회만을 분리한다. greedy decoding을 단일 stochastic draw로 바꾸면 7.6 포인트 [-9.81, -5.41]를 잃지만, 동일한 고정 draw 세 개를 실행으로 선택하면 Seen에서 15.1 포인트 [13.48, 16.76]를 얻는다. 이는 저장된 실행에 대한 기술적 분해이며, portfolio를 adapter 하나와만 비교하면 그 학습 신호의 증거가 과장되는 이유를 보여 준다.
% \noindent\textbf{Fixed candidate breadth.} For three stored draws with success indicators \(a_{ij}\), the expected uniformly selected one-draw success for input \(i\) is \(\frac{1}{3}\sum_j a_{ij}\), whereas the three-draw union succeeds when \(\max_j a_{ij}=1\). Their paired difference isolates additional opportunities within the identical candidate set. Replacing greedy decoding by one stochastic draw costs 7.6 points [-9.81, -5.41], whereas execution-selecting three of those identical fixed draws contributes 15.1 points [13.48, 16.76] on Seen. This is a descriptive decomposition of stored executions, and it shows why comparing a portfolio only with one adapter overstates the evidence for its training signal.

temperature sweep은 대표 수치에 유리한 조건만 고르지 않고 선언된 모든 조건을 보존한다. \(T=1.0\)까지 단일 draw 비율은 Seen에서 41.1--43.1\% 범위에 머물고, 세 draw 합집합은 60.0/75.2\%에 이르며, \(T=1.5\)에서 decoder는 15.8/35.2\%로 붕괴한다. \(T=0.8\)에서의 별도 20-draw 스트림은 Seen 74.8\%와 Unseen 84.0\%에 도달하며 early stopping 하에서 평균 7.44회와 5.08회를 호출한다. 이 더 높은 비율들은 다른 생성 예산을 쓰므로 3회 호출 기본 결과를 대체하지 않는다. 미세조정도 중요하다: 맞춘 base model의 세 draw 합집합은 30.4/65.6\%에 그쳐, 적응이 Seen에서 27.2 포인트 [22.99, 31.41], Unseen에서 6.4 포인트 [1.19, 11.34]를 더한다. 따라서 폭만으로 base model 대비 개선 전체가 설명되지는 않는다.
% The temperature sweep retains all declared conditions instead of selecting the best one for the headline. Through \(T=1.0\) the one-draw rate stays within 41.1--43.1\% on Seen, the three-draw union reaches 60.0/75.2\%, and at \(T=1.5\) the decoder collapses to 15.8/35.2\%. A separate 20-draw stream at \(T=0.8\) reaches 74.8\% Seen and 84.0\% Unseen, using on average 7.44 and 5.08 calls under early stopping. Those higher rates spend a different generation budget and do not replace the three-call primary results. Fine-tuning also matters: the matched base-model three-draw union reaches only 30.4/65.6\%, so adaptation adds 27.2 points [22.99, 31.41] on Seen and 6.4 points [1.19, 11.34] on Unseen. Breadth alone therefore does not explain all improvement over the base model.

temperature를 맞춘 조건에서, 한 checkpoint의 draw 세 개를 서로 다른 checkpoint 세 개의 draw 하나씩으로 바꾸면 RR이 Seen에서 -0.1 포인트 [-2.00, 1.80], Unseen에서 2.4 포인트 [-0.41, 5.31] 변한다. 이 구간들은 checkpoint 다양성의 일관된 이점을 확립하지 않는다. 동등성을 보이는 것도 아니다: 불확실성은 실용적으로 의미 있는 이득과 손해를 여전히 허용한다. 결정적 다중 seed 이득이 이 결과와 공존할 수 있는데, 한 checkpoint에서 표집하는 것만으로도 이미 다양성이 공급되기 때문이다.
% At matched temperature, replacing three draws of one checkpoint by one draw from each of three checkpoints changes RR by -0.1 points [-2.00, 1.80] on Seen and 2.4 points [-0.41, 5.31] on Unseen. These intervals do not establish a consistent advantage from checkpoint diversity. They also do not show equivalence: the uncertainty still admits benefits and harms of practical interest. A deterministic multi-seed gain can coexist with this result because sampling from one checkpoint already supplies diversity.

한 추론 스택에서의 current-only factorial이 이 설명을 검정한다. greedy checkpoint 세 개는 하나보다 9.8 [7.85, 11.92]와 10.8 [7.23, 14.64] 포인트를 얻지만, stochastic decoder를 맞추면 서로 다른 checkpoint는 2.1 포인트 [0.00, 4.16]와 1.2 포인트 [-2.93, 5.93]만 더한다. equal-problem Seen 구간은 0을 포함하므로, 반올림된 instance 가중 하한이 견고한 checkpoint 이점을 확립하지는 않는다. 그 스택에서의 절대 Seen/Unseen 비율은 greedy checkpoint 하나 53.1/67.2\%, greedy checkpoint 세 개 62.9/78.0\%, 같은 checkpoint의 stochastic 3개 조합 66.8/79.6\%, 서로 다른 checkpoint의 3개 조합 68.9/80.8\%이며, 과거 스택의 72.0/81.2\%와 대비된다. backend 민감도가 실질적이므로, 배포 권고는 평가된 스택으로 한정되며 backend와 무관한 우월성으로 주장하지 않는다.
% A current-only factorial on one inference stack tests this explanation. Three greedy checkpoints gain 9.8 [7.85, 11.92] and 10.8 [7.23, 14.64] points over one, but under the matched stochastic decoder distinct checkpoints add only 2.1 points [0.00, 4.16] and 1.2 points [-2.93, 5.93]. The equal-problem Seen interval includes zero, so the rounded instance-weighted lower bound does not establish a robust checkpoint benefit. Absolute Seen/Unseen rates on that stack are 53.1/67.2\% for one greedy checkpoint, 62.9/78.0\% for three greedy checkpoints, 66.8/79.6\% for a same-checkpoint stochastic triple, and 68.9/80.8\% for a distinct-checkpoint triple, against 72.0/81.2\% on the historical one. Backend sensitivity is material, and the deployment recommendation is restricted to the evaluated stack rather than asserted as backend-independent superiority.

\noindent\textbf{Serialized history.} 고정된 3개 조합에서 더 앞선 제출들을 제거하면 두 pool 모두 수리가 늘어난다. 그 이득은 Mixed와 Answer에 대해 Seen 8.8/11.1 포인트, Unseen 7.6/6.0 포인트이며 모든 구간이 0을 제외한다. target은 같게 두고 그 맥락만 없앤 재학습은 Holm 보정 후 유의한 차이를 내지 않으며 보정된 최소 \(p\)는 0.313이므로, 직렬화된 이력은 측정된 이점의 일부가 아니고 배포 구성은 current-only prompt를 쓴다.
% \noindent\textbf{Serialized history.} Removing earlier submissions from the frozen triples raises repair for both pools. The gains are 8.8/11.1 Seen points and 7.6/6.0 Unseen points for Mixed/Answer, with all intervals excluding zero. Matched retraining without that context shows no significant difference after Holm correction, with smallest adjusted \(p=0.313\), so serialized history is not part of the measured advantage and the deployed configuration uses current-only prompts.

선택 공간 통제도 이질적 target의 일반적 이점을 확립하지 못한다. Answer-9Choose3은 Mixed와 동일한 9개 checkpoint pool 크기와 84개 부분집합 기회를 받는다. 기본 5-fold cross-fitted mixed에서 terminal을 뺀 대비는 +2.2 포인트 [-0.19, 4.63]이고, cross-fitting을 하지 않은 추정치는 +1.7 [-0.79, 4.29]이다. 이 추정치들은 양수지만 불확실하다. 종합하면 후보 폭과 적응은 각각 측정 가능한 이득을 기여하지만, stochastic decoder를 맞추고 나면 서로 다른 checkpoint는 일관된 이점을 더하지 않으며 직렬화된 history가 필요한 입력이라는 근거도 없다.
% Selection-space controls also fail to establish a general heterogeneous-target benefit. Answer-9Choose3 receives the same nine-checkpoint pool size and 84-subset opportunity as Mixed. The primary five-fold cross-fitted mixed-minus-Answer contrast is +2.2 points [-0.19, 4.63], compared with the non-cross-fitted +1.7 [-0.79, 4.29]. These estimates are positive but uncertain. Overall, candidate breadth and adaptation each contribute measured gains, whereas distinct checkpoints add no consistent advantage once the stochastic decoder is matched and serialized history is not supported as a necessary input.

\subsection{RQ4: Generality}
\label{sec:generality}
\noindent\textbf{Problems and execution suites.} Unseen 안에서 Mixed는 Zero-shot을 12.8 포인트 [6.83, 18.75] 앞서며, 배타적 성공은 45개 대 13개, 정확 McNemar \(p=3.01\times10^{-5}\)이다. 공동 수리 142개 중 122개가 두 방법 모두에서 TED가 정의되며, 그 122개에서 TED를 6.41 [3.43, 9.89] 줄인다. Unseen의 절대 RR이 Seen보다 높은 것은 더 강한 일반화의 증거가 아니다: 두 분할은 trajectory 가용성과 문제 구성이 다르다. Unseen 54개 문제 전부를 수리 전 난이도 공변량 여섯 개로 서로 다른 Seen 문제에 매칭하면 원래 격차가 -4.6 equal-problem 포인트 [-14.18, 5.30]로 바뀐다. 매칭은 측정된 불균형을 줄이지만 관측되지 않은 난이도까지 맞출 수는 없으므로, 우리는 분할 간 원시 차이가 아니라 분할 내 짝지은 대비에 의존한다.
% \noindent\textbf{Problems and execution suites.} Within Unseen, Mixed exceeds Zero-shot by 12.8 points [6.83, 18.75], with 45 versus 13 exclusive successes and exact McNemar \(p=3.01\times10^{-5}\). Among 142 joint repairs, 122 have defined TED for both methods; on those 122 it reduces TED by 6.41 [3.43, 9.89]. The higher absolute Unseen than Seen RR is not evidence of stronger generalization: the partitions differ in trajectory availability and problem composition. Matching all 54 Unseen problems to distinct Seen problems on six pre-repair difficulty covariates changes the raw gap into -4.6 equal-problem points [-14.18, 5.30]. We therefore rely on within-split paired contrasts rather than the raw cross-split difference, since matching cannot balance unobserved difficulty.

보완적인 observed/hidden slice 검사는 기존의 작성된 테스트 묶음을 분할한다. Unseen에서 Mixed와 Answer-9Choose3은 observed slice와 보류 slice를 각각 250개 중 189개와 184개 입력에서 함께 통과한다. observed 묶음 성공 중 조건부 확인율은 192개 중 189개(98.4\%)와 186개 중 184개(98.9\%)이며, 배타적 공동 성공 13개 대 8개로 \(p=0.383\)이다. 다른 seed로 Seen 328개 문제 전체에 같은 절차를 반복하면 확인율은 97.8\%와 97.9\%이지만 공동 성공은 997개 중 452개 대 469개다. 따라서 높은 확인율이 Mixed가 이긴다는 것을 보여 주지는 않는다. 이들은 같은 작성 테스트의 보류 slice이므로, 조건부 백분율이 전체 분모 기준 수리율을 대체해서는 안 된다.
% A complementary observed/hidden-slice check partitions the existing authored suite. On Unseen, Mixed and Answer-9Choose3 jointly pass observed and held-back slices on 189/250 and 184/250 inputs, respectively. Conditional confirmation among observed-suite successes is 189/192 (98.4\%) and 184/186 (98.9\%); 13 versus 8 exclusive joint successes yield \(p=0.383\). Repeating the procedure on all 328 Seen problems with a distinct seed yields 97.8\% and 97.9\% confirmation, but joint success is 452/997 versus 469/997. High confirmation thus does not demonstrate that Mixed wins. These are held-back slices of the same authored tests, so the conditional percentage must not replace the full-denominator repair rate.

\noindent\textbf{Earlier prefixes.} 결국 성공한 trajectory의 실행 가능한 prefix 가운데 Seen 2,770개와 Unseen 674개에서 current-only Answer-3Seed는 RR 69.6\%와 80.1\%에 이른다. 앞·중간·마지막 3분의 1은 Seen에서 70.0\%, 67.6\%, 71.4\%, Unseen에서 82.9\%, 77.3\%, 81.8\%다. 이는 평가를 마지막 실패 제출 너머로 확장하며 단순한 단조 위치 효과를 찾지 못한다. 끝내 acceptance에 이르지 못한 trajectory는 포함하지 않고 한 trajectory에서 나온 여러 prefix는 서로 종속적이므로, 2,770개 prefix 비율은 997개 입력 결과에 더하지 않는다.
% \noindent\textbf{Earlier prefixes.} Across 2,770 Seen and 674 Unseen executable prefixes of eventually successful trajectories, current-only Answer-3Seed reaches 69.6\% and 80.1\% RR. The early, middle, and last thirds reach 70.0\%, 67.6\%, and 71.4\% on Seen and 82.9\%, 77.3\%, and 81.8\% on Unseen. This extends evaluation beyond the last failed submission and finds no simple monotonic position effect. It does not cover trajectories that never reach acceptance and multiple prefixes from one trajectory are dependent, so the 2,770-prefix rate is not added to the 997-input result.

\noindent\textbf{Model scale and classroom data.} 1.5B 파라미터에서도 checkpoint 세 개는 하나보다 13.4 포인트 [11.16, 15.92]를 얻지만, mixed에서 terminal을 뺀 값은 -0.8 [-2.62, 1.07]이다. Seen에서 Mixed는 50.25\%, 9개 checkpoint terminal 통제는 51.05\%에 이른다. 이 더 작은 모델은 복수 기회의 유용성을 재현하지만 제한 없는 mixed-target 이점을 재현하지는 않으며, 이는 한 모델 계열 안의 한 번의 규모 변화이지 모델 계열 전반의 포괄이 아니다.
% \noindent\textbf{Model scale and classroom data.} At 1.5B parameters three checkpoints still gain 13.4 points over one [11.16, 15.92], but mixed-minus-Answer is -0.8 [-2.62, 1.07]. Mixed reaches 50.25\% and the nine-checkpoint Answer control 51.05\% on Seen. This smaller model reproduces the utility of multiple opportunities, not an unrestricted mixed-target advantage, and it is one scale change within a model family rather than broad model-family coverage.

Java portfolio 결과는 RQ2의 직접적인 맞춘 target 재학습과 다르다. Mixed에서 Answer-9Choose3을 뺀 값은 보류된 exercise 네 개에서 양수(3.9 포인트 [2.99, 5.11])이고 보류된 학생에서는 결론을 내릴 수 없다(0.6 [-1.20, 2.59]). 절대 RR은 exercise-held-out trajectory 304개에서 56.25\% 대 52.30\%, student-held-out trajectory 181개에서 83.98\% 대 83.43\%다. exercise 추정치는 cluster 네 개에만 기대고 있다: exercise 하나를 빼고 다시 적합시키면 대비가 3.6과 4.4 포인트 사이에 머물고, 개별 exercise는 2.5에서 5.5 포인트 범위다. 이 민감도 검사는 그 exercise들에서 부호를 보존하지만, cluster 네 개로는 폭넓은 교실 모집단 주장을 뒷받침할 수 없다. 맞춘 target 트레이드오프는 보편적 portfolio 이점보다 모집단 간 뒷받침이 더 분명하다.
% The Java portfolio results differ from RQ2's direct matched-target retraining. Mixed-minus-Answer-9Choose3 is positive on four held-out exercises (3.9 points [2.99, 5.11]) and inconclusive on held-out students (0.6 [-1.20, 2.59]). Absolute RR is 56.25\% versus 52.30\% over 304 exercise-held-out trajectories and 83.98\% versus 83.43\% over 181 student-held-out trajectories. The exercise estimate rests on four clusters only: refitting with one exercise left out keeps the contrast between 3.6 and 4.4 points, and single exercises range from 2.5 to 5.5 points. This sensitivity check preserves the sign on those exercises, but four clusters cannot support a broad classroom-population claim. The matched-target tradeoff has clearer cross-population support than a universal portfolio benefit.

\noindent\textbf{Representation and overlap.} accepted/non-accepted 이진 mining은 세밀한 severity 순서를 없애지만 target 집합도 함께 바꾼다. 재학습은 정본에서 대안을 뺀 방향으로 Progress RR을 Seen에서 +2.3, Unseen에서 -2.8 포인트 변화시킨다. 변화가 균일하지 않다는 점은 이 순서가 무해한 구현 세부가 아님을 보여 준다. Mixed와 Answer-9Choose3에서 반환된 수리가 학습 시점의 accepted 프로그램과 정확히 일치하는 경우는 선택의 0.6\%와 1.3\%이고, 0.90 토큰 유사도 임계값을 넘는 근접 중복은 3.8\%와 5.3\%이며, 같은 문제의 학습 target에 대한 최대 유사도의 중위수는 66.7\%와 68.6\%다. 낮은 정확 복사율이 구조적 재사용, 사전학습 오염, 사용자 수준 중복을 배제하지는 않는다~\cite{allamanis2019adverse}. 종합하면 맞춘 target 트레이드오프는 student-held-out Java에서 재현되고 후보 폭은 더 작은 모델 규모에서도 유용하지만, mixed-target의 제한 없는 우월성은 일관되게 재현되지 않는다.
% \noindent\textbf{Representation and overlap.} Binary accepted/non-accepted mining removes the fine severity ordering but also changes the target set. Retraining changes Progress RR by +2.3 Seen and -2.8 Unseen points in the canonical-minus-alternative direction. The nonuniform changes show that the ordering is not an innocuous implementation detail. For Mixed and Answer-9Choose3, exact matches between a returned repair and a training-time accepted program occur in 0.6\% and 1.3\% of selections, near-duplicates above a 0.90 token-similarity threshold in 3.8\% and 5.3\%, and median maximum similarity to a same-problem training target is 66.7\% and 68.6\%. Low exact-copy rates do not exclude structural reuse, pretraining contamination, or user-level overlap~\cite{allamanis2019adverse}. Overall, the matched-target tradeoff replicates on student-held-out Java and candidate breadth remains useful at a smaller model scale, whereas mixed-target unrestricted superiority does not replicate consistently.

\subsection{Threats to Validity}
(1) 런타임 변동성, 정의되지 않는 source AST, Python 공백이 라벨과 거리에 영향을 준다. 우리는 unknown, 분모, 공백에 민감한 보정을 보존하지만, 해시는 provenance를 확립하되 정확성을 확립하지는 않고, source와 동료 매칭이 모든 target의 의미나 스타일을 같게 만들지도 않는다. (2) acceptance는 의미적 정확성의 증명이 아니며~\cite{smith2015cure}, 같은 묶음에서 떼어낸 slice는 독립적인 명세가 아니고, TED와 retention은 인지 부하나 이후 학습을 측정하지 않는다. CodeNet은 초보자를 식별하거나 숙달을 측정하지 않고, Java는 교실 제출물을 제공하지만 피드백 사용을 관찰하는 개입은 아니며, exercise별·학생별 분해는 어떤 학생이 다른 수리를 받게 되는지를 기술하되 어떤 학생이 이득을 얻는지는 기술하지 않고, Figure~\ref{fig:case}는 추정치를 담지 않는 사후 사례 하나다. 과목 데이터 사용 조건이 학생 제출물의 재배포를 허용하지 않으므로 우리는 CodeNet 프로그램을 보여 준다. (3) 필터링은 짧고 결국 성공하는 Python trajectory를 선호하며 Seen 내 사용자 중복을 허용하고, Java는 과목 맥락 하나와 보류된 exercise 네 개만 더하며, cluster bootstrap과 equal-problem 추정치는 작은 cluster의 불확실성, 다중성, 앞선 결과를 본 뒤 고른 분석의 편향을 없애지 못한다. 이런 구별들이 교육적 해석과 target 품질 해석을 제한한다.
% (1) Runtime variability, undefined source ASTs, and Python whitespace affect labels and distances. We retain unknowns, denominators, and whitespace-sensitive corrections, but hashes establish provenance, not correctness, and source and peer matching do not equate all target semantics or styles. (2) Acceptance is not proof of semantic correctness~\cite{smith2015cure}, same-suite slices are not independent specifications, and TED and retention do not measure cognitive load or subsequent learning. CodeNet does not identify novices or measure mastery, Java supplies classroom submissions rather than an intervention observing feedback use, and the per-exercise and per-student resolution describes which students would receive a different repair, not which students benefit, with Figure~\ref{fig:case} one post-hoc case that carries no estimate. We display a CodeNet program because the course data terms do not permit redistributing student submissions. (3) Filtering favors short, eventually successful Python trajectories and permits Seen user overlap, Java adds one course context and only four held-out exercises, and cluster bootstrap and equal-problem estimates do not eliminate small-cluster uncertainty, multiplicity, or the bias of analyses chosen after earlier results. These distinctions limit educational and target-quality interpretations.

\section{Related Work}
\label{sec:related}
\noindent\textbf{Repair and Generation Budgets.} generate-and-validate 수리는 탐색, 학습된 변환, 언어 모델에 걸쳐 있다~\cite{gazzola2019automatic,monperrus2018automatic,weimer2009automatically,legoues2012genprog}. 탐색 분석~\cite{qi2014strength}과 실행 기반 평가~\cite{haque2023fixeval,chen2021evaluating}는 후보 품질과 노출을 분리한다. 신경망 패치, ensemble, 합성 손상, 실행 정보를 쓰는 자기지도는 서로 다른 학습 신호를 제공하며~\cite{tufano2019empirical,lutellier2020coconut,yasunaga2021break,ye2022selfapr}, zero-shot 연구는 과제 적응 없는 수리를 검토한다~\cite{xia2022less,jiang2023impact}. 독립 ensemble과 가중치 평균은 다양성의 또 다른 개념을 제공한다~\cite{lakshminarayanan2017simple,wortsman2022model}. 우리는 portfolio 수리를 새로 제안하지 않는다. 동일 target seed, 동일한 탐색 공간, 고정된 draw, current-only 통제로 trajectory target만 분리한다.
% \noindent\textbf{Repair and Generation Budgets.} Generate-and-validate repair spans search, learned transformations, and language models~\cite{gazzola2019automatic,monperrus2018automatic,weimer2009automatically,legoues2012genprog}. Search analyses~\cite{qi2014strength} and execution-based evaluation~\cite{haque2023fixeval,chen2021evaluating} separate candidate quality from exposure. Neural patches, ensembles, synthetic corruption, and execution-informed self-supervision provide different training signals~\cite{tufano2019empirical,lutellier2020coconut,yasunaga2021break,ye2022selfapr}; zero-shot studies examine repair without task adaptation~\cite{xia2022less,jiang2023impact}. Independent ensembles and weight averaging supply other notions of diversity~\cite{lakshminarayanan2017simple,wortsman2022model}. We do not introduce portfolio repair; we isolate trajectory targets with same-target seeds, equal search spaces, fixed draws, and current-only controls.

\noindent\textbf{Programming-Assignment Feedback.} 교육용 수리는 군집화, 정렬, 리팩터링으로 올바른 프로그램을 활용하고~\cite{gulwani2018automated,wang2018search,hu2020re}, 관련 표현과 튜터링 시스템은 피드백을 전파하고 힌트를 생성한다~\cite{piech2015embeddings,glassman2015overcode,rivers2017datadriven,price2017isnap}. 언어 모델은 수리, 구문 피드백, 대화, 동료, 반례를 뒷받침한다~\cite{joshi2023repair,zhang2024pydex,phung2023generating,liu2024fastfixer,yang2024cref,zhao2024peer,orvalho2025counterexample}. 과제를 고려한 피드백과 다양화된 피드백은 또 다른 참조 전략을 쓴다~\cite{heo2023referent,choi2021automated,choi2025automated}. LSGen도 시간순으로 틀린 제출과 이후 올바른 제출의 짝을 retrieval용으로 mine하므로~\cite{dai2026learner} trajectory 자체가 우리의 새로움은 아니며, 여기서도 LSGen은 강한 Seen 우위를 유지한다. 다만 LSGen은 이력의 기여를 추가 후보의 기여에서 분리하지 않으므로, 우리가 이력과 후보 예산을 함께 고정하는 이유가 남는다. next-step 힌트 생성기는 안내를 무엇에 맞추는가에서 이 연구와 갈린다. 데이터 기반 힌트는 해답 공간이나 과거 cohort의 경로를 읽고 제출물을 그 위에 투영하므로, 그 공간에서 같은 위치에 있는 두 학생은 각자의 코드가 지금 어떤 테스트를 통과하는지와 무관하게 같은 다음 단계를 받는다~\cite{rivers2017datadriven,price2017isnap,roest2024next}. 우리의 target 규칙은 대신 제출물 자신의 실행 증거를 읽고, 텍스트 힌트가 아니라 완성된 프로그램을 반환하므로, 두 산출물은 서로 다른 척도에서 측정된다~\cite{yi2017feasibility,koutcheme2024benchmarking,keuning2018systematic}. 우리의 더 좁은 개입은 맞춘 source에 대해 target을 교체하여 coverage--locality 트레이드오프를 드러내며, 피드백 전략 전반에 대한 우월성을 드러내는 것이 아니다.
% \noindent\textbf{Programming-Assignment Feedback.} Educational repair exploits correct programs through clustering, alignment, and refactoring~\cite{gulwani2018automated,wang2018search,hu2020re}; related representations and tutoring systems propagate feedback and generate hints~\cite{piech2015embeddings,glassman2015overcode,rivers2017datadriven,price2017isnap}. Language models support repair, syntax feedback, conversations, peers, and counterexamples~\cite{joshi2023repair,zhang2024pydex,phung2023generating,liu2024fastfixer,yang2024cref,zhao2024peer,orvalho2025counterexample}. Assignment-aware and diversified feedback use further reference strategies~\cite{heo2023referent,choi2021automated,choi2025automated}. LSGen also mines chronological wrong-to-later-correct submission pairs for retrieval~\cite{dai2026learner}, so trajectories are not our novelty, and it retains its strong Seen advantage here. It does not separate the history's contribution from that of extra candidates, however, which is why we hold the history and the candidate budget fixed together. Next-step hint generators differ from this work in what their guidance is fitted to. Data-driven hints read a solution space or a past cohort's paths and project the submission onto it, so two students at the same position in that space receive the same next step independently of which tests their own code currently passes~\cite{rivers2017datadriven,price2017isnap,roest2024next}. Our target rule reads the submission's own execution evidence instead and returns a complete program rather than a textual hint, so the two kinds of output are measured on different scales~\cite{yi2017feasibility,koutcheme2024benchmarking,keuning2018systematic}. Our narrower intervention replaces the target for matched sources and exposes a coverage--locality tradeoff, not dominance over feedback strategies.

\noindent\textbf{History and Learner Evidence.} ZPD와 scaffolding은 지원받는 수행에 관한 것이며 프로그램 edit distance에 관한 것이 아니다~\cite{cole1978mind,murray2002toward,chounta2017grey,schulze2024beyond}. knowledge tracing은 상호작용에서 숙련도를 모형화하고~\cite{corbett1994knowledge,piech2015deep,ghosh2020context}, TIKTOC은 testcase 증거를 포함한다~\cite{duan2024tiktoc}. next-step 힌트, 피드백 사다리, 초보자 반응 연구는 안내를 더 직접적으로 검토하며~\cite{roest2024next,heickal2024generating,xiao2024exploring}, 피드백 이론은 그 해석과 사용을 강조한다~\cite{narciss2008feedback,hattie2007power,shute2008focus,aleven2000limitations}. 이 논문은 학습자의 직렬화된 history를 조건으로 쓰면 생성된 수리가 개선된다고 주장하지 않는다. 배포 구성은 현재 제출물만으로 prompt를 구성하며, 그 선택의 근거가 된 맞춘 재학습과 prompt 통제는 부정적 결과를 포함해 보충자료에 보고한다.
% \noindent\textbf{History and Learner Evidence.} ZPD and scaffolding concern supported performance, not program edit distance~\cite{cole1978mind,murray2002toward,chounta2017grey,schulze2024beyond}. Knowledge tracing models proficiency from interactions~\cite{corbett1994knowledge,piech2015deep,ghosh2020context}; TIKTOC incorporates testcase evidence~\cite{duan2024tiktoc}. Next-step hints, feedback ladders, and novice-response studies examine guidance more directly~\cite{roest2024next,heickal2024generating,xiao2024exploring}, while feedback theory emphasizes its interpretation and use~\cite{narciss2008feedback,hattie2007power,shute2008focus,aleven2000limitations}. This paper does not claim that conditioning on a learner's serialized history improves generated repairs. Our deployed configuration prompts with the current submission alone, and the supplement reports the matched retraining and prompt controls behind that choice, including their negative outcomes.

\section{Conclusion}
\label{sec:conclusion}
자동 프로그램 수리는 버기 학생 제출의 수리율을 크게 높여 왔다. 그러나 기존 기법은 반환물이 무엇을 향할지를 학생 자신의 시도와 무관하게 정하므로, 반환물이 제출물의 대부분을 대체할 수 있다. 이 논문의 목표는 학생 자신의 trajectory에서 가져온 한 걸음을 향해 버기 제출을 수리하고, 그 이득을 target의 것으로 읽을 수 있게 만드는 것이다. 이를 위해 \textsc{ZPDPatch}는 실행 증거에서 supervision 짝을 mine하고, 규칙마다 adapter를 독립적으로 학습하며, 실행된 validation 수리로 portfolio를 고정한다. 맞춘 Python 실험과 student-held-out Java 실험은 같은 coverage--locality 트레이드오프를 보이고 그것이 exercise와 학생에 걸쳐 균일하지 않음을 보이며, 후보 폭과 모델 적응과 맞춘 동료 target이 남은 개선의 측정 가능한 부분을 설명하므로 보존 증거 기반 target이 개인에게 고유한 supervision은 아니다. 그래서 우리는 current-only Answer 3개 조합을 유지하고 Progress 규칙은 locality가 제약일 때의 선택지로 보고하며, 교육적 이득과 더 넓은 모델 계열에 대한 일반성은 측정되지 않은 채로 남는다.
% Automated Program Repair has substantially raised the repair rate for buggy student submissions. However, existing techniques settle what a return aims at without reference to the student's own attempts, so a return can replace most of the submission. This paper aims to repair a buggy submission toward a step taken from the student's own trajectory, and to make the gain readable as the target's. To this end, \textsc{ZPDPatch} mines supervision pairs from execution evidence, trains one adapter per rule, and freezes a portfolio by executed validation repairs. Matched Python and student-held-out Java experiments show the same coverage--locality tradeoff, uneven across exercises and students, and candidate breadth, model adaptation, and matched peer targets account for the measurable part of the remaining improvement, so the retained-evidence target is not uniquely personal supervision. We therefore retain the current-only Answer triple and report the Progress rule as the option for when locality binds, while educational benefit and broader model-family generality remain unmeasured.
