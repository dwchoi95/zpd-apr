\begin{abstract}
실패한 연습문제 제출에 대한 자동 수리는 패치이기만 한 것이 아니라 피드백 산출물이다. 학생은 자기 코드 옆에서 그것을 읽으므로, 한 토큰만 고친 수정과 전면 재작성은 둘 다 테스트를 통과하더라도 서로 다른 사건이다. 학생이 받게 되는 것은 수리 모델이 어떤 target을 향해 학습되었는지에 달려 있고, 제출 이력은 accepted solution을 대신할 대안을 제공한다. 그러나 이력을 쓰는 시스템은 후보를 더 많이 생성하기만 해도 좋아질 수 있고 target 규칙을 바꾸면 학습 모집단도 함께 바뀌므로, trajectory 특유의 이득을 말하려면 target 구성과 입력 이력, 후보 폭을 각각 따로 통제해야 한다. 우리는 \textsc{ZPDPatch}를 제시한다. 이것은 세 가지 실행 증거 관계를 mine하고, adapter를 독립적으로 학습하며, 회귀 대신 제출물을 그대로 반환하는 gate 뒤에서 validation으로 고정된 portfolio를 선택한다. 181개 student-held-out CS1 Java trajectory에서 source와 개수를 맞춘 학습 하에 terminal target은 155개를, progress target은 92개를 수리한다. 이 결손은 균일하지 않고 집중되어 있어 17개 exercise 중 15개에서 terminal이 앞서며 한 exercise에서는 최대 12개를 더 수리한다. 두 규칙이 모두 수리한 90개 trajectory에서 progress 규칙의 retention 이득은 학생의 63.3\%에서 정확히 0이고, 31.1\%에서 양, 5.6\%에서 음이다. 997개 Seen과 250개 problem-held-out Python 입력으로 이루어진 더 큰 online-judge 코퍼스도 같은 트레이드오프를 재현하며, coverage는 19.2와 11.2 퍼센트포인트 낮고 보존된 source token은 5.6과 6.5 포인트 많다. 고정된 후보 draw 세 번만으로도 Seen에서 15.1 포인트가 더해지며, 완료된 history 특화 변형 가운데 고정된 채택 기준을 만족한 것은 없으므로 우리는 current-only terminal portfolio를 유지한다. 우리가 보고하는 것은 피드백의 성질이며 학습에 미치는 효과가 아니다.
% An automated repair of a failing exercise submission is not only a patch but a feedback artifact. The student reads it beside their own code, so a one-token fix and a full rewrite are different events even when both pass the tests. What the student receives depends on the target the repair model was trained toward, and submission histories offer an alternative to the accepted solution. However, a history-aware system can improve simply by generating more candidates, and changing its target rule also changes its training population, so a trajectory-specific benefit needs separate controls for target construction, input history, and candidate breadth. We present \textsc{ZPDPatch}, which mines three execution-evidence relations, trains independent adapters, and selects a validation-frozen portfolio behind a gate that returns the submission unchanged rather than a regression. On 181 student-held-out CS1 Java trajectories under source- and count-matched training, terminal targets repair 155 and progress targets 92; the deficit is concentrated rather than uniform, with terminal targets ahead on 15 of 17 exercises and up to 12 additional repairs on one exercise. On the 90 trajectories both rules repair, the progress rule's retention advantage is zero for 63.3\% of students, positive for 31.1\%, and negative for 5.6\%. A larger online-judge corpus of 997 Seen and 250 problem-held-out Python inputs reproduces the tradeoff, with 19.2 and 11.2 percentage points less coverage and 5.6 and 6.5 points more retained source tokens. Three fixed candidate draws alone add 15.1 Seen points, and no completed history-specific variant satisfies its fixed adoption criteria, so we retain the current-only terminal portfolio. We report properties of the feedback, not its effect on learning.
\end{abstract}

\section{Introduction}
\label{sec:introduction}
자동 프로그램 수리(APR)는 generate-and-validate 순환을 따르며, 버기 프로그램에 변경을 생성하고 실행 가능한 명세를 통과하는 것을 택한다~\cite{gazzola2019automatic,monperrus2018automatic,weimer2009automatically,legoues2012genprog}. 프로그래밍 과목에서 그런 수리는 피드백이고, 학생은 판정만이 아니라 자기 제출물에 특정된 코드를 받는다~\cite{keuning2018systematic,joshi2023repair,zhang2024pydex}. 학생은 그것을 자신이 제출한 코드 옆에서 읽으며, 피드백은 학생이 행동으로 옮길 수 있을 때에만 그의 행동을 바꾼다~\cite{narciss2008feedback,shute2008focus}. 그러나 테스트를 통과한다는 사실은 수리가 제출물을 얼마나 대체하는지에 대해 아무것도 말해 주지 않는다. 한 토큰 수정과 선택한 접근을 버리는 재작성은 둘 다 모든 테스트를 통과해도 서로 다른 피드백이다. 같은 trajectory의 더 앞선 제출들은 시도된 전략, 반복된 오류, 이미 통과한 테스트를 기록하므로, 수리 모델은 그것들을 읽기만 하는 것이 아니라 그것들로부터 학습할 수도 있다. 수리가 현재 코드만이 아니라 그 trajectory에 의존해야 하는가? 그 선택은 학생이 받는 것을 어떻게 바꾸는가?
% Automated Program Repair (APR) follows a generate-and-validate loop, generating changes to a buggy program and keeping one that passes an executable specification~\cite{gazzola2019automatic,monperrus2018automatic,weimer2009automatically,legoues2012genprog}. In a programming course such a repair is feedback, and the student receives code specific to their own submission rather than only a verdict~\cite{keuning2018systematic,joshi2023repair,zhang2024pydex}. A student reads it beside the submission it replaces, and feedback changes what a student does only if it can be acted on~\cite{narciss2008feedback,shute2008focus}. Passing the tests, however, says nothing about how much of the submission the repair replaces. A one-token fix and a rewrite that discards the chosen approach are different feedback even when both pass every test. Earlier submissions in the same trajectory record attempted strategies, repeated errors, and tests already passed, so a repair model can learn from them and not only read them. Should a repair depend on that trajectory, rather than on the current code alone? What does that choice change in what a student receives?

기존 방법들은 올바른 동료 프로그램을 군집화·정렬·정규화하거나~\cite{gulwani2018automated,wang2018search,hu2020re}, 언어 모델로 수리를 생성·진단하거나~\cite{joshi2023repair,zhang2024pydex,liu2024fastfixer,yang2024cref,orvalho2025counterexample}, 학습자별 해답을 retrieval해 생성을 안내한다~\cite{dai2026learner}. 컴퓨팅 교육 쪽의 또 다른 계열은 해답 공간 위로 피드백을 전파하고 과거 학습자 데이터에서 next-step 힌트를 끌어낸다~\cite{piech2015embeddings,rivers2017datadriven,price2017isnap,roest2024next}. 이들은 강력한 대안이며, retrieval 기반 LSGen은 우리 Seen 입력의 80.2\%를 수리한다(Section~\ref{sec:experiment}). 그럼에도 그 성공은 더 앞선 제출들이 현재 코드와 적응, 추가 생성 기회를 넘어서는 정보를 더한다는 것을 입증하지는 않는다.
% Existing methods cluster, align, or normalize correct peer programs~\cite{gulwani2018automated,wang2018search,hu2020re}, generate and diagnose repairs with language models~\cite{joshi2023repair,zhang2024pydex,liu2024fastfixer,yang2024cref,orvalho2025counterexample}, or retrieve a learner-specific solution to guide generation~\cite{dai2026learner}. A parallel line in computing education propagates feedback over solution spaces and derives next-step hints from past learner data~\cite{piech2015embeddings,rivers2017datadriven,price2017isnap,roest2024next}. These are strong alternatives, and retrieval-based LSGen repairs 80.2\% of our Seen inputs (Section~\ref{sec:experiment}). Their success nevertheless does not establish that earlier submissions add information beyond current code, adaptation, and additional generation opportunities.

우리는 \emph{trajectory-conditioned repair}를 현재 제출에 이르는 순서열에 그 supervision이나 생성된 변경이 의존하는 수리로 정의한다. 두 사용자가 서로 다른 실패 수정들을 거쳐 비슷한 코드에 도달할 수 있고, 이는 서로 다른 다음 변경을 시사한다. 근접발달영역(ZPD)은 선행 활동에 근거한 지원을 뒷받침한다~\cite{cole1978mind,murray2002toward,chounta2017grey,schulze2024beyond}. 우리가 검정하는 가설은 더 좁고 서로 분리된 두 개다. 첫째, 학생 자신의 이후 제출에서 mine한 target은 accepted solution보다 제출물을 더 많이 보존해야 한다. 둘째, 실제 이력은 current-code, shuffled-history, 타인 이력 통제군보다 실행 기준으로 측정한 수리를 개선해야 하며, 회귀나 미해결 결과를 늘리지 않아야 한다. Section~\ref{sec:limitation}은 하나의 비교로 둘을 함께 검정할 수 없는 이유를 보인다. 관측된 순서열은 숙달을 측정하지 않으며, 더 작은 패치가 학습을 입증하지도 않는다.
% We define \emph{trajectory-conditioned repair} as repair whose supervision or generated change depends on the sequence leading to the current submission. Two users may reach similar code after different failed revisions, suggesting different next changes. The Zone of Proximal Development (ZPD) motivates support informed by prior activity~\cite{cole1978mind,murray2002toward,chounta2017grey,schulze2024beyond}. Our testable hypotheses are narrower and separate. First, a target mined from a student's own later submissions should preserve more of the submission than the accepted solution does. Second, authentic history should improve executed repair over current-code, shuffled-history, and other-user controls without increasing regressions or unresolved outcomes. Section~\ref{sec:limitation} shows why one comparison cannot test both. An observed sequence does not measure mastery, and a smaller patch does not establish learning.

trajectory의 두 번째 용도는 학습 target을 바꾸는 것인데, 이후의 개선 상태가 최종 accepted solution을 대신할 수 있기 때문이다. 우리의 terminal 규칙은 예제 40,454개를, progress 규칙은 21,416개를 내므로 예제 수와 실패 source의 분포가 target과 함께 움직인다. 후보 폭 또한 중요한데, 고정된 stochastic draw 세 번은 기대되는 단일 draw보다 Seen repair rate를 15.1 포인트 올린다. 따라서 terminal adapter 하나에 대한 이득만으로는 trajectory에서 끌어낸 target이나 실제 이력의 효과를 분리할 수 없다. 우리는 source를 맞춘 재학습, 동일 target 독립 seed, 맞춘 후보 예산을 써서 이 설명들을 구분한다.
% A second use of a trajectory changes the training target, because later improvements can replace the eventual accepted solution. Our terminal rule emits 40,454 examples and the progress rule 21,416, so the example count and the distribution of failing sources move with the target. Candidate breadth also matters, since three fixed stochastic draws add 15.1 Seen repair-rate points over the expected single draw. A gain over one terminal adapter therefore cannot isolate trajectory-derived targets or authentic history. We use source-matched retraining, same-target independent seeds, and matched candidate budgets to distinguish these explanations.

우리는 \textsc{ZPDPatch}를 제시한다. \emph{Mine}은 terminal, strict-verdict, test-progress 관계를 구성하고, \emph{Train}은 adapter를 독립적으로 적합시키며, \emph{Select}는 validation으로 고른 checkpoint 3개 조합을 고정한다. 실행 gate는 수리를 반환하거나 버기 프로그램을 유지하며 선택적으로 edit budget 안에서 동작하므로, 과목은 반환된 수리가 제출물을 얼마나 대체할 수 있는지를 제한할 수 있고 관측된 통과율을 낮추는 수리는 결코 받지 않는다. 별도의 통제군들은 target을 맞춘 동료 프로그램으로 교체하고, 이력을 제거하거나 교란하며, draw를 고정한다.
% We present \textsc{ZPDPatch}. \emph{Mine} constructs terminal, strict-verdict, and test-progress relations, \emph{Train} fits independent adapters, and \emph{Select} freezes a validation-selected checkpoint triple. An execution gate returns a repair or retains the buggy program, optionally within an edit budget, so a course can bound how much of a submission a returned repair may replace and never receive one that lowers the observed pass rate. Separate controls replace targets with matched peer programs, remove or perturb histories, and hold draws fixed.

997개 Seen과 250개 problem-held-out Python 입력에서, 맞춘 조건의 terminal target은 19.2와 11.2 포인트 더 많은 입력을 수리하고, progress target은 공동 수리에서 source token retention을 5.6과 6.5 퍼센트포인트 높인다. student-disjoint CS1 Java 재학습은 두 방향 모두를 재현하며, 이를 exercise별·학생별로 분해하면 트레이드오프가 균일하지 않음이 드러난다. terminal target이 17개 exercise 중 15개에서 앞서는 한편, retention 이득은 두 규칙에서 모두 수리를 받은 학생의 31.1\%에만 도달한다. 한편 우리의 관계 혼합 portfolio는 61.5\%/74.8\%로, 현재 제출물만 보는 terminal-target 3개 조합의 72.0\%/81.2\%보다 낮다. 각 실행 전에 고정한 기준으로 판정한 후속 개발 프로그램(Section~\ref{sec:development})은 일반적인 실행 기반 선택은 개선했지만, 그 이득을 실제 이력으로 설명할 수 있는 구성은 내지 못했다. 우리는 기존 버전을 유지한다. 증거가 뒷받침하는 것은 제안했던 history 특유의 이점이 아니라 target이 유발하는 coverage--locality 트레이드오프이기 때문이다.
% On 997 Seen and 250 problem-held-out Python inputs, matched terminal targets repair 19.2 and 11.2 points more inputs, while progress targets increase source-token retention by 5.6 and 6.5 percentage points on joint repairs. Student-disjoint CS1 Java retraining reproduces both directions, and resolving it per exercise and per student shows an uneven tradeoff, with terminal targets leading on 15 of 17 exercises while the retention advantage reaches only 31.1\% of the students who receive a repair from both rules. However, our mixed-relation portfolio reaches 61.5\%/74.8\%, below the 72.0\%/81.2\% of a terminal-target triple that sees only the current submission. A further development program, judged by criteria fixed before each run (Section~\ref{sec:development}), improves generic execution-based selection but produces no configuration whose gain authentic history explains. We retain the existing version, because the evidence supports a target-induced coverage--locality tradeoff rather than the proposed history-specific advantage.

\section{Preliminaries}
\label{sec:preliminaries}
\subsection{Submissions and Execution Evidence}

\begin{figure}[h]
\small
\begin{algorithmic}[1]
\Require Current code $c$, context $x$, ordered generators $S$, tests $\mathcal E$, edit budget $B$
\Ensure Returned program $c^*$
\State $c^*\gets c$; $q^*\gets\textsc{Execute}(c,\mathcal E)$
\For{$v\in S$}
 \State $z\gets\textsc{Generate}(v,x)$
 \If{$B<\infty$ and $\mathrm{ted}^{\dagger}(c,z)>B$}
  \State \textbf{continue}
 \EndIf
 \State $q\gets\textsc{Execute}(z,\mathcal E)$
 \If{$q=1$} \State \Return $z$ \EndIf
 \If{$(q,-\mathrm{ted}^{\dagger}(c,z))>(q^*,-\mathrm{ted}^{\dagger}(c,c^*))$}
  \State $c^*\gets z$; $q^*\gets q$
 \EndIf
\EndFor
\State \Return $c^*$
\end{algorithmic}
\caption{Execution-gated repair procedure.}
\label{alg:generic}
\end{figure}
\label{sec:formulation}
문제 \(p\)에 대해 제출 상태는 튜플 \(s=(c,v,o)\)이며, 여기서 \(c\)는 완전한 소스 코드, \(v\)는 기록된 online-judge 판정, \(o\)는 사용 가능한 각 testcase 식별자를 재실행 결과로 대응시킨다. 문제 맥락 \(d_p\)는 문제 설명과 자원 제한을 담고, \(\mathcal E_p\)는 사용 가능한 테스트 묶음이다. trajectory \(\tau=[s_1,\ldots,s_n]\)은 한 사용자가 한 문제에 제출한 것들을 순서대로 놓는다. 정본 데이터셋은 각 trajectory를 처음 기록된 acceptance에서 끊는다. 이 끝점은 보존된 trajectory 내의 마지막 accepted 제출이며, acceptance 이후의 수정이 아니다. 기록된 판정과 재실행 결과는 별도 필드로 남는데, 런타임 버전과 실행 변동성이 프로그램의 관측된 거동을 바꿀 수 있기 때문이다.
% For a problem \(p\), a submission state is a tuple \(s=(c,v,o)\), where \(c\) represents complete source code, \(v\) denotes the recorded online-judge verdict, and \(o\) maps each available testcase identifier to its re-executed outcome. The problem context \(d_p\) contains the statement and resource limits, and \(\mathcal E_p\) is the available test suite. A trajectory \(\tau=[s_1,\ldots,s_n]\) orders submissions by one user on one problem. The canonical dataset ends each trajectory at its first recorded acceptance; this endpoint is the final accepted submission within the retained trajectory, not a later post-acceptance revision. Recorded verdicts and replayed outcomes remain distinct fields, because runtime versions and execution variability can change a program's observed behavior.

학습 예제는 입력 \(x=(d_p,h_i)\)와 이후 코드 \(y\)를 짝지으며, \(h_i\)는 현재 상태에서 끝나는 허용된 제출 prefix다. target constructor는 보존되는 prefix와 그 target을 함께 결정한다. 추론 시 현재 프로그램은 항상 주어지며, history-conditioned prompt는 관측된 더 앞선 제출들도 포함하지만 current-only prompt는 포함하지 않는다. 미래의 accepted 프로그램은 학습 target이거나 오프라인 평가 기준일 뿐, 추론 prompt의 일부가 되는 일은 없다. \emph{terminal target}은 Accepted(AC) 끝점이다. \emph{progress target}은 실행 증거 규칙에 따라 보존된 다음 상태이며 그 자체가 accepted일 수도 있다. \emph{intermediate target}은 보존된 비종단 상태를 가리키는 용어로 남겨 두며, Progress 데이터셋이 그런 상태로만 제한되는 것은 아니다.
% A training example pairs input \(x=(d_p,h_i)\) with later code \(y\), where \(h_i\) is the permitted submission prefix ending at the current state. A target constructor determines both the retained prefix and its target. At inference, the current program is always available; a history-conditioned prompt also includes earlier observed submissions, whereas a current-only prompt does not. The future accepted program is a training target or an offline assessment reference, never part of the inference prompt. A \emph{terminal target} is the Accepted (AC) endpoint. A \emph{progress target} is the next retained state under an execution-evidence rule and can itself be accepted. We reserve \emph{intermediate target} for a retained nonterminal state; the Progress dataset is not restricted to such states.

\subsection{Generate-and-Validate Selection}

Figure~\ref{alg:generic}은 공통 controller를 규정한다: 버기 프로그램이 fallback이고, 각 generator는 완전한 후보 하나를 내며 유한한 edit budget이 그 후보를 배제할 수 있고, 실행은 후보를 즉시 받아들이거나 가장 좋은 부분 수리를 유지한다. 여기서 \(q\)는 통과한 테스트의 비율이고, \(\mathrm{ted}^{\dagger}\)는 변경된 두 프로그램이 모두 파싱될 때의 추상 구문 트리(AST) edit distance이며, 코드가 바뀌지 않았으면 0, 그 밖에는 무한이다. 제한 없는 budget은 거리 검사를 건너뛰어 구문 오류 수리를 허용하고, 유한한 budget은 source 거리가 정의되지 않는 변경을 거부한다.
% Figure~\ref{alg:generic} specifies the common controller: the buggy program is the fallback, each generator emits one complete candidate that a finite edit budget can exclude, and execution either accepts a candidate immediately or keeps the best partial repair. Here \(q\) is the fraction of tests passed, and \(\mathrm{ted}^{\dagger}\) is Abstract Syntax Tree (AST) edit distance when both changed programs parse, zero for unchanged code, and infinity otherwise. An unrestricted budget bypasses the distance check, allowing syntax repair; a finite budget rejects changes whose source distance is undefined.

이 controller는 generator 구성, 입력 맥락, 기회 수를 분리한다. reference 기반, 학습 기반, 반복적 수리는 이 선택들을 서로 다르게 구체화한다~\cite{gulwani2018automated,tufano2019empirical,yang2024cref}. 우리의 통제는 특정 구현들을 비교하는 것이며, 선행 방법이 모두 accepted 끝점으로 학습한다는 가정이 아니다.
% The controller separates generator construction, input context, and opportunity count. Reference-based, learned, and iterative repair instantiate these choices differently~\cite{gulwani2018automated,tufano2019empirical,yang2024cref}. Our controls compare specific implementations, not an assumption that all prior methods train on accepted endpoints.

\EndFor

\subsection{Mine}
Mine의 목표는 모든 supervision 짝이 관측된 source와 이후 제출로 추적되도록 만드는 것이다. 제출들은 문제와 사용자로 묶이고, 시간순으로 정렬되며, 첫 acceptance에서 끊긴다. 정본 정규화는 연속 중복을 제거하면서 생성과 실행에 쓰인 소스 코드는 보존한다. 빌더는 history 길이나 전이 수에 상한을 두지 않는다. 대신 whole-trajectory 필터가, 필요한 prompt--target 구성 중 하나라도 4,096 토큰을 넘으면 분할 전에 그 trajectory를 제외한다. 제외는 평가 모집단을 바꾸는 것이며, 프로그램이나 history를 잘라낸 뒤 그 조각을 완전한 것처럼 제시하는 일은 없다.
% The goal of Mine is to make every supervision pair traceable to an observed source and a later submission. Submissions are grouped by problem and user, chronologically ordered, and cut at the first acceptance. Canonical normalization removes consecutive duplicates while preserving the source code used for generation and execution. The builder imposes no maximum history or transition count. A whole-trajectory filter instead excludes a trajectory before splitting if any required prompt--target configuration exceeds 4,096 tokens. Exclusion changes the evaluated population; it never cuts off a program or history and presents the fragment as complete.

거친 severity 함수는 Accepted(AC)에 0, Wrong Answer(WA)에 1, Time 또는 Memory Limit Exceeded(TLE/MLE)에 2, Runtime Error(RE)에 3, Compile Error(CE)에 4를 부여하며, 인식되지 않은 결과와 내부 오류는 가장 심각한 범주에 둔다. 이는 운용상의 순서이며 정확성까지의 의미적 거리가 아니다. Strict는 기록된 판정을 비교한다. Progress는 기록된 판정 문자열이 같을 때 재실행 결과까지 비교한다. 그 캐시는 완전해야 하고, 비교되는 벡터들은 비어 있지 않은 동일한 testcase 키를 가져야 한다. provenance에는 문제, 코드, 테스트, 실행 구성이 포함된다. 이후 개발에서의 인프라 불확실성은 unknown으로 보고하며, 수리에 유리한 라벨로 바꾸지 않는다.
% The coarse severity function assigns 0 to Accepted (AC), 1 to Wrong Answer (WA), 2 to Time or Memory Limit Exceeded (TLE/MLE), 3 to Runtime Error (RE), and 4 to Compile Error (CE); unrecognized and internal outcomes occupy the most severe category. This is an operational ordering, not semantic distance to correctness. Strict compares recorded verdicts. Progress additionally compares replayed outcomes when the recorded verdict strings agree. Its cache must be complete, and compared vectors must have equal, nonempty testcase keys. Provenance includes problem, code, tests, and execution configuration. Infrastructure uncertainty in later development is reported as unknown, not converted into a favorable repair label.

testcase 전체 집합이 같을 때, \(o_t\prec_\times o_r\)는 \(o_t\)의 모든 테스트가 \(o_r\)의 대응 테스트보다 severity가 크지 않고 적어도 하나에서 엄격히 감소할 때 성립한다. 개선 술어는 다음과 같다:
% For equal testcase universes, \(o_t\prec_\times o_r\) holds when every test in \(o_t\) has severity no greater than its counterpart in \(o_r\), with a strict decrease on at least one. The improvement predicates are:
\begin{equation}
\begin{aligned}
\mathsf{Improves}_S(r,t)&\iff \mathrm{sev}(v_t)<\mathrm{sev}(v_r),\\
\mathsf{Improves}_P(r,t)&\iff \mathsf{Improves}_S(r,t)\\
 &\quad\lor\ (v_t=v_r\land o_t\prec_\times o_r).
\end{aligned}
\label{eq:progress}
\end{equation}
직관적으로 Equation~\eqref{eq:progress}는 거친 개선과, 판정이 바뀌지 않아 가려진 progress를 함께 보존한다. RE에서 WA로의 severity 개선이 반드시 통과 비율을 높이지는 않으며, 판정을 개선하는 간선이 테스트 단위 우위를 요구하지도 않는다. mine된 관계는 supervision을 제공하는 것이며 배포 안전성을 보장하지 않는다.
% Intuitively, Equation~\eqref{eq:progress} retains coarse improvements and progress hidden by an unchanged verdict. A severity improvement such as RE to WA need not increase the pass fraction, and a verdict-improving edge does not require test-wise dominance. The mined relation supplies supervision, not a deployment-safety guarantee.

Answer는 AC가 아닌 각 source와 accepted 끝점에 대해 독립적인 짝을 낸다. 따라서 \([s_1,\ldots,s_9]\)는 \(([s_1],c_9),\ldots,([s_8],c_9)\)를 만들며, 누적된 prefix를 Answer 학습에 노출하지 않는다. Strict와 Progress는 \(R=[s_1]\)에서 시작해 이후 각 상태를 \emph{마지막으로 보존된} 상태와 비교하고, 술어가 성립할 때만 덧붙인다. \(s_t\)를 덧붙이기 전에 빌더는 \((R,c_t)\)를 낸다. WA, 개선된 WA, AC의 경우 Strict는 \(([s_1],c_3)\)을 내고 Progress는 \(([s_1],c_2)\)와 \(([s_1,s_2],c_3)\)을 낸다. accepted 끝점은 두 규칙에서 모두 적격으로 남는다. Strict의 쌍별 술어가 Progress의 것에 포함되더라도, 독립적으로 훑어 얻은 간선 집합이 포함 관계일 필요는 없다.
% Answer emits an independent pair for each non-AC source and the accepted endpoint. Thus \([s_1,\ldots,s_9]\) yields \(([s_1],c_9),\ldots,([s_8],c_9)\); it does not expose accumulated prefixes to Answer training. Strict and Progress start with \(R=[s_1]\), compare each later state with the \emph{last retained} state, and append it only when the predicate holds. Before appending \(s_t\), the builder emits \((R,c_t)\). For WA, improved WA, AC, Strict emits \(([s_1],c_3)\), whereas Progress emits \(([s_1],c_2)\) and \(([s_1,s_2],c_3)\). The accepted endpoint remains eligible in both rules. Although Strict's pairwise predicate is contained in Progress's, their independently scanned edge sets need not be nested.

시간순 인덱스는 엄격히 증가하므로 구성은 순환 없이 종료한다. 키가 고정된 증거에서는 보존된 간선이 해당 판정/테스트 severity 순위도 낮춘다. 이는 빌더의 불변식이며, 학습된 ZPD 효과의 증거가 아니다. accepted/non-accepted 이진 mining은 Strict 짝 16,973개 중 14,027개, Progress 짝 21,416개 중 18,009개를 보존한다. 그 라벨로 재학습한 모델은 Seen 수리 결정의 84.6\%와 87.5\%에서 정본 모델과 일치하므로(Section~\ref{sec:generality}), 우리는 이 순서를 보편적인 것이 아니라 운용적인 것으로 읽는다.
% Chronological indices strictly increase, so construction terminates without cycles. With fixed-key evidence, retained edges also decrease the appropriate verdict/test severity rank. These are builder invariants, not evidence of a learned ZPD effect. Binary accepted/non-accepted mining retains 14,027 of 16,973 Strict pairs and 18,009 of 21,416 Progress pairs. Models retrained on them agree with the canonical ones on 84.6\% and 87.5\% of Seen repair decisions (Section~\ref{sec:generality}), so we read the ranking as operational rather than universal.

\subsection{Train}
Train의 목표는 모델과 최적화를 비교 가능하게 유지하면서 각 관계를 독립적으로 학습하는 것이다. 구현은 Qwen2.5-Coder-7B-Instruct를 4-bit 양자화 Low-Rank Adaptation(QLoRA)으로 미세조정한다~\cite{hui2024qwen2,dettmers2023qlora}. adapter는 rank 16, scaling 32, dropout 0.05이며 attention과 feed-forward projection을 대상으로 한다. 정본 학습은 1 epoch, 학습률 \(2\times10^{-4}\), seed 2027--2029를 쓴다. cross-entropy 손실은 assistant target 토큰에서만 계산한다. 역할 중립 prompt는 문제 설명, 제한, 허용된 제출들, 실행/편집 요약, 완전한 해답 요청을 담는다. 규칙 이름도 선호하는 패치 크기도 적지 않으므로, 특화는 명시적 지시가 아니라 데이터에서 나와야 한다.
% The goal of Train is to learn each relation independently while keeping model and optimization comparable. The implementation fine-tunes Qwen2.5-Coder-7B-Instruct with 4-bit Quantized Low-Rank Adaptation (QLoRA)~\cite{hui2024qwen2,dettmers2023qlora}. Adapters have rank 16, scaling 32, and dropout 0.05, targeting attention and feed-forward projections. Canonical training uses one epoch, learning rate \(2\times10^{-4}\), and seeds 2027--2029. Assistant target tokens supply cross-entropy loss. The role-neutral prompt contains the statement, limits, permitted submissions, execution/edit summaries, and a request for a complete solution. It names neither the rule nor a preferred patch size, so specialization must come from the data rather than explicit instructions.

target은 오프라인에서 이용 가능한 미래 제출이며, 추론 입력은 관측된 상태만 담는다. current-only 통제는 위치를 재설정하고 더 앞선 항목을 제거해, 위치 라벨을 통한 길이 누출을 막는다. Answer 학습은 이미 단일 source이므로 추론 시 history를 주면 분포 변화가 생긴다. 반면 history 제거 재학습 통제는 target을 고정하고 더 앞선 제출의 직렬화만 바꾼다. source를 맞춘 target 학습은 현재 입력과 개수를 고정한다. 이 설계들은 서로 다른 질문에 답하므로, history에 관한 하나의 주장으로 합치지 않는다.
% Targets are future submissions available offline; inference inputs contain only observed states. Current-only controls reset positions and remove earlier entries, preventing length leakage through position labels. Answer training is already single-source, so supplying history at inference creates a distribution change. The history-removal retraining control instead holds targets fixed and changes earlier-submission serialization. Source-matched target training holds current input and count fixed. These designs answer different questions and are not pooled into one claim about history.

paired-target 통제는 문제, 사용자, 제출 식별자, 정확히 같은 버기 프로그램으로 레코드를 내부 결합하고, Answer target과 Progress target이 서로 다른 source만 남긴다. 조건마다 학습 7,389개와 validation 931개 예제가 동일한 current-only 입력을 쓴다. 별도의 peer 통제는 같은 문제, 같은 split의 다른 사용자를 요구하며 target의 실행 증거가 정확히 같아야 한다. 같은 사용자의 target을 \(y_u\), 그 동료 교체본을 \(y_v\)라 하면, semantic-token diff 거리 \(d\)에 대해 불일치 \(\delta=|d(c,y_v)-d(c,y_u)|\)가 \(\delta\le2\) 또는 \(\delta/\max(1,d(c,y_u))\le0.1\)을 만족해야 한다. 증거가 희소한 집단을 먼저 방문하며, 동점일 때는 거리 불일치, 재사용, 식별자 순으로 우선하고 donor 재사용은 3회로 제한한다. 이 그리디 규칙은 조건마다 학습 5,231개와 validation 306개 예제를 만든다. 결과가 같고 거리가 가깝다는 것이 구조나 스타일의 동일성을 뜻하지는 않으므로, 측정된 효과는 교체 규칙 전체에 속하며 provenance만 떼어낸 것이 아니다.
% The paired-target control inner-joins records by problem, user, submission identifier, and the exact buggy program, retaining sources with distinct Answer and Progress targets. Its 7,389 training and 931 validation examples per condition use identical current-only inputs. The separate peer control requires another user on the same problem and in the same split, with exactly equal target execution evidence. Writing \(y_u\) for the same-user target and \(y_v\) for its peer replacement, for semantic-token diff distance \(d\) the discrepancy \(\delta=|d(c,y_v)-d(c,y_u)|\) must satisfy \(\delta\le2\) or \(\delta/\max(1,d(c,y_u))\le0.1\). Scarce evidence groups are visited first; ties prioritize distance discrepancy, reuse, and identifier, with donor reuse capped at three. This greedy rule yields 5,231 training and 306 validation examples per condition. Equal outcomes and nearby distances do not equate structure or style, so its measured effect belongs to the entire replacement rule, not isolated provenance.

\subsection{Select}
Select의 목표는 최종 테스트 결과를 보지 않고 고른, 크기가 제한된 portfolio를 배포하는 것이다. validation 입력 \(U\)에 대해 \(R_v^B\)를 checkpoint \(v\)가 edit budget \(B\) 안에서 수리한 입력이라고 하자. 선택은 다음을 최대화한다:
% The goal of Select is to deploy a bounded portfolio chosen without final-test outcomes. For validation inputs \(U\), let \(R_v^B\) be inputs repaired by checkpoint \(v\) within edit budget \(B\). Selection maximizes:
\begin{equation}
 f_B(S)=\frac{1}{|U|}\left|\bigcup_{v\in S} R_v^B\right|,\qquad |S|=3.
\label{eq:portfolio}
\end{equation}
직관적으로 Equation~\eqref{eq:portfolio}는 낮은 학습 손실이나 모든 관계의 포함이 아니라 서로 보완되는 성공을 보상한다. validation은 적격한 461개 문제마다 해시로 고정한 trajectory 하나를 쓴다. mixed pool은 checkpoint 9개와 84개 조합을 갖고, 관계마다 하나씩 요구하면 대신 27개가 된다. 제한 없는 기본 mixed 선택은 Answer2027, Answer2028, Progress2027이다. 관계 제약을 둔 선택은 별개의 조건이다. Answer-9Choose3은 terminal checkpoint 9개와 동일한 84개 조합 탐색을 받는다. 동점은 기록된 pass-rate, improvement, 결정적 식별자 우선순위로 처리한다. budget 지정 선택은 \(B\in\{5,10,20,40,80,160\}\)에서 선언된 목적식을 반복하며, 테스트 결과를 보고 budget을 고르지 않는다.
% Intuitively, Equation~\eqref{eq:portfolio} rewards complementary successes, not low training loss or the presence of every relation. Validation uses one fixed-hash trajectory from each of 461 eligible problems. The mixed pool has nine checkpoints and 84 triples; requiring one checkpoint per relation instead permits 27. The primary unconstrained mixed choice is Answer2027, Answer2028, and Progress2027. The relation-constrained choice is a different condition. Answer-9Choose3 receives nine terminal checkpoints and the same 84-triple search. Ties use recorded pass-rate, improvement, and deterministic identifier priorities. Budget-indexed selection repeats the declared objective at \(B\in\{5,10,20,40,80,160\}\), without choosing a budget from test results.

선택된 checkpoint와 그 순서는 고정된다. 각각은 독립적인 후보를 최대 하나 내며, 처음 관측된 acceptance에서 생성을 멈춘다. 모든 테스트를 통과하는 것이 없으면 Figure~\ref{alg:generic}은 통과 비율을 먼저, 그다음 더 작은 거리를 우선한다. 바뀌지 않은 코드가 항상 가능하므로, 동일한 고정 실행 측정에서는 반환된 통과 비율이 낮아질 수 없고 유한한 edit budget을 넘을 수도 없다. 이는 테스트 단위 비회귀가 아니다: 비율이 같아도 서로 다른 테스트에서의 이득과 손실이 가려질 수 있다. 또한 새로운 실행, 보지 못한 테스트 묶음, 자원 변동성 하에서의 비회귀를 보장하지도 않는다. 개발 과정은 이런 더 강한 실패 양상을 명시적으로 측정한다.
% Selected checkpoints and order are frozen. Each emits at most one independent candidate, and the first observed acceptance stops generation. If none passes all tests, Figure~\ref{alg:generic} prioritizes pass fraction and then smaller distance. Because unchanged code is feasible, for the same fixed execution measurements the returned pass fraction cannot decrease, and a finite edit budget cannot be exceeded. This is not per-test non-regression: equal fractions can conceal gains and losses on different tests. It also does not guarantee non-regression under fresh execution, an unseen suite, or resource variability. Development explicitly measures these stronger failure modes.

후보가 고정되고 독립적이면, 순서는 호출 수와 패치의 정체를 바꾸지만 적격한 acceptance의 존재 여부는 바꾸지 않는다. 저장된 후보는 선택을 정확히 재생할 수 있게 하지만 생성 품질을 보장하지는 않는다. terminal 짝짓기는 trajectory 길이에 선형이며, \(n\)개 제출을 \(m\)개 테스트로 재실행하려면 \(O(nm)\)의 실행과 증거 저장이 필요하다. 84개 조합 탐색은 우리 pool 크기에서 한정된 것이며, 임의 크기 pool로 확장되는 최적화기가 아니다.
% For fixed independent candidates, order changes calls and patch identity but not the existence of an eligible acceptance. Stored candidates permit exact selection replay, not a guarantee of generation quality. Terminal pairing is linear in trajectory length; replaying \(n\) submissions on \(m\) tests requires \(O(nm)\) executions and evidence storage. The 84-triple search is bounded at our pool size, not a scalable optimizer for arbitrary pools.

% \noindent\textbf{Other settings.} Training and generation use one NVIDIA RTX 5090. Repair Rate(RR)는 반환된 프로그램이 모든 테스트를 통과한 적격 입력의 비율이다. Pass Rate(PR)는 통과 테스트 비율의 평균이고, Improvement Rate(IR)는 그 비율이 증가한 경우를 센다. AST 사이의 Tree Edit Distance(TED)는 현재 코드에서 반환 코드까지의 변경을 측정하며~\cite{zhang1989simple,pawlik2016tree}, 어느 한쪽이 파싱되지 않으면 정의되지 않는다. 정의되지 않는 경우는 제한 없는 RR에는 남지만 TED 요약에는 들어가지 않으며, 유한한 gate는 거리가 정의되지 않는 변경을 거부한다. 짝짓지 않은 TED는 성공하고 파싱 가능한 반환물의 평균이고, 짝지은 locality는 공동 성공만 쓴다. retention은 \texttt{SequenceMatcher}(autojunk 해제)가 일치시킨 토큰 또는 공백을 제거한 비어 있지 않은 줄을 source 개수로 나눈다. Python 토큰화는 레이아웃 토큰을 빼고 주석은 유지하며, Java는 단어와 구두점을 분리한다. retention 차이는 퍼센트포인트(pp)이며 토큰 수나 학습 측정치가 아니다.
% Repair Rate (RR) is the fraction of eligible inputs whose returned program passes every test. Pass Rate (PR) averages passed-test fractions; Improvement Rate (IR) records an increased fraction. Tree Edit Distance (TED) between ASTs measures current-to-returned change~\cite{zhang1989simple,pawlik2016tree} and is undefined when either program does not parse. Undefined cases remain in unrestricted RR but not TED summaries; finite gates reject undefined-distance changes. Unpaired TED averages successful, parseable returns; paired locality uses joint successes. Retention divides tokens or nonempty stripped lines matched by \texttt{SequenceMatcher} (autojunk disabled) by the source count. Python tokenization omits layout tokens but keeps comments; Java separates words and punctuation. Retention differences are percentage points (pp), not token counts or learning measures.

따로 언급하지 않으면 대괄호는 복원추출한 10,000회 problem-cluster 재표집에서 얻은 95\% percentile bootstrap 구간이며, 표집된 각 cluster에서 짝지은 입력을 모두 보존한다~\cite{efron1979bootstrap}. Java는 학생과 exercise를 따로 재표집한다. instance 가중 추정치는 합산 차이를 표집 입력 수로 나누고, equal-problem 추정치는 문제별 평균을 평균한다. 정확 양측 McNemar 검정은 입력 짝의 독립성을 가정하므로 cluster를 고려한 구간을 대체하지 않고 보조할 뿐이다~\cite{mcnemar1947note}. Holm 보정은 history 제거 재학습 4개 검정(Strict/Progress $\times$ Seen/Unseen)에 적용되며 모든 탐색적 대비에 적용되는 것이 아니다~\cite{holm1979simple}. 개별 비율의 Wilson 구간은 따로 보고한다~\cite{wilson1927probable}. 프로토콜은 통제가 언제 고정되었는지 밝히지만, 확장된 연구가 외부에 사전등록된 것은 아니다. 적응적으로 들여다본 개발은 탐색적으로 남는다. 공백에 민감한 보정과 원래 집계는 따로 보존한다.
% Unless stated otherwise, brackets give 95\% percentile bootstrap intervals from 10,000 problem-cluster resamples with replacement, preserving all paired inputs in each sampled cluster~\cite{efron1979bootstrap}. Java separately resamples students and exercises. Instance-weighted estimates divide pooled differences by sampled inputs; equal-problem estimates average problem means. Exact two-sided McNemar tests assume independent input pairs and are supplementary to cluster-aware intervals, not substitutes for them~\cite{mcnemar1947note}. Holm adjustment covers the four history-removal retraining tests (Strict/Progress $\times$ Seen/Unseen), not every exploratory contrast~\cite{holm1979simple}; individual-rate Wilson intervals are reported separately~\cite{wilson1927probable}. Protocols identify when controls were frozen, but the extended study was not externally preregistered. Adaptively inspected development remains exploratory. We retain whitespace-sensitive corrections and original counts separately.

\noindent\textbf{Matched targets.} Table~\ref{tab:targets}는 현재 입력과 학습 예제 수를 고정한 채 target만 바꾼다. % \noindent\textbf{What a student receives.} Cohort means do not describe an individual student, so we resolve the Java contrast by exercise and by student. Terminal targets repair more trajectories on 15 of the 17 exercises, tie on 2, and lose on none; the 63 additional repairs are concentrated rather than uniform, reaching 12 on one exercise where progress targets repair 3 of 15 trajectories against 15. Among the 90 trajectories that both rules repair, the lexical-retention difference is exactly zero for 63.3\% of students, positive for 31.1\%, and negative for 5.6\%, with median 0.0 points, upper quartile 4.4, minimum -21.1, and maximum 49.7; line retention behaves the same, zero for 64.4\% with maximum 47.6. The mean advantage is therefore a minority effect with a long tail: most students who receive a working repair from either rule get back the same amount of their own code, about a third get more, by a median of 9.6 points, and a few get less. Figure~\ref{fig:case} illustrates that tail on Python, where the progress-target repair continues the student's own boundary edit while the terminal-target repair replaces the algorithm. Which rule a course deploys therefore depends on the exercise and on whether coverage or locality binds.

\noindent\textbf{Peer targets.} 결과와 거리를 맞춘 별도의 교체는 RR을 Seen에서 50.4\%에서 54.7\%로, Unseen에서 78.4\%에서 84.4\%로 올린다. 같은 사용자에서 동료를 뺀 구간은 [-7.71, -0.84]와 [-11.79, -0.41]이고, 정확 McNemar \(p=0.005\)와 \(p=0.032\)이다. 매칭은 정본 Progress 학습 레코드 21,416개 중 5,231개(24.4\%)와 validation 2,685개 중 306개(11.4\%)를 덮는다. 이 결과는 이 caliper, donor 상한, source 모집단, 교체 규칙에 관한 것이다. 결과가 같고 edit distance가 가깝더라도 target의 구조, 스타일, 길이는 다를 수 있으므로 이 대비가 사용자 정체성을 분리하지는 않는다. 여기서는 맞춘 동료 target이 coverage를 개선하며, 이 통제 하에서 자기 자신의 trajectory가 유일하게 필요한 것은 아니다.
% \noindent\textbf{Peer targets.} The separate outcome- and distance-matched replacement raises RR from 50.4\% to 54.7\% on Seen and from 78.4\% to 84.4\% on Unseen. Same-minus-peer intervals are [-7.71, -0.84] and [-11.79, -0.41], with exact McNemar \(p=0.005\) and \(p=0.032\). Matches cover 5,231/21,416 canonical Progress training records (24.4\%) and 306/2,685 validation records (11.4\%). The result concerns this caliper, donor cap, source population, and replacement rule. Equal outcomes and nearby edit distance still permit differences in target structure, style, and length, so the contrast does not isolate user identity. Matched peer targets improve coverage here; one's own trajectory is not uniquely necessary under this control.

\noindent\textbf{Operational locality.} 선언된 구조적 budget은 패치 크기에 명시적인 공학적 의미를 준다: 배포는 그 안의 변경만 받아들인다. budget별 Seen 비율은 current-only Answer-3Seed/Mixed/LSGen 순으로 TED 5에서 16.9/22.5/4.8\%, 10에서 28.5/32.4/8.0, 20에서 40.3/44.0/13.9, 40에서 51.4/50.9/30.4, 80에서 61.0/56.0/50.8, 160에서 66.8/57.9/67.6이며 각각 997개 입력 기준이다. TED 20에서 Mixed는 Seen 입력의 44.0\%를 수리해 LSGen의 13.9\%보다 30.1 포인트 [26.45, 33.82] 높다. 사전에 지정한 여섯 budget 전체에서 LSGen에 대한 평균 우위는 14.7 포인트 [12.03, 17.43]이다. 이는 budget별 결과이며 제한 없는 우월성 주장이 아니다: 160에서는 LSGen이 이기고, current-only Answer-3Seed는 40부터 Mixed를 앞선다. Unseen에서 Mixed 대 current-only Answer-3Seed는 5에서 38.8\% 대 32.0\%, 10에서 48.0\% 대 40.8\%, 20에서 57.6\% 대 54.8\%이며 40에서 순서가 뒤집힌다. 관측된 어떤 budget도 사후에 유일한 기본 평가 지점으로 지정하지 않는다.
% \noindent\textbf{Operational locality.} A declared structural budget gives patch size an explicit engineering meaning: the deployment admits only changes within it. Per-budget Seen rates are 16.9/22.5/4.8\% at TED 5, 28.5/32.4/8.0 at 10, 40.3/44.0/13.9 at 20, 51.4/50.9/30.4 at 40, 61.0/56.0/50.8 at 80, and 66.8/57.9/67.6 at 160 for current-only Answer-3Seed/Mixed/LSGen, each over 997 inputs. Across the six prespecified budgets its mean advantage over LSGen is 14.7 points [12.03, 17.43]. This is a budget-indexed outcome, not an unrestricted superiority claim: LSGen wins at 160, and current-only Answer-3Seed overtakes Mixed from 40 onward. On Unseen, Mixed versus current-only Answer-3Seed is 38.8\% versus 32.0\% at 5, 48.0\% versus 40.8\% at 10, and 57.6\% versus 54.8\% at 20; the order reverses at 40. No observed budget is retroactively designated the unique primary endpoint.

\noindent\textbf{Answer to RQ2.} target 구성은 맞춘 입력 하에서 coverage와 locality를 서로 반대 방향으로 바꾸며, student-held-out Java에서도 같은 방향이고, 두 효과 모두 exercise나 학생에 걸쳐 균일하지 않다. 맞춘 동료 target이 coverage를 개선하므로 이 효과는 개인에게 고유한 supervision이 아니며, 교육적 이득은 측정되지 않은 채로 남는다.
% \noindent\textbf{Answer to RQ2.} Target construction changes coverage and locality in opposite directions under matched inputs, with the same direction on student-held-out Java, and neither effect is uniform across exercises or students. Matched peer targets improve coverage, so the effect is not uniquely personal supervision; pedagogical benefit remains unmeasured.

\subsection{RQ3: Component Efficacy}
\noindent\textbf{Fixed candidate breadth.} 성공 지시자 \(a_{ij}\)를 갖는 저장된 draw 세 개에 대해, 입력 \(i\)에서 균일하게 고른 단일 draw의 기대 성공은 \(\frac{1}{3}\sum_j a_{ij}\)이고, 세 draw의 합집합은 \(\max_j a_{ij}=1\)일 때 성공한다. 두 값의 짝지은 차이는 동일한 후보 집합 안에서 추가 기회만을 분리한다. greedy decoding을 단일 stochastic draw로 바꾸면 7.6 포인트 [-9.81, -5.41]를 잃지만, 동일한 고정 draw 세 개를 실행으로 선택하면 Seen에서 15.1 포인트 [13.48, 16.76]를 얻는다. 이는 저장된 실행에 대한 기술적 분해이며, 미래의 draw 세 번이 성공을 보장하거나 오류가 독립이라는 주장이 아니다. 이 결과는 portfolio를 adapter 하나와만 비교하면 그 특화된 학습 신호의 증거가 과장되는 이유를 직접 보여 준다.
% \noindent\textbf{Fixed candidate breadth.} For three stored draws with success indicators \(a_{ij}\), the expected uniformly selected one-draw success for input \(i\) is \(\frac{1}{3}\sum_j a_{ij}\), whereas the three-draw union succeeds when \(\max_j a_{ij}=1\). Their paired difference isolates additional opportunities within the identical candidate set. Replacing greedy decoding by one stochastic draw costs 7.6 points [-9.81, -5.41], whereas execution-selecting three of those identical fixed draws contributes 15.1 points [13.48, 16.76] on Seen. This is a descriptive decomposition of stored executions, not a claim that three future draws have guaranteed success or independent errors. It directly demonstrates why comparing a portfolio only with one adapter overstates evidence for its specialized training signal.

temperature sweep은 대표 수치에 유리한 조건만 고르지 않고 선언된 모든 조건을 보존한다. \(T=1.0\)까지 단일 draw 비율은 Seen에서 41.1--43.1\% 범위에 머물고, 세 draw 합집합은 60.0/75.2\%에 이르며, \(T=1.5\)에서 decoder는 15.8/35.2\%로 붕괴한다. \(T=0.8\)에서의 별도 20-draw 스트림은 Seen 74.8\%와 Unseen 84.0\%에 도달하며 early stopping 하에서 평균 7.44회와 5.08회를 호출한다. 이 더 높은 비율들은 다른 생성 예산을 쓰므로 3회 호출 기본 결과를 대체하지 않는다. 미세조정도 중요하다: 맞춘 base model의 세 draw 합집합은 30.4/65.6\%에 그쳐, 적응이 Seen에서 27.2 포인트 [22.99, 31.41], Unseen에서 6.4 포인트 [1.19, 11.34]를 더한다. 따라서 폭만으로 base model 대비 개선 전체가 설명되지는 않는다.
% The temperature sweep retains all declared conditions instead of selecting the best one for the headline. Through \(T=1.0\) the one-draw rate stays within 41.1--43.1\% on Seen, the three-draw union reaches 60.0/75.2\%, and at \(T=1.5\) the decoder collapses to 15.8/35.2\%. A separate 20-draw stream at \(T=0.8\) reaches 74.8\% Seen and 84.0\% Unseen, using on average 7.44 and 5.08 calls under early stopping. Those higher rates spend a different generation budget and do not replace the three-call primary results. Fine-tuning also matters: the matched base-model three-draw union reaches only 30.4/65.6\%, so adaptation adds 27.2 points [22.99, 31.41] on Seen and 6.4 points [1.19, 11.34] on Unseen. Breadth alone therefore does not explain all improvement over the base model.

temperature를 맞춘 조건에서, 한 checkpoint의 draw 세 개를 서로 다른 checkpoint 세 개의 draw 하나씩으로 바꾸면 RR이 Seen에서 -0.1 포인트 [-2.00, 1.80], Unseen에서 2.4 포인트 [-0.41, 5.31] 변한다. 이 구간들은 checkpoint 다양성의 일관된 이점을 확립하지 않는다. 동등성을 보이는 것도 아니다: 불확실성은 실용적으로 의미 있는 이득과 손해를 여전히 허용한다. 결정적 다중 seed 이득이 이 결과와 공존할 수 있는데, 한 checkpoint에서 표집하는 것만으로도 이미 다양성이 공급되기 때문이다.
% At matched temperature, replacing three draws of one checkpoint by one draw from each of three checkpoints changes RR by -0.1 points [-2.00, 1.80] on Seen and 2.4 points [-0.41, 5.31] on Unseen. These intervals do not establish a consistent advantage from checkpoint diversity. They also do not show equivalence: the uncertainty still admits benefits and harms of practical interest. A deterministic multi-seed gain can coexist with this result because sampling from one checkpoint already supplies diversity.

한 추론 스택에서의 current-only factorial이 이 설명을 검정한다. greedy checkpoint 세 개는 하나보다 9.8 [7.85, 11.92]와 10.8 [7.23, 14.64] 포인트를 얻지만, stochastic decoder를 맞추면 서로 다른 checkpoint는 2.1 포인트 [0.00, 4.16]와 1.2 포인트 [-2.93, 5.93]만 더한다. equal-problem Seen 구간은 0을 포함하므로, 반올림된 instance 가중 하한이 견고한 checkpoint 이점을 확립하지는 않는다. 그 스택에서의 절대 Seen/Unseen 비율은 greedy checkpoint 하나 53.1/67.2\%, greedy checkpoint 세 개 62.9/78.0\%, 같은 checkpoint의 stochastic 3개 조합 66.8/79.6\%, 서로 다른 checkpoint의 3개 조합 68.9/80.8\%이며, 과거 스택의 72.0/81.2\%와 대비된다. backend 민감도가 실질적이므로, 배포 권고는 평가된 스택으로 한정되며 backend와 무관한 우월성으로 주장하지 않는다.
% A current-only factorial on one inference stack tests this explanation. Three greedy checkpoints gain 9.8 [7.85, 11.92] and 10.8 [7.23, 14.64] points over one, but under the matched stochastic decoder distinct checkpoints add only 2.1 points [0.00, 4.16] and 1.2 points [-2.93, 5.93]. The equal-problem Seen interval includes zero, so the rounded instance-weighted lower bound does not establish a robust checkpoint benefit. Absolute Seen/Unseen rates on that stack are 53.1/67.2\% for one greedy checkpoint, 62.9/78.0\% for three greedy checkpoints, 66.8/79.6\% for a same-checkpoint stochastic triple, and 68.9/80.8\% for a distinct-checkpoint triple, against 72.0/81.2\% on the historical one. Backend sensitivity is material, and the deployment recommendation is restricted to the evaluated stack rather than asserted as backend-independent superiority.

\noindent\textbf{History and portfolio selection.} target은 같게 두고 더 앞선 제출 맥락만 없앤 재학습은 Holm 보정 후 네 주요 검정에서 유의한 RR 차이를 내지 않으며, 보정된 최소 \(p\)는 0.313이다. 이 음성 결과는 이득을 trajectory에서 끌어낸 관계로 국소화하지 않는다. history로 선택한 3개 조합을 고정한 채 history를 제거하면 Mixed RR이 61.5/74.8\%에서 70.3/82.4\%로, Answer-9Choose3이 59.8/74.8\%에서 70.9/80.8\%로(Seen/Unseen) 올라간다. 이득은 Mixed/Answer에 대해 Seen 8.8/11.1 포인트, Unseen 7.6/6.0 포인트이며 모든 구간이 0을 제외한다. 이것은 고정된 3개 조합이며 Table~\ref{tab:main}의 current-only 재선택 행이 아니다. 이 결과는 prompt 분포 비용과 양립하는데, 특히 terminal 학습이 단일 source 입력을 쓰기 때문이다. 또한 측정된 portfolio 이점에 history가 필요하다는 서술과는 양립하지 않는다. 맞춘 재학습과 입력 고정 개입을 서로 교환 가능한 추정치로 다루어서는 안 된다.
% \noindent\textbf{History and portfolio selection.} Retraining with the same targets but without earlier-submission context yields no significant RR difference in the four principal tests after Holm correction; the smallest adjusted \(p\) is 0.313. This negative result does not localize gains to trajectory-derived relations. For history-selected triples held fixed, removing history raises Mixed RR from 61.5/74.8\% to 70.3/82.4\% and Answer-9Choose3 from 59.8/74.8\% to 70.9/80.8\% (Seen/Unseen). 선택 공간 통제도 이질적 target의 일반적 이점을 확립하지 못한다. Answer-9Choose3은 Mixed와 동일한 9개 checkpoint pool 크기와 84개 부분집합 기회를 받는다. 기본 5-fold cross-fitted mixed에서 terminal을 뺀 대비는 +2.2 포인트 [-0.19, 4.63]이고, cross-fitting을 하지 않은 추정치는 +1.7 [-0.79, 4.29]이다. 이 추정치들은 양수지만 불확실하다. 고정된 3개 조합의 여섯 순서를 정확히 재생하는 것은 독립 후보 controller를 확인하는 것이며 학습된 다양성의 가치를 확인하는 것이 아니다.

The primary five-fold cross-fitted mixed-minus-terminal contrast is +2.2 points [-0.19, 4.63], compared with the non-cross-fitted +1.7 [-0.79, 4.29]. These estimates are positive but uncertain. Target heterogeneity has a small, uncertain unrestricted contrast against the equally searched terminal pool.

\subsection{RQ4: Generality}
\label{sec:generality}
\noindent\textbf{Problems and execution suites.} Unseen 안에서 Mixed는 Zero-shot을 12.8 포인트 [6.83, 18.75] 앞서며, 배타적 성공은 45개 대 13개, 정확 McNemar \(p=3.01\times10^{-5}\)이다. 공동 수리 142개 중 122개가 두 방법 모두에서 TED가 정의되며, 그 122개에서 TED를 6.41 [3.43, 9.89] 줄인다. Unseen의 절대 RR이 Seen보다 높은 것은 더 강한 일반화의 증거가 아니다: 두 분할은 trajectory 가용성과 문제 구성이 다르다. % \noindent\textbf{Answer to RQ4.} The matched-target tradeoff replicates on authentic student-held-out Java, and candidate breadth remains useful at smaller model scale. Mixed-target unrestricted superiority does not replicate consistently. Prefix, difficulty, overlap, verdict-order, and hidden-slice checks narrow specific threats, but they do not make CodeNet a classroom study or acceptance a proof of correctness.

\subsection{RQ5: Development Diagnosis}

\noindent\textbf{Decision rule.} 이후 개발은 Current-Only(C), Authentic-History(H), Shuffled-History(HS), Matched Other-User(U) 조건을 비교했다. 채택 조건은 H의 합산 stable acceptance가 모든 통제군보다 엄격히 클 것, 회귀·회귀 상한·unknown 어느 것도 C보다 늘지 않을 것, 요구된 모든 문제 fold에서 더 나쁘지 않을 것, 평가가 완료될 것이었다. stable acceptance는 source와 후보 모두에 대해 네 번의 재실행 블록(worker 순서 1, 8, 8, 1)에서 테스트별 결과가 완전하고 동일하며, 후보의 모든 테스트가 통과할 것을 요구한다. 회귀는 stable 비교에서 이전에 통과한 testcase를 잃는 것을 뜻한다. 실행이 누락되거나 일관되지 않거나 인프라상 불확실하면 unknown이다. 회귀 수 $r$, unknown 수 $u$, 입력 수 $n$에 대해 보수적 상한은 $(r+u)/n$이며, 이는 신뢰 상한이 아니다. 이 요구들은 Figure~\ref{alg:generic}의 고정 측정 통과 비율 불변식보다 강하다. 과거 판정도 재실행과 다르다: 고유한 학습 target 14,027개 중 7,979개만 accepted로 캐시되어 있었다. 우리는 런타임 불확실성을 학생 능력으로 해석하지 않고 그대로 보존한다. 예측 손실은 RR이 아니다.
% \noindent\textbf{Decision rule.} Subsequent development compared Current-Only (C), Authentic-History (H), Shuffled-History (HS), and Matched Other-User (U) conditions. Adoption required strictly greater pooled stable acceptance for H than every control; no increase versus C in regressions, regression upper bounds, or unknowns; all required problem folds non-worse; and completed evaluation. Stable acceptance requires complete, identical per-test outcomes across four replay blocks (worker order 1, 8, 8, 1) for both source and candidate, with every candidate test accepted. Regression means losing a previously passed testcase in a stable comparison. Missing, inconsistent, or infrastructure-uncertain execution is unknown. For regression count $r$, unknown count $u$, and $n$ inputs, the conservative upper bound is $(r+u)/n$; it is not a confidence bound. These requirements exceed the fixed-measurement pass-fraction invariant of Figure~\ref{alg:generic}. Historical verdicts also differ from replay: only 7,979 of 14,027 unique training targets were cached as accepted. We retain runtime uncertainty rather than interpreting it as student ability. Predictive loss is not RR.

\subsection{Threats to Validity}
\noindent\textbf{Internal validity.} 런타임 변동성, 정의되지 않는 source AST, Python 공백이 라벨과 거리에 영향을 준다. 우리는 unknown, 분모, 공백에 민감한 보정을 보존하며, 해시는 provenance를 확립하지만 정확성을 확립하지는 않는다. source와 동료 매칭이 모든 target의 의미나 스타일을 같게 만들지는 않는다.
% \noindent\textbf{Internal validity.} Runtime variability, undefined source ASTs, and Python whitespace affect labels and distances. We retain unknowns, denominators, and whitespace-sensitive corrections; hashes establish provenance, not correctness. Source and peer matching do not equate all target semantics or styles.

\noindent\textbf{Construct validity.} acceptance는 의미적 정확성의 증명이 아니며~\cite{smith2015cure}, 같은 묶음에서 떼어낸 slice는 독립적인 명세가 아니다. TED와 retention은 인지 부하나 이후 학습을 측정하지 않는다. CodeNet은 초보자를 식별하거나 숙달을 측정하지 않는다. Java는 교실 제출물을 제공하지만 피드백 사용을 관찰하는 개입은 아니다. exercise별·학생별 분해는 어떤 학생이 다른 수리를 받게 되는지를 기술하며 어떤 학생이 이득을 얻는지를 기술하지 않고, Figure~\ref{fig:case}는 추정치를 담지 않는 사후 사례 하나다. 과목 데이터 사용 조건이 학생 제출물의 재배포를 허용하지 않으므로 우리는 CodeNet 프로그램을 보여 준다. 이런 구별들이 교육적 해석과 target 품질 해석을 제한한다.
% \noindent\textbf{Construct validity.} Acceptance is not proof of semantic correctness~\cite{smith2015cure}; same-suite slices are not independent specifications. TED and retention do not measure cognitive load or subsequent learning. CodeNet does not identify novices or measure mastery. Java supplies classroom submissions, not an intervention observing feedback use. The per-exercise and per-student resolution describes which students would receive a different repair, not which students benefit, and Figure~\ref{fig:case} is one post-hoc case that carries no estimate. We display a CodeNet program because the course data terms do not permit redistributing student submissions. These distinctions limit educational and target-quality interpretations.

\noindent\textbf{External and conclusion validity.} 필터링은 짧고 결국 성공하는 Python trajectory를 선호하며 Seen 내 사용자 중복을 허용한다. Java는 과목 맥락 하나와 보류된 exercise 네 개만 더한다. cluster bootstrap과 equal-problem 추정치는 작은 cluster의 불확실성, 다중성, 적응적 개발 편향을 없애지 못한다. gate는 개별 실행 전에 고정되었으나 전체 프로그램에 대해 고정된 것은 아니며, 재사용된 개발 결과는 탐색적으로 남는다.
% \noindent\textbf{External and conclusion validity.} Filtering favors short, eventually successful Python trajectories and permits Seen user overlap. Java adds one course context and only four held-out exercises. Cluster bootstrap and equal-problem estimates do not eliminate small-cluster uncertainty, multiplicity, or adaptive-development bias. Gates were frozen before individual runs, not the entire program; reused development results remain exploratory.

\section{Related Work}
\label{sec:related}
\noindent\textbf{Repair and generation budgets.} generate-and-validate 수리는 탐색, 학습된 변환, 언어 모델에 걸쳐 있다~\cite{gazzola2019automatic,monperrus2018automatic,weimer2009automatically,legoues2012genprog}. 탐색 분석~\cite{qi2014strength}과 실행 기반 평가~\cite{haque2023fixeval,chen2021evaluating}는 후보 품질과 노출을 분리한다. 신경망 패치, ensemble, 합성 손상, 실행 정보를 쓰는 자기지도는 서로 다른 학습 신호를 제공하며~\cite{tufano2019empirical,lutellier2020coconut,yasunaga2021break,ye2022selfapr}, zero-shot 연구는 과제 적응 없는 수리를 검토한다~\cite{xia2022less,jiang2023impact}. 독립 ensemble과 가중치 평균은 다양성의 또 다른 개념을 제공한다~\cite{lakshminarayanan2017simple,wortsman2022model}. 우리는 portfolio 수리를 새로 제안하지 않는다. 동일 target seed, 동일한 탐색 공간, 고정된 draw, current-only 통제로 trajectory target만 분리한다.
% \noindent\textbf{Repair and generation budgets.} Generate-and-validate repair spans search, learned transformations, and language models~\cite{gazzola2019automatic,monperrus2018automatic,weimer2009automatically,legoues2012genprog}. Search analyses~\cite{qi2014strength} and execution-based evaluation~\cite{haque2023fixeval,chen2021evaluating} separate candidate quality from exposure. Neural patches, ensembles, synthetic corruption, and execution-informed self-supervision provide different training signals~\cite{tufano2019empirical,lutellier2020coconut,yasunaga2021break,ye2022selfapr}; zero-shot studies examine repair without task adaptation~\cite{xia2022less,jiang2023impact}. Independent ensembles and weight averaging supply other notions of diversity~\cite{lakshminarayanan2017simple,wortsman2022model}. We do not introduce portfolio repair; we isolate trajectory targets with same-target seeds, equal search spaces, fixed draws, and current-only controls.

\noindent\textbf{Programming-exercise feedback.} 교육용 수리는 군집화, 정렬, 리팩터링으로 올바른 프로그램을 활용하고~\cite{gulwani2018automated,wang2018search,hu2020re}, 관련 표현과 튜터링 시스템은 피드백을 전파하고 힌트를 생성한다~\cite{piech2015embeddings,glassman2015overcode,rivers2017datadriven,price2017isnap}. 언어 모델은 수리, 구문 피드백, 대화, 동료, 반례를 뒷받침한다~\cite{joshi2023repair,zhang2024pydex,phung2023generating,liu2024fastfixer,yang2024cref,zhao2024peer,orvalho2025counterexample}. 과제를 고려한 피드백과 다양화된 피드백은 또 다른 참조 전략을 쓴다~\cite{heo2023referent,choi2021automated,choi2025automated}. LSGen도 시간순으로 틀린 제출과 이후 올바른 제출의 짝을 retrieval용으로 mine하므로~\cite{dai2026learner} trajectory 자체가 우리의 새로움은 아니며, 여기서도 LSGen은 강한 Seen 우위를 유지한다. 벤치마킹과 설문 연구는 모집단과 프로토콜 차이를 강조한다~\cite{yi2017feasibility,koutcheme2024benchmarking,keuning2018systematic}. 이 방법들이 모두 terminal target으로 학습하는 것은 아니다: 우리의 더 좁은 개입은 맞춘 source에 대해 target을 교체하여 coverage--locality 트레이드오프를 드러내며, 피드백 전략 전반에 대한 우월성을 드러내는 것이 아니다.
% \noindent\textbf{Programming-exercise feedback.} Educational repair exploits correct programs through clustering, alignment, and refactoring~\cite{gulwani2018automated,wang2018search,hu2020re}; related representations and tutoring systems propagate feedback and generate hints~\cite{piech2015embeddings,glassman2015overcode,rivers2017datadriven,price2017isnap}. Language models support repair, syntax feedback, conversations, peers, and counterexamples~\cite{joshi2023repair,zhang2024pydex,phung2023generating,liu2024fastfixer,yang2024cref,zhao2024peer,orvalho2025counterexample}. Assignment-aware and diversified feedback use further reference strategies~\cite{heo2023referent,choi2021automated,choi2025automated}. LSGen also mines chronological wrong-to-later-correct submission pairs for retrieval~\cite{dai2026learner}, so trajectories are not our novelty, and it retains its strong Seen advantage here. Benchmarking and surveys emphasize population and protocol differences~\cite{yi2017feasibility,koutcheme2024benchmarking,keuning2018systematic}. These methods do not uniformly train on terminal targets: our narrower intervention replaces the target for matched sources and exposes a coverage--locality tradeoff, not dominance over feedback strategies.

\noindent\textbf{History and learner evidence.} ZPD와 scaffolding은 지원받는 수행에 관한 것이며 프로그램 edit distance에 관한 것이 아니다~\cite{cole1978mind,murray2002toward,chounta2017grey,schulze2024beyond}. knowledge tracing은 상호작용에서 숙련도를 모형화하고~\cite{corbett1994knowledge,piech2015deep,ghosh2020context}, TIKTOC은 testcase 증거를 포함한다~\cite{duan2024tiktoc}. next-step 힌트, 피드백 사다리, 초보자 반응 연구는 안내를 더 직접적으로 검토하며~\cite{roest2024next,heickal2024generating,xiao2024exploring}, 피드백 이론은 그 해석과 사용을 강조한다~\cite{narciss2008feedback,hattie2007power,shute2008focus,aleven2000limitations}. 우리는 더 좁은 수리 전제를 검정한다: 실제 history가 현재 코드와 교란된 history를 넘어 생성된 변경을 개선하는지다. 결과는 그 전제를 확립하지 않는다. 교육적 주장에는 실행 가능한 출력만이 아니라 이해, 전이, 자력 수정에 대한 측정이 추가로 필요하다.
% \noindent\textbf{History and learner evidence.} ZPD and scaffolding concern supported performance, not program edit distance~\cite{cole1978mind,murray2002toward,chounta2017grey,schulze2024beyond}. Knowledge tracing models proficiency from interactions~\cite{corbett1994knowledge,piech2015deep,ghosh2020context}; TIKTOC incorporates testcase evidence~\cite{duan2024tiktoc}. Next-step hints, feedback ladders, and novice-response studies examine guidance more directly~\cite{roest2024next,heickal2024generating,xiao2024exploring}, while feedback theory emphasizes its interpretation and use~\cite{narciss2008feedback,hattie2007power,shute2008focus,aleven2000limitations}. We test the narrower repair prerequisite: whether authentic history improves generated changes beyond current code and perturbed histories. The results do not establish that prerequisite. Educational claims additionally require comprehension, transfer, and independent-correction measurements, not only executable outputs.

\section{Conclusion}
\label{sec:conclusion}
우리는 trajectory에서 끌어낸 수리 target과 실행 기반 portfolio를 위한 Mine--Train--Select 기법인 \textsc{ZPDPatch}를 제시했다. 맞춘 Python 실험과 student-held-out Java 실험은 같은 coverage--locality 트레이드오프를 보인다: progress target은 공동 성공에서 source를 더 많이 보존하지만 더 적은 입력을 수리한다. 후보 폭과 적응은 상당한 이득을 기여하는 반면, 실제 history와 target 이질성은 제한 없는 조건에서 일관된 이점을 보이지 않는다. 개발은 일반적인 실행 기반 선택은 개선했지만 history 특화 채택 gate를 통과하지 못했으므로, 우리는 current-only terminal 3개 조합을 유지한다. exercise별·학생별로 분해하면 그 트레이드오프는 균일하지 않다: coverage 비용은 특정 exercise에 집중되고, retention 이득은 어느 규칙에서든 수리를 받은 학생의 약 3분의 1에 도달하며, 바로 그 지점에서 과목이 선택을 해야 한다. 교육적 이득과 더 넓은 모델 계열에 대한 일반성은 측정되지 않은 채로 남는다.
% We presented \textsc{ZPDPatch}, a Mine--Train--Select technique for trajectory-derived repair targets and execution-guided portfolios. Matched Python and student-held-out Java experiments show the same coverage--locality tradeoff: progress targets preserve more source on joint successes but repair fewer inputs. Candidate breadth and adaptation contribute substantial gains, while authentic history and target heterogeneity show no consistent unrestricted advantage. Development improves generic execution selection but passes no history-specific adoption gate, so we retain the current-only terminal triple. Resolved per exercise and per student, that tradeoff is uneven: the coverage cost concentrates on particular exercises, and the retention gain reaches about a third of the students who receive a repair from either rule, which is where a course would have to choose. Educational benefit and broader model-family generality remain unmeasured.
