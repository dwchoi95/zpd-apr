## 독립 리뷰

### 요약

이 논문은 실제 학생 제출 궤적에서 Progress, Strict, Answer의 세 감독 관계를 구성하고, 관계별 3개 시드로 학습한 9개 QLoRA 체크포인트 중 검증 실행 coverage가 높은 3개를 선택하여 순차 실행하는 ZPDPatch를 제안한다. 실행 기반 fallback은 관측 테스트 비퇴행과 선택적 AST 편집 예산 준수를 보장한다.

가장 중요한 실험적 결론은 예상과 달리 명확하다. 전체 궤적 입력은 current-code-only보다 안정적으로 낫지 않고, 관계 이질성을 강제한 포트폴리오는 동일 Answer target의 3-seed 포트폴리오보다 낫지 않다. 따라서 관측된 coverage 향상의 주된 근거는 trajectory relation이 아니라 독립 체크포인트 다양성이다.

## 강점

- 주장과 증거의 정렬이 이례적으로 정직하다. history 효과와 relation heterogeneity 효과가 확인되지 않았음을 숨기지 않고, Answer-3Seed가 더 강한 설명이라는 결론을 초록부터 결론까지 일관되게 유지한다.
- 실험 설계가 전반적으로 세심하다. 문제 단위 cluster bootstrap, equal-problem estimand, exact McNemar, 다중비교 보정, 세 학습 시드, hidden-test partition, 문제-held-out CodeNet 평가, 학생-held-out Java 재현을 포함한다.
- 동일 target의 Answer-3Seed 기준선을 포함한 것은 특히 중요하다. 이 기준선이 없었다면 heterogeneous policy의 효과를 과대 해석했을 가능성이 높다.
- 원본 프로그램을 후보 집합에 포함하는 fallback과 edit-budget gate는 단순하지만 실용적이며, 관측 테스트 비퇴행과 편집 예산 준수라는 명확한 시스템 속성을 제공한다.
- patch size와 repair coverage를 구분하고, 작은 TED를 교육적 우월성으로 해석하지 않는 점이 적절하다. LSGen과의 budget-frontier 비교도 unrestricted RR 하나보다 정보량이 많다.
- 논문은 읽기 쉽고 재현에 필요한 데이터 구성, 캐시 키, 학습 설정, 실행 제한, 통계 절차를 상당히 구체적으로 기술한다.

## 약점과 치명도 순위

### 1. 높음 — 가장 중요한 비교에서 학습 및 모델 선택 기회가 비대칭이다

ZPDPatch는 9개 체크포인트를 학습하고 84개 가능한 triple 중 검증 결과로 최적 조합을 선택한다. 반면 Answer-3Seed는 세 Answer 체크포인트로 이루어진 하나의 사전 지정 triple이다. 추론 시 생성 횟수는 같지만, 학습 비용은 논문 자체 수치로 37.1 GPU-hours 대 17.5 GPU-hours이며 후보군 크기와 validation-selection 자유도도 다르다.

따라서 Answer-3Seed 대비 Unseen budget frontier의 +2.60점은 relation diversity 때문인지, 9개 중 3개를 선택할 수 있었기 때문인지 분리되지 않는다. “target- and compute-matched”라는 표현도 추론 compute에만 해당하며 전체 실험 compute에는 해당하지 않는다.

가장 필요한 기준선은 9개의 독립 Answer 체크포인트를 학습한 뒤 동일하게 모든 84개 triple에서 검증 최적 조합을 선택하는 **Answer-9Choose3**이다. 이 비교 없이는 mixed portfolio selection의 잔여 이점을 인과적으로 해석하기 어렵다.

### 2. 높음 — 핵심 trajectory 기여가 실험적으로 지지되지 않아 technical novelty와 significance가 약해진다

논문의 동기와 상당 부분의 방법론은 submission trajectory에 기반하지만:

- Full Trajectory는 Current Code Only보다 안정적으로 우수하지 않다.
- relation-constrained portfolio는 Seen에서 Answer-3Seed보다 유의하게 나쁘다.
- unconstrained winner는 Answer 두 개와 Progress 하나이다.
- unconstrained portfolio는 Answer-3Seed와 Seen, Unseen unrestricted RR에서 구분되지 않는다.
- Java 재현에서도 Answer-3Seed가 수치상 더 높다.

따라서 현재 지지되는 시스템은 주로 “여러 독립 SFT 체크포인트를 실행하고 validation coverage로 선택하는 ensemble”이다. 실행 set-union, exhaustive selection, fallback, TED gate 각각은 유용하지만 기술적으로 매우 새로운 구성요소는 아니다. 논문의 가치 있는 부정적 결과와 조심스러운 해석은 인정하지만, FSE Research Track의 “innovative and significant original research” 기준에서 현재 핵심 기여가 충분한지 의문이다.

### 3. 높음 — history가 실제로 필요한 평가 사례가 부족하다

최종 평가는 각 trajectory의 마지막 실패 상태를 주로 사용한다. 그러나 논문의 강한 동기는 “같은 현재 코드라도 이전 경로에 따라 적절한 다음 패치가 달라진다”는 것이다. 현재 실험은 이 상황을 직접 구성하거나 측정하지 않는다.

필요한 것은 동일하거나 매우 유사한 current code를 갖지만 서로 다른 history와 후속 개선을 보이는 matched/counterfactual 사례다. 이러한 history-sensitive subset에서도 Full이 Current보다 낫지 않다면 trajectory-conditioned repair 주장은 더 축소되어야 한다. 반대로 차이가 확인되면 현재 논문에서 빠진 핵심 증거가 된다.

### 4. 중간 — 일부 이론적 표현이 실제 보장보다 강하다

- WA, TLE/MLE, RE, CE를 하나의 “severity” 순서로 두는 선택은 편리하지만 의미론적 개선 순서로 자명하지 않다. 예를 들어 RE에서 WA로 이동했다고 해서 테스트 행동이 일반적으로 개선되었다고 볼 수 없다. 대안 순서에 대한 민감도 분석이 필요하다.
- 서로 독립 학습되고 출력을 상호 입력하지 않는다는 사실은 후보 오류의 확률적 “conditional independence”를 보장하지 않는다. 동일 base model과 데이터에서 학습된 체크포인트의 오류는 강하게 상관될 수 있다. “non-adaptive” 또는 “non-interacting generation”이 정확한 표현이다.
- submodularity와 finite-family Hoeffding bound는 맞지만, 84개 조합을 전수열거하는 설정에서 기술적 깊이는 제한적이다. 논문도 bound가 18.8점으로 실질적 effect certificate가 아님을 인정한다.
- “Test outcomes never enter selection”은 validation execution outcome으로 R_v를 구성한다는 설명과 문자 그대로 모순된다. “final test-split outcomes never enter selection”으로 명확히 고쳐야 한다.

### 5. 중간 — 외적 타당성과 correctness 증거가 아직 제한적이다

CodeNet Unseen은 무작위 problem holdout이 아니라 trajectory 수가 적은 하위 10% 문제이므로 전체 신규 과제 분포를 대표하지 않는다. CodeWorkout은 학생 holdout이지만 17개 exercise 모두가 학습에 존재하므로 신규 과제 일반화 재현은 아니다. 또한 두 실험 모두 같은 7B base model 계열을 사용한다.

Hidden-test audit는 강점이지만, hidden tests가 동일 benchmark suite의 해시 분할이므로 독립적으로 작성된 테스트나 semantic oracle과 동일하지 않다.

### 6. 중간 — 재현성은 약속되어 있지만 PDF만으로 확인할 수 없다

Data Availability는 anonymized artifact가 “will provide”된다고 기술한다. 실제 제출 부록에 코드, 정확한 split IDs, 아홉 checkpoint hash, 생성 출력, runner image, 통계 스크립트와 manifest가 포함되어야 결과를 신뢰성 있게 재검산할 수 있다.

### 형식상 별도 치명적 위험

초기 제출은 본문과 그림 18페이지, 참고문헌 4페이지로 제한되며 비준수는 desk reject 대상이다. 현재 PDF는 22페이지이고 참고문헌이 19페이지 중간에서 시작한다. 즉, Threats와 Conclusion 일부가 19페이지에 있어 초기 제출 기준으로 본문 18페이지 제한을 초과한 것으로 보인다. Data Availability는 제한에서 제외될 수 있지만 Conclusion과 Threats는 제외되지 않는다. 제출 전 반드시 본문을 18페이지 안으로 줄여야 한다.

## FSE 기준별 판단

- **Originality: 보통.** trajectory-derived supervision 관계의 체계화는 흥미롭지만, 실제로 성능을 설명하는 것은 기존적인 seed diversity와 execution selection에 가깝다.
- **Importance: 보통 이상.** trajectory 효과와 checkpoint diversity를 혼동하지 말아야 한다는 부정적 결과는 커뮤니티에 유용하다. 다만 한 모델과 제한된 교육용 APR 범위에서 얻은 결론이다.
- **Soundness: 보통 이상.** 실행·통계 절차는 대체로 엄밀하나, 9-checkpoint 선택과 고정 3-checkpoint baseline의 비대칭이 핵심 비교를 약화한다.
- **Evaluation: 강함.** 다수 control, cluster 분석, hidden partition, Java replication이 돋보인다. 그러나 core mechanism을 지지하지 못하며 공정한 9-Answer selection control이 빠졌다.
- **Presentation: 강함.** 명확하고 자기비판적이며 표와 결과 해석이 좋다. 다만 초록이 지나치게 조밀하고 이론적 언어 일부가 과장되어 있다.
- **Related work comparison: 보통 이상.** 관련 교육 APR과 LLM repair를 폭넓게 다루지만, 최종 기여가 checkpoint portfolio라면 ensemble/checkpoint-diversity/model-selection 문헌과의 비교가 더 필요하다.
- **Reproducibility: 보통 이상, artifact 조건부.** 방법 기술은 좋지만 실제 artifact 없이는 machine-readable 결과와 runner conformance를 확인할 수 없다.

## 판정 근거

이 논문은 “결과가 원래 가설을 지지하지 않을 때 이를 어떻게 정직하게 보고할 것인가”의 좋은 사례이며, 실험적 엄밀성과 표현 품질만 보면 Accept 경계에 있다. 그러나 가장 강한 증거가 trajectory supervision의 효용을 확인하지 못하고, 남은 작은 이점은 더 큰 학습·선택 후보군이라는 교란과 분리되지 않는다. 따라서 현재 상태에서는 주요 기술적 기여가 FSE Accept 수준에 약간 미달한다고 판단한다.

Strong Reject가 아닌 이유는 실험 설계와 부정적 발견 자체가 상당히 가치 있고, 문제들이 명확한 추가 실험과 재프레이밍으로 해결 가능하기 때문이다.

## 더 높은 판정을 위해 필요한 변경

1. Answer 체크포인트도 9개 독립 시드로 학습하고 동일한 84개 triple selection을 적용하여 mixed 9Choose3과 Answer 9Choose3을 unrestricted RR, 모든 TED budget, Seen/Unseen, Java에서 비교한다.
2. 동일 current code 또는 동등한 실행 상태를 가지지만 다른 history와 후속 target을 갖는 counterfactual/matched subset을 만들고, history가 필요한 사례에서 Full 대 Current를 평가한다.
3. 위 결과가 여전히 null이면 제목·초록·기여를 “trajectory-conditioned repair의 성능 향상”보다 “trajectory supervision과 checkpoint diversity를 분리한 부정적·진단적 연구”로 더 명확히 재정의한다.
4. verdict severity 순서에 대한 근거와 대안 순서 민감도 분석을 추가하고, conditional independence 및 test-outcome 관련 과장된 표현을 수정한다.
5. 최소 한 개의 다른 base model, 무작위 problem-held-out split, 그리고 가능하면 CodeWorkout exercise-held-out 평가를 추가한다.
6. validation-selected ZPDPatch와 Answer baseline 사이의 jointly repaired patch TED 및 동일 budget frontier를 직접 paired 분석한다.
7. 실행 가능한 익명 artifact와 모든 split/checkpoint/output manifest를 제출하고, 본문을 초기 제출 18페이지 제한 안으로 축약한다.
